---
title: New Composition API
description: Nuxt Bridge は Nuxt 3 と互換性のある Composable を実装します。
---

`@nuxtjs/composition-api` から Nuxt 3 互換 API に移行することで、Nuxt 3 に移行する際の書き直しを減らすことができます。

## `ssrRef` と `shallowSsrRef`

これら 2 つの関数は、内部で非常に似たように動作する新しい Composable である `useState` に置き換えられました。

主な違いは、この状態に _key_ を提供する必要があること（`ssrRef` と `shallowSsrRef` では Nuxt が自動生成していました）、および Nuxt 3 プラグイン（`defineNuxtPlugin` で定義されたもの）またはコンポーネントインスタンス内でのみ呼び出すことができることです。（言い換えると、リクエスト間での状態共有の危険性があるため、[`useState`](/docs/api/composables/use-state) をグローバル/アンビエントコンテキストで使用することはできません。）

```diff
- import { ssrRef } from '@nuxtjs/composition-api'

- const ref1 = ssrRef('initialData')
- const ref2 = ssrRef(() => 'factory function')
+ const ref1 = useState('ref1-key', () => 'initialData')
+ const ref2 = useState('ref2-key', () => 'factory function')
  // 状態へのアクセス
  console.log(ref1.value)
```

状態にキーが付いているため、同じキーを使用している限り、複数の場所から同じ状態にアクセスできます。

この Composable の使用方法については、[Nuxt 3 ドキュメント](/docs/api/composables/use-state)で詳しく読むことができます。

## `ssrPromise`

この関数は削除されており、使用していた場合は代替実装を見つける必要があります。`ssrPromise` の使用事例がある場合は、ディスカッションでお知らせください。

## `onGlobalSetup`

この関数は削除されましたが、その使用事例は `defineNuxtPlugin` 内で [`useNuxtApp`](/docs/api/composables/use-nuxt-app) または [`useState`](/docs/api/composables/use-state) を使用することで満たすことができます。また、レイアウトの `setup()` 関数内で任意のカスタムコードを実行することもできます。

```diff
- import { onGlobalSetup } from '@nuxtjs/composition-api'

- export default () => {
-   onGlobalSetup(() => {
+ export default defineNuxtPlugin((nuxtApp) => {
+   nuxtApp.hook('vue:setup', () => {
      // ...
    })
- }
+ })
```

## `useStore`

Vuex ストアインスタンスにアクセスするためには、`useNuxtApp().$store` を使用できます。

```diff
- import { useStore } from '@nuxtjs/composition-api`
+ const { $store } = useNuxtApp()
```

## `useContext` と `withContext`

`useNuxtApp` を使用して注入されたヘルパーにアクセスできます。

```diff
- import { useContext } from '@nuxtjs/composition-api`
+ const { $axios } = useNuxtApp()
```

::note
`useNuxtApp()` は、通常 Nuxt 2 コンテキストからアクセスするのと同じプロパティをすべて含む `nuxt2Context` というキーも提供していますが、Nuxt 3 では存在しないため、これを直接使用しないことをお勧めします。代わりに、必要なものにアクセスする別の方法があるかどうかを確認してください。（ない場合は、機能リクエストまたはディスカッションを起こしてください。）
::

## `wrapProperty`

このヘルパー関数はもう提供されていませんが、以下のコードで置き換えることができます:

```js
const wrapProperty = (property, makeComputed = true) => () => {
  const vm = getCurrentInstance().proxy
  return makeComputed ? computed(() => vm[property]) : vm[property]
}
```

## `useAsync` と `useFetch`

これら 2 つの Composable は、[Nuxt 3 ドキュメント](/docs/getting-started/data-fetching)で説明されている `useLazyAsyncData` および `useLazyFetch` で置き換えることができます。以前の `@nuxtjs/composition-api` Composable と同様に、これらの Composable はクライアントサイドでのルートナビゲーションをブロックしません（それゆえ名前の「lazy」部分）。

::important
似たような名前にもかかわらず、API は完全に異なることに注意してください。重要なことに、Composable 外の他の変数の値を変更しようとしてはいけません（以前の `useFetch` で行っていた可能性があるように）。
::

::warning
`useLazyFetch` は [Nitro](/docs/bridge/nitro) のために設定されている必要があります。
::

`useAsync` から新しい Composable への移行:

```diff
<script setup>
- import { useAsync } from '@nuxtjs/composition-api'
- const posts = useAsync(() => $fetch('/api/posts'))
+ const { data: posts } = useLazyAsyncData('posts', () => $fetch('/api/posts'))
+ // または、より簡単に！
+ const { data: posts } = useLazyFetch('/api/posts')
</script>
```

`useFetch` から新しい Composable への移行:

```diff
<script setup>
- import { useFetch } from '@nuxtjs/composition-api'
- const posts = ref([])
- const { fetch } = useFetch(() => { posts.value = await $fetch('/api/posts') })
+ const { data: posts, refresh } = useLazyAsyncData('posts', () => $fetch('/api/posts'))
+ // または、より簡単に！
+ const { data: posts, refresh } = useLazyFetch('/api/posts')
  function updatePosts() {
-   return fetch()
+   return refresh()
  }
</script>
```

### `useMeta`

`vue-meta` と連携するために、`useNuxt2Meta` を使用することができます。これは Nuxt Bridge で動作し（Nuxt 3 では動作しません）、`vue-meta` 互換の方法でメタタグを操作できます。

```diff
<script setup>
- import { useMeta } from '@nuxtjs/composition-api'
  useNuxt2Meta({
    title: 'My Nuxt App',
  })
</script>
```

computed 値や ref を渡すこともでき、メタ値はリアクティブに更新されます:

```ts
<script setup>
const title = ref('my title')
useNuxt2Meta({
  title,
})
title.value = 'new title'
</script>
```

::note
同じコンポーネント内で `useNuxt2Meta()` と Options API の `head()` を両方使用しないように注意してください。動作が予測不可能になる可能性があります。
::

Nuxt Bridge は、[`useHead`](/docs/api/composables/use-head) Composable でアクセスできる Nuxt 3 互換のメタ実装も提供しています。

```diff
<script setup>
- import { useMeta } from '@nuxtjs/composition-api'
  useHead({
    title: 'My Nuxt App',
  })
</script>
```

`nuxt.config` で明示的に有効にする必要もあります:

```js
import { defineNuxtConfig } from '@nuxt/bridge'
export default defineNuxtConfig({
  bridge: {
    meta: true
  }
})
```

この [`useHead`](/docs/api/composables/use-head) Composable は、`<head>` を操作するために内部で `@unhead/vue`（`vue-meta` ではなく）を使用しています。したがって、競合する可能性があるため、ネイティブの Nuxt 2 `head()` プロパティと [`useHead`](/docs/api/composables/use-head) の両方を使用しないことをお勧めします。

この Composable の使用方法についての詳細は、[Nuxt 3 ドキュメント](/docs/getting-started/seo-meta)を参照してください。

### 明示的インポート

Nuxt は、必要に応じてインポートを明示的にするために使用できる `#imports` エイリアスで、すべての自動インポートを公開しています:

```vue
<script setup lang="ts">
import { ref, computed } from '#imports'

const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### 自動インポートの無効化

Composable とユーティリティの自動インポートを無効にしたい場合は、`nuxt.config` ファイルで `imports.autoImport` を `false` に設定できます。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    autoImport: false
  }
})
```

これにより自動インポートは完全に無効になりますが、`#imports` からの[明示的インポート](#explicit-imports)を使用することは依然として可能です。
