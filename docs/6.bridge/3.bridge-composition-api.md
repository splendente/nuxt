---
title: Legacy Composition API
description: 'Nuxt Bridge で Composition API に移行する方法を学びます。'
---

Nuxt Bridge は Composition API 構文へのアクセスを提供します。これは Nuxt 3 と整合するように特別に設計されています。このため、以前に Composition API を使用していた場合、Nuxt Bridge を有効にする際にいくつかの追加ステップがあります。

## モジュールの削除

- 依存関係から `@vue/composition-api` を削除します。
- 依存関係から `@nuxtjs/composition-api` を削除します（および `nuxt.config` のモジュールからも）。

## `@vue/composition-api` の使用

`@nuxtjs/composition-api` ではなく `@vue/composition-api` だけを使用していた場合は、非常に簡単です。

1. まず、Composition API を手動で登録しているプラグインを削除します。Nuxt Bridge がこれを処理します。

   ```diff
   - import Vue from 'vue'
   - import VueCompositionApi from '@vue/composition-api'
   -
   - Vue.use(VueCompositionApi)
   ```

2. それ以外は、何もする必要はありません。ただし、必要に応じて `@vue/composition-api` からの明示的なインポートを削除し、Nuxt Bridge が自動インポートしてくれることに依存することもできます。

## `@nuxtjs/composition-api` からの移行

Nuxt Bridge は `@nuxtjs/composition-api` とは少し異なる方法で Composition API を実装し、異なる Composable を提供します（Nuxt 3 が提供する Composable と整合するように設計されています）。

一部の Composable が削除され、まだ置き換えがないため、これは少し複雑なプロセスになります。

### buildModules から `@nuxtjs/composition-api/module` を削除

インポートをすぐに更新する必要はありません。Nuxt Bridge は現在使用しているほとんどのインポートに对して自動的に「shim」を提供し、新しい Nuxt 3 互換 Composable に移行する時間を与えます。ただし、以下の例外があります:

- `withContext` が削除されました。[以下](/docs/bridge/nuxt3-compatible-api#usecontext-and-withcontext)を参照してください。
- `useStatic` が削除されました。現在のところ置き換えはありません。これの使用事例がある場合は、お気軽にディスカッションを起こしてください。
- 非推奨だった `reqRef` と `reqSsrRef` は、現在完全に削除されました。これを置き換えるには、[ssrRef](/docs/bridge/nuxt3-compatible-api#ssrref-and-shallowssrref) に関する以下の指示に従ってください。

### `bridge.capi` の設定

```ts
import { defineNuxtConfig } from '@nuxt/bridge'

export default defineNuxtConfig({
  bridge: {
    capi: true,
    nitro: false // Nitro への移行が完了している場合は、true に設定
  }
})
```

`@nuxtjs/composition-api` から使用しているその他の Composable については、以下の手順に従ってください。

### useFetch

`$fetchState` と `$fetch` が削除されました。

```diff
const {
- $fetch,
- $fetchState,
+ fetch,
+ fetchState,
} = useFetch(() => { posts.value = await $fetch('/api/posts') })
```

### `defineNuxtMiddleware`

これはタイプヘルパーのスタブ関数で、現在削除されています。

`defineNuxtMiddleware` ラッパーを削除します:

```diff
- import { defineNuxtMiddleware } from '@nuxtjs/composition-api`
- export default defineNuxtMiddleware((ctx) => {})
+ export default (ctx) => {}
```

For typescript support, you can use `@nuxt/types`:

```ts
import type { Middleware } from '@nuxt/types'

export default <Middleware> function (ctx) { }
```

### `defineNuxtPlugin`

これはタイプヘルパーのスタブ関数で、現在削除されています。

関数を削除することで、Nuxt 2 スタイルのプラグインを使用し続けることもできます（[defineNuxtMiddleware](#definenuxtmiddleware) と同様）。

`defineNuxtPlugin` ラッパーを削除します:

```diff
- import { defineNuxtPlugin } from '@nuxtjs/composition-api'
- export default defineNuxtPlugin((ctx, inject) => {})
+ export default (ctx, inject) => {}
```

TypeScript サポートのために、`@nuxt/types` を使用できます:

```ts
import type { Plugin } from '@nuxt/types'

export default <Plugin> function (ctx, inject) {}
```

::warning
この例は有効ですが、Nuxt 3 は少し異なるシグネチャを持つ新しい defineNuxtPlugin 関数を導入します。
::

:ReadMore{link="/docs/guide/directory-structure/plugins#creating-plugins"}

### `useRouter` と `useRoute`

Nuxt Bridge は [`useRouter`](/docs/api/composables/use-router) と `useRoute` を通じて、これらの Composable の直接的な置き換えを提供します。

唯一の主な違いは、[`useRoute`](/docs/api/composables/use-route) が computed プロパティを返さなくなったことです。

```diff
- import { useRouter, useRoute } from '@nuxtjs/composition-api'

  const router = useRouter()
  const route = useRoute()

- console.log(route.value.path)
+ console.log(route.path)
```
