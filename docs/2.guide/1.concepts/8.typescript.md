## 型チェック

デフォルトでは、Nuxt はパフォーマンス上の理由で、[`nuxt dev`](/docs/api/commands/dev) や [`nuxt build`](/docs/api/commands/build) を実行するときに型をチェックしません。

ビルド時や開発時に型チェックを有効にするには、`vue-tsc` と `typescript` を開発依存関係としてインストールしてください：

::code-group{sync="pm"}

  ```bash [npm]
  npm install --save-dev vue-tsc typescript
  ```

  ```bash [yarn]
  yarn add --dev vue-tsc typescript
  ```

  ```bash [pnpm]
  pnpm add -D vue-tsc typescript
  ```

  ```bash [bun]
  bun add -D vue-tsc typescript
  ```

::

この後、[`nuxt typecheck`](/docs/api/commands/typecheck) コマンドを実行して型をチェックしてください：

```bash [Terminal]
npx nuxt typecheck
```

ビルド時や開発時に型チェックを有効にするには、`nuxt.config` ファイルで [`typescript.typeCheck`](/docs/api/nuxt-config#typecheck) オプションを使用することもできます：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  typescript: {
    typeCheck: true
  }
})
```

## 自動生成される型

`nuxt dev` や `nuxt build` を実行すると、Nuxt は IDE の型サポート（および型チェック）のために以下のファイルを生成します：

### `.nuxt/nuxt.d.ts`

このファイルには、使用しているすべてのモジュールの型と、Nuxt が必要とする主要な型が含まれています。IDE はこれらの型を自動的に認識するはずです。

ファイル内の一部の参照は、`buildDir`（`.nuxt`）内でのみ生成されるファイルを指しているため、完全な型付けを得るには `nuxt dev` または `nuxt build` を実行する必要があります。

### `.nuxt/tsconfig.app.json`

このファイルには、Nuxt や使用しているモジュールによって注入された解決済みエイリアスを含む、プロジェクトの推奨基本 TypeScript 設定が含まれているため、`~/file` や `#build/file` などのエイリアスに対して完全な型サポートとパス自動補完を得ることができます。

::note
デフォルト以外のディレクトリを含めるために、[nuxt.config](/docs/api/nuxt-config#imports) の `imports` セクションの使用を検討してください。これはアプリ全体で使用している型を自動インポートするのに便利です。
::

[この設定を拡張する方法について詳しく読む](/docs/guide/directory-structure/tsconfig)。

::tip{icon="i-lucide-video" to="https://youtu.be/umLI7SlPygY" target="_blank"}
Daniel Roe が組み込み Nuxt エイリアスについて説明している動画を見る。
::

::note
Nitro も API ルートの[型を自動生成](/docs/guide/concepts/server-engine#typed-api-routes)します。さらに、Nuxt はグローバルに利用可能なコンポーネントや[コンポーザブルからの自動インポート](/docs/guide/directory-structure/composables)、その他のコア機能の型も生成します。
::

::note
後方互換性のため、Nuxt は依然として `./.nuxt/tsconfig.json` を生成します。しかし、より優れた型安全性とパフォーマンスのために、新しい設定ファイル（`.nuxt/tsconfig.app.json`、`.nuxt/tsconfig.server.json` など）で [TypeScript プロジェクト参照](/docs/guide/directory-structure/tsconfig)を使用することを推奨します。

`./.nuxt/tsconfig.json` を拡張する場合は、すべてのオプションが `tsconfig.json` で定義されたものによって上書きされることに注意してください。`"compilerOptions.paths"` などのオプションを独自の設定で上書きすると、TypeScript がモジュール解決を考慮しなくなり、`#imports` などのモジュール解決が認識されなくなる可能性があります。

オプションをさらに拡張する必要がある場合は、`nuxt.config` 内で [`alias` プロパティ](/docs/api/nuxt-config#alias)を使用できます。Nuxt はそれらを取得し、生成された TypeScript 設定をそれに応じて拡張します。
::

## プロジェクト参照

Nuxt は型チェックのパフォーマンスを向上させ、より優れた IDE サポートを提供するために [TypeScript プロジェクト参照](https://www.typescriptlang.org/docs/handbook/project-references.html)を使用しています。この機能は TypeScript がコードベースをより小さく、より管理しやすい片断に分割することを可能にします。

### Nuxt がプロジェクト参照を使用する方法

`nuxt dev` や `nuxt build` を実行すると、Nuxt はアプリケーションの異なる部分に対して複数の `tsconfig.json` ファイルを生成します。

- **`.nuxt/tsconfig.app.json`** - アプリケーションコードの設定
- **`.nuxt/tsconfig.node.json`** - `nuxt.config` とモジュールの設定
- **`.nuxt/tsconfig.server.json`** - サーバーサイドコードの設定（該当する場合）
- **`.nuxt/tsconfig.json`** - 後方互換性のためのレガシー設定

これらのファイルはそれぞれ、適切な依存関係を参照し、その特定のコンテキストに対して最適な型チェックを提供するように設定されています。

### プロジェクト参照の利点

- **より高速なビルド**: TypeScript は変更されていないプロジェクトの再ビルドをスキップできます
- **より優れた IDE パフォーマンス**: IDE はより高速な IntelliSense とエラーチェックを提供できます
- **分離されたコンパイル**: アプリケーションの一部のエラーが他の部分のコンパイルを阻害しません
- **より明確な依存関係管理**: 各プロジェクトはその依存関係を明示的に宣言します

::note
プロジェクト参照の設定は Nuxt によって自動的に処理されます。通常、これらの設定を手動で変更する必要はありませんが、それらがどのように動作するかを理解することは型チェックの問題をトラブルシュートするのに役立ちます。
::

## 厳密チェック

TypeScript はプログラムのより多くの安全性と分析を提供するための特定のチェックが付属しています。

より優れた型安全性を提供するために、[厳密チェック](https://www.typescriptlang.org/docs/handbook/migrating-from-javascript.html#getting-stricter-checks)は Nuxt でデフォルトで有効になっています。

現在コードベースを TypeScript に変換している場合は、`nuxt.config` で `strict` を `false` に設定して厳密チェックを一時的に無効にすることをお勧めします：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  typescript: {
    strict: false
  }
})
```
