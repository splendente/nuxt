Nuxt を構築する中で、私たちは新しいサーバーエンジンである [Nitro](https://nitro.build/) を作成しました。

多くの機能が搭載されています：

- Node.js、ブラウザー、サービスワーカーなどのクロスプラットフォームサポート。
- サーバーレスの箱から出してすぐに使えるサポート。
- API ルートサポート。
- 自動コード分割と非同期読み込みチャンク。
- 静的 + サーバーレスサイトのためのハイブリッドモード。
- Hot Module Reloading 付きの開発サーバー。

## API レイヤー

サーバーの [API エンドポイント](/docs/guide/directory-structure/server#api-routes)と[ミドルウェア](/docs/guide/directory-structure/server#server-middleware)は、内部で [h3](https://github.com/h3js/h3) を使用する Nitro によって追加されます。

主要な機能には次のものがあります：

- ハンドラーは自動的に処理される JSON レスポンスのためにオブジェクト/配列を直接返すことができます
- ハンドラーは Promise を返すことができ、それは待機されます（`res.end()` と `next()` もサポートされています）
- ボディ解析、Cookie 処理、リダイレクト、ヘッダーなどのヘルパー関数

詳細については [h3 ドキュメント](https://github.com/h3js/h3)をご覧ください。

`server/` ディレクトリの API レイヤーについて詳しく学びます。
::

## 直接 API 呼び出し

Nitro はグローバルに利用可能な [`$fetch`](/docs/api/utils/dollarfetch) ヘルパーを介してルートの「直接」呼び出しを可能にします。これはブラウザーで実行される場合はサーバーへの API 呼び出しを行いますが、サーバーで実行される場合は関連する関数を直接呼び出し、**追加の API 呼び出しを節約** します。

[`$fetch`](/docs/api/utils/dollarfetch) API は [ofetch](https://github.com/unjs/ofetch) を使用しており、主要な機能には次のものがあります：

- JSON レスポンスの自動解析（必要に応じて生レスポンスへのアクセスも可能）
- リクエストボディとパラメーターは正しい `Content-Type` ヘッダーとともに自動的に処理されます

`$fetch` 機能の詳細については、[ofetch](https://github.com/unjs/ofetch) をご覧ください。

## 型付き API ルート

API ルート（またはミドルウェア）を使用する場合、`res.end()` を使用してレスポンスを送信する代わりに値を返す限り、Nitro はこれらのルートの型情報を生成します。

[`$fetch()`](/docs/api/utils/dollarfetch)や[`useFetch()`](/docs/api/composables/use-fetch)を使用する際に、これらの型にアクセスできます。

## スタンドアロンサーバー

Nitro は `node_modules` に依存しないスタンドアロンサーバーの配布ファイルを生成します。

Nuxt 2 のサーバーはスタンドアロンではなく、`nuxt start`（[`nuxt-start`](https://www.npmjs.com/package/nuxt-start)または[`nuxt`](https://www.npmjs.com/package/nuxt)配布で）を実行するか、カスタムプログラム使用によって Nuxt コアの一部を関与させる必要があり、これは脆弱で破損しやすく、サーバーレスやサービスワーカー環境には適していません。

Nuxt は `nuxt build` を実行する際に、この配布ファイルを [`.output`](/docs/guide/directory-structure/output) ディレクトリに生成します。

出力には、任意の環境（実験的なブラウザーサービスワーカーを含む！）で Nuxt サーバーを実行し、静的ファイルを提供するためのランタイムコードが含まれており、JAMstack の真のハイブリッドフレームワークとなっています。さらに、Nuxt はマルチソースドライバーとローカルアセットをサポートするネイティブストレージレイヤーを実装しています。
