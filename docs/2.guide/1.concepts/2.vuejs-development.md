Nuxt は Vue 3 を統合しており、これは Nuxt ユーザーに新しいパターンを可能にする Vue の新しいメジャーリリースです。

::note
Nuxt を使用するために Vue の深い知識は必要ありませんが、[vuejs.org](https://vuejs.org) でドキュメントを読んで、いくつかの例を確認することをお勧めします。
::

Nuxt は常に Vue をフロントエンドフレームワークとして使用してきました。

私たちが Nuxt を Vue の上に構築することを選んだ理由は次のとおりです：

- Vue のリアクティビティモデル：データの変更が自動的にインターフェースの変更をトリガーします。
- コンポーネントベースのテンプレート：HTML をウェブの共通言語として保持しながら、直感的なパターンを可能にし、インターフェースを一貫性を保ちながら強力に保ちます。
- 小さなプロジェクトから大規模なウェブアプリケーションまで、Vue はスケールで高いパフォーマンスを維持し、アプリケーションがユーザーに価値を提供し続けることを保証します。

## Nuxt での Vue

### シングルファイルコンポーネント

[Vue のシングルファイルコンポーネント](https://vuejs.org/guide/scaling-up/sfc.html)（SFC または `*.vue` ファイル）は、Vue コンポーネントのマークアップ（`<template>`）、ロジック（`<script>`）、スタイリング（`<style>`）をカプセル化します。Nuxt は [Hot Module Replacement](https://vite.dev/guide/features.html#hot-module-replacement) で SFC に対してゼロ設定エクスペリエンスを提供し、シームレスな開発者エクスペリエンスを提供します。

### 自動インポート

Nuxt プロジェクトの [`components/`](/docs/guide/directory-structure/components) ディレクトリに作成されたすべての Vue コンポーネントは、インポートする必要なくプロジェクトで使用できます。コンポーネントがどこでも使用されていない場合、本番環境のコードには含まれません。

:read-more{to="/docs/guide/concepts/auto-imports"}

### Vue Router

ほとんどのアプリケーションには複数のページとそれらの間をナビゲートする方法が必要です。これは **ルーティング** と呼ばれます。Nuxt は [`pages/`](/docs/guide/directory-structure/pages) ディレクトリと命名規則を使用して、公式の [Vue Router ライブラリ](https://router.vuejs.org) を使用してファイルにマップされたルートを直接作成します。

:read-more{to="/docs/getting-started/routing"}

:link-example{to="/docs/examples/features/auto-imports"}

## Nuxt 2 / Vue 2 との違い

Nuxt 3+ は Vue 3 をベースとしています。新しいメジャー Vue バージョンは、Nuxt が活用するいくつかの変更を導入しています：

- より優れたパフォーマンス
- Composition API
- TypeScript サポート

### 高速レンダリング

Vue Virtual DOM（VDOM）はゼロから書き直され、より優れたレンダリングパフォーマンスを可能にします。さらに、コンパイルされたシングルファイルコンポーネントで作業する際、Vue コンパイラは静的と動的マークアップを分離することで、ビルド時にさらに最適化することができます。

これにより、初回レンダリング（コンポーネント作成）と更新が高速化され、メモリ使用量が減ります。Nuxt 3 では、サーバーサイドレンダリングも高速化されます。

### より小さなバンドル

Vue 3 と Nuxt 3 では、バンドルサイズの削減に焦点が当てられています。バージョン 3 では、テンプレートディレクティブや組み込みコンポーネントを含む Vue の機能のほとんどが tree-shakable です。使用しない場合、本番環境のバンドルには含まれません。

このようにして、最小限の Vue 3 アプリケーションは 12 kb gzipped まで削減できます。

### Composition API

Vue 2 でコンポーネントにデータとロジックを提供する唯一の方法は Options API を通じてでした。これは `data` や `methods` などの事前定義されたプロパティを使用してテンプレートにデータとメソッドを返すことを可能にします：

```vue twoslash
<script>
export default {
  data() {
    return {
      count: 0
    }
  },
  methods: {
    increment(){
      this.count++
    }
  }
}
</script>
```

Vue 3 で導入された [Composition API](https://vuejs.org/guide/extras/composition-api-faq.html) は Options API の置き換えではありませんが、アプリケーション全体でのより優れたロジックの再利用を可能にし、複雑なコンポーネントで関心事ごとにコードをグループ化するより自然な方法です。

 `<script>` 定義で `setup` キーワードと併用すると、上記のコンポーネントを Composition API と Nuxt 3 の自動インポートされたリアクティビティ API で書き直した例は次のとおりです：

```vue twoslash [components/Counter.vue]
<script setup lang="ts">
const count = ref(0)
const increment = () => count.value++
</script>
```

Nuxt の目標は、Composition API を中心とした優れた開発者エクスペリエンスを提供することです。

- Vue と Nuxt の [組み込みコンポーザブル](/docs/api/composables/use-async-data) から自動インポートされた [リアクティビティ関数](https://vuejs.org/api/reactivity-core.html) を使用します。
- [`composables/` ディレクトリ](/docs/guide/directory-structure/composables) で独自の自動インポートされた再利用可能な関数を書きます。

### TypeScript サポート

Vue 3 と Nuxt 3+ の両方が TypeScript で書かれています。完全に型付けされたコードベースはミスを防ぎ、API の使用方法を文書化します。これは、それを活用するためにアプリケーションを TypeScript で書く必要があることを意味するものではありません。Nuxt 3 では、ファイルを `.js` から `.ts` にリネームするか、コンポーネントに `<script setup lang="ts">` を追加することでオプトインできます。

::read-more{to="/docs/guide/concepts/typescript"}
Nuxt での TypeScript の詳細をお読みください
::
