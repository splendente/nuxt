## Nuxt コンテキスト

組み込みやユーザーが作成した多くの Composables やユーティリティは、Nuxt インスタンスへのアクセスが必要な場合があります。これはアプリケーションのどこでも存在するわけではありません。なぜなら、リクエストごとに新しいインスタンスが作成されるからです。

現在、Nuxt コンテキストは[プラグイン](/docs/guide/directory-structure/plugins)、[Nuxt フック](/docs/guide/going-further/hooks)、[Nuxt ミドルウェア](/docs/guide/directory-structure/middleware)（`defineNuxtRouteMiddleware` でラップされている場合）、および [setup 関数](https://vuejs.org/api/composition-api-setup.html)（ページとコンポーネント内）でのみアクセスできます。

Composable がコンテキストへのアクセスなしに呼び出された場合、「Nuxt インスタンスへのアクセスが必要な Composable がプラグイン、Nuxt フック、Nuxt ミドルウェア、または Vue setup 関数の外部で呼び出されました」というエラーが発生する場合があります。その場合、[`nuxtApp.runWithContext`](/docs/api/composables/use-nuxt-app#runwithcontext) を使用して、このコンテキスト内で関数を明示的に呼び出すこともできます。

## NuxtApp へのアクセス

Composables、プラグイン、コンポーネント内では、[`useNuxtApp()`](/docs/api/composables/use-nuxt-app) を使用して `nuxtApp` にアクセスできます：

```ts [composables/useMyComposable.ts]
export function useMyComposable () {
  const nuxtApp = useNuxtApp()
  // ランタイム nuxt アプリインスタンスにアクセス
}
```

あなたの Composable が常に `nuxtApp` を必要としない場合、または単にそれが存在するかどうかをチェックしたい場合、[`useNuxtApp`](/docs/api/composables/use-nuxt-app) は例外を投げるため、代わりに [`tryUseNuxtApp`](/docs/api/composables/use-nuxt-app#tryusenuxtapp) を使用できます。

プラグインも便宜上、第一引数として `nuxtApp` を受け取ります。

:read-more{to="/docs/guide/directory-structure/plugins"}

## ヘルパーの提供

すべての Composables とアプリケーションで使用できるヘルパーを提供できます。これは通常 Nuxt プラグイン内で行われます。

```ts
const nuxtApp = useNuxtApp()
nuxtApp.provide('hello', (name) => `Hello ${name}!`)

console.log(nuxtApp.$hello('name')) // "Hello name!" を出力
```

::read-more{to="/docs/guide/directory-structure/plugins#providing-helpers"}
プラグインで `provide` キーを持つオブジェクトを返すことでヘルパーを注入することができます。
::

::read-more{to="https://v2.nuxt.com/docs/directory-structure/plugins#inject-in-root--context" target="_blank"}
Nuxt 2 プラグインでは、これは **inject 関数**と呼ばれていました。
::
