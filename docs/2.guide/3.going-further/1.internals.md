このガイドは、Nuxt の上に新しいソリューションやモジュール統合を開発するために、Nuxt の内部をより深く理解するのに役立ちます。

## Nuxt インターフェース

[`nuxt dev`](/docs/api/commands/dev) で Nuxt を開発モードで起動するか、[`nuxt build`](/docs/api/commands/build) でプロダクションアプリケーションをビルドするとき、
内部的に `nuxt` と呼ばれる共通のコンテキストが作成されます。これは `nuxt.config` ファイルとマージされた正規化されたオプション、
いくつかの内部状態、そして [unjs/hookable](https://github.com/unjs/hookable) によって支援される強力な[フックシステム](/docs/api/advanced/hooks)を保持し、
異なるコンポーネント間の通信を可能にします。これを **Builder Core** と考えることができます。

このコンテキストは [Nuxt Kit](/docs/guide/going-further/kit) コンポーザブルで使用するためにグローバルに利用可能です。
したがって、プロセスごとに実行できる Nuxt のインスタンスは 1 つだけです。

Nuxt インターフェースを拡張し、ビルドプロセスの異なる段階にフックするために、[Nuxt モジュール](/docs/guide/going-further/modules)を使用できます。

詳細については、[ソースコード](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/core/nuxt.ts)をチェックしてください。

## NuxtApp インターフェース

ブラウザーまたはサーバーでページをレンダリングする際、`nuxtApp` と呼ばれる共有コンテキストが作成されます。
このコンテキストは Vue インスタンス、ランタイムフック、そして ssrContext やハイドレーション用のペイロードなどの内部状態を保持します。
これを **Runtime Core** と考えることができます。

このコンテキストは、Nuxt プラグインや `<script setup>`、Vue コンポーザブル内で [`useNuxtApp()`](/docs/api/composables/use-nuxt-app) コンポーザブルを使用してアクセスできます。
グローバルな使用はブラウザーでは可能ですが、ユーザー間でのコンテキスト共有を避けるため、サーバーでは不可能です。

[`useNuxtApp`](/docs/api/composables/use-nuxt-app) はコンテキストが現在利用できない場合に例外をスローするため、コンポーザブルが常に `nuxtApp` を必要としない場合は、例外をスローする代わりに `null` を返す [`tryUseNuxtApp`](/docs/api/composables/use-nuxt-app#tryusenuxtapp) を使用できます。

`nuxtApp` インターフェースを拡張し、異なる段階にフックしたりコンテキストにアクセスしたりするために、[Nuxt プラグイン](/docs/guide/directory-structure/plugins)を使用できます。

このインターフェースの詳細については、[Nuxt App](/docs/api/composables/use-nuxt-app) をチェックしてください。

`nuxtApp` は以下のプロパティを持っています：

```js
const nuxtApp = {
  vueApp, // グローバル Vue アプリケーション: https://vuejs.org/api/application.html#application-api

  versions, // Nuxt と Vue のバージョンを含むオブジェクト

  // これらはランタイム NuxtApp フックを呼び出したり追加したりできます
  // https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/nuxt.ts#L18
  hooks,
  hook,
  callHook,

  // サーバーサイドでのみアクセス可能
  ssrContext: {
    url,
    req,
    res,
    runtimeConfig,
    noSSR,
  },

  // これは文字列化されてサーバーからクライアントに渡されます
  payload: {
    serverRendered: true,
    data: {},
    state: {}
  }

  provide: (name: string, value: any) => void
}
```

詳細については、[ソースコード](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/nuxt.ts)をチェックしてください。

## ランタイムコンテキスト vs. ビルドコンテキスト

Nuxt は Node.js を使用してプロジェクトをビルドしてバンドルしますが、ランタイム側も持っています。

どちらの領域も拡張できますが、ランタイムコンテキストはビルド時から分離されています。したがって、ランタイム設定以外の状態、コード、またはコンテキストを共有すべきではありません！

`nuxt.config` と [Nuxt モジュール](/docs/guide/going-further/modules)はビルドコンテキストを拡張するために使用でき、[Nuxt プラグイン](/docs/guide/directory-structure/plugins)はランタイムを拡張するために使用できます。

プロダクション用のアプリケーションをビルドする際、`nuxt build` は `nuxt.config` と [Nuxt モジュール](/docs/guide/going-further/modules)から独立した、`.output` ディレクトリ内にスタンドアロンビルドを生成します。
