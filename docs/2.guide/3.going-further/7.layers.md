Nuxt レイヤーは、モノレポ内、git リポジトリ、または npm パッケージから、部分的な Nuxt アプリケーションを共有して再利用するために使用できる強力な機能です。レイヤーの構造は標準的な Nuxt アプリケーションとほぼ同一であり、作成や保守が簡単になります。

:read-more{to="/docs/getting-started/layers"}

最小限の Nuxt レイヤーディレクトリは、それがレイヤーであることを示す [`nuxt.config.ts`](/docs/guide/directory-structure/nuxt-config) ファイルを含む必要があります。

```ts [base/nuxt.config.ts]
export default defineNuxtConfig({})
```

さらに、レイヤーディレクトリ内の特定の他のファイルは、このレイヤーを拡張するプロジェクトのために Nuxt によって自動スキャンされ、使用されます。

- [`components/*`](/docs/guide/directory-structure/components)   - デフォルトコンポーネントを拡張
- [`composables/*`](/docs/guide/directory-structure/composables)  - デフォルト Composables を拡張
- [`layouts/*`](/docs/guide/directory-structure/layouts)  - デフォルトレイアウトを拡張
- [`pages/*`](/docs/guide/directory-structure/pages)        - デフォルトページを拡張
- [`plugins/*`](/docs/guide/directory-structure/plugins)        - デフォルトプラグインを拡張
- [`server/*`](/docs/guide/directory-structure/server)       - デフォルトサーバーエンドポイントとミドルウェアを拡張
- [`utils/*`](/docs/guide/directory-structure/utils)   - デフォルトユーティリティを拡張
- [`nuxt.config.ts`](/docs/guide/directory-structure/nuxt-config)- デフォルト Nuxt 設定を拡張
- [`app.config.ts`](/docs/guide/directory-structure/app-config)  - デフォルトアプリ設定を拡張

## 基本例

::code-group

  ```ts [nuxt.config.ts]
  export default defineNuxtConfig({
    extends: [
      './base'
    ]
  })
  ```

  ```vue [app.vue]
    <template>
      <BaseComponent/>
    </template>
  ```

  ```ts [base/nuxt.config.ts]
    export default defineNuxtConfig({
      // base nuxt.config.ts から拡張！
      app: {
        head: {
          title: '設定の拡張は楽しい！',
          meta: [
            { name: 'description', content: 'Nuxt の extends 機能を使用しています！' }
          ],
        }
      }
    })
  ```

  ```vue [base/components/BaseComponent.vue]
    <template>
      <h1>コンポーネントの拡張は楽しい！</h1>
    </template>
  ```

::

## スターターテンプレート

開始するには、[nuxt/starter/layer テンプレート](https://github.com/nuxt/starter/tree/layer)でレイヤーを初期化できます。これにより、構築できる基本的な構造が作成されます。開始するには、ターミナルでこのコマンドを実行してください：

```bash [Terminal]
npm create nuxt -- --template layer nuxt-layer
```

次のステップについては README の指示に従ってください。

## レイヤーの公開

リモートソースまたは npm パッケージを使用してレイヤーを公開して共有できます。

### Git リポジトリ

Git リポジトリを使用して Nuxt レイヤーを共有できます。いくつかの例：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    'github:username/repoName',        // GitHub リモートソース
    'github:username/repoName/base',   // /base ディレクトリ内の GitHub リモートソース
    'github:username/repoName#dev',    // dev ブランチからの GitHub リモートソース
    'github:username/repoName#v1.0.0', // v1.0.0 タグからの GitHub リモートソース
    'gitlab:username/repoName',        // GitLab リモートソースの例
    'bitbucket:username/repoName',     // Bitbucket リモートソースの例
  ]
})
```

::tip
プライベートリモートソースを拡張したい場合は、トークンを提供するために環境変数 `GIGET_AUTH=<token>` を追加する必要があります。
::

::tip
セルフホストされた GitHub または GitLab インスタンスからリモートソースを拡張したい場合は、環境変数 `GIGET_GITHUB_URL=<url>` または `GIGET_GITLAB_URL=<url>` で URL を提供するか、`nuxt.config` の [the `auth` option](https://github.com/unjs/c12#extending-config-layer-from-remote-sources) で直接設定する必要があります。
::

::warning
リモートソースをレイヤーとして拡張している場合、Nuxt の外部でその依存関係にアクセスできないことに注意してください。たとえば、リモートレイヤーが eslint プラグインに依存している場合、これはあなたの eslint 設定で使用できません。これは、これらの依存関係がパッケージマネージャーがアクセスできない特別な場所（`node_modules/.c12/layer_name/node_modules/`）に配置されるためです。
::

::note
Git リモートソースを使用する際、レイヤーに npm 依存関係があり、それらをインストールしたい場合は、レイヤーオプションで `install: true` を指定することで実行できます。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    ['github:username/repoName', { install: true }]
  ]
})
```
::

### npm パッケージ

拡張したいファイルと依存関係を含む npm パッケージとして Nuxt レイヤーを公開できます。これにより、設定を他の人と共有したり、複数のプロジェクトで使用したり、プライベートで使用したりできます。

npm パッケージから拡張するには、モジュールが npm に公開され、ユーザーのプロジェクトに devDependency としてインストールされていることを確認する必要があります。その後、モジュール名を使用して現在の Nuxt 設定を拡張できます：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // スコープ付き Node モジュール
    '@scope/moduleName',
    // または単にモジュール名
    'moduleName'
  ]
})
```

レイヤーディレクトリを npm パッケージとして公開するには、`package.json` に正しいプロパティが入力されていることを確認する必要があります。これにより、パッケージが公開される際にファイルが含まれることが保証されます。

```json [package.json]
{
  "name": "my-theme",
  "version": "1.0.0",
  "type": "module",
  "main": "./nuxt.config.ts",
  "dependencies": {},
  "devDependencies": {
    "nuxt": "^3.0.0"
  }
}
```

::important
レイヤーでインポートされる依存関係は、`dependencies` に**明示的に追加**するようにしてください。`nuxt` 依存関係や、公開前のレイヤーのテストにのみ使用されるものは、`devDependencies` フィールドに残しておくべきです。
::

これで、モジュールを npm に公開またはプライベートで公開することができます。

::important
レイヤーをプライベート npm パッケージとして公開する場合は、Node モジュールをダウンロードするために npm で認証するためにログインすることを確認する必要があります。
::

## ティップス

### 名前付きレイヤーエイリアス

自動スキャンされるレイヤー（`~~/layers` ディレクトリから）は自動的にエイリアスを作成します。たとえば、`~~/layers/test` レイヤーには `#layers/test` でアクセスできます。

他のレイヤーに名前付きレイヤーエイリアスを作成したい場合は、レイヤーの設定で名前を指定できます。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  $meta: {
    name: 'example',
  },
})
```

これにより、レイヤーを指す `#layers/example` のエイリアスが作成されます。

### 相対パスとエイリアス

レイヤーコンポーネントや Composables でグローバルエイリアス（`~/` や `@/` など）を使用してインポートする場合、これらのエイリアスはユーザーのプロジェクトパスに相対して解決されることに注意してください。回避策として、**相対パスを使用**してインポートするか、名前付きレイヤーエイリアスを使用できます。

また、レイヤーの `nuxt.config` ファイルで相対パスを使用する場合（ネストした `extends` を除く）、レイヤーではなくユーザーのプロジェクトに相対して解決されます。回避策として、`nuxt.config` で完全に解決されたパスを使用します：

```js [nuxt.config.ts]
import { fileURLToPath } from 'url'
import { dirname, join } from 'path'

const currentDir = dirname(fileURLToPath(import.meta.url))

export default defineNuxtConfig({
  css: [
    join(currentDir, './assets/main.css')
  ]
})
```

## Nuxt モジュールのマルチレイヤーサポート

モジュールのカスタムマルチレイヤー処理をサポートするために、内部配列 `nuxt.options._layers` を使用できます。

```ts [modules/my-module.ts]
export default defineNuxtModule({
  setup(_options, nuxt) {
    for (const layer of nuxt.options._layers) {
      // 各レイヤーで拡張するためにカスタムディレクトリの存在をチェックできます
      console.log('Custom extension for', layer.cwd, layer.config)
    }
  }
})
```

**注意事項：**
- `_layers` 配列の早い項目は優先度が高く、後の項目をオーバーライドします
- ユーザーのプロジェクトは `_layers` 配列の最初の項目です
