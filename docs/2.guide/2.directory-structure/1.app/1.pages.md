::note
アプリケーションのバンドルサイズを削減するため、このディレクトリは**任意**です。つまり、[`app.vue`](/docs/guide/directory-structure/app) のみを使用する場合は [`vue-router`](https://router.vuejs.org) が含まれません。ページシステムを強制するには、`nuxt.config` で `pages: true` を設定するか、[`router.options.ts`](/docs/guide/recipes/custom-routing#using-approuteroptions) を配置してください。
::

## 使用方法

ページは Vue コンポーネントであり、Nuxt がサポートする任意の[有効な拡張子](/docs/api/configuration/nuxt-config#extensions)を持つことができます（デフォルトでは `.vue`、`.js`、`.jsx`、`.mjs`、`.ts`、または `.tsx`）。

Nuxt は `~/pages/` ディレクトリ内のすべてのページに対して自動的にルートを作成します。

::code-group

```vue [pages/index.vue]
<template>
  <h1>インデックスページ</h1>
</template>
```

```ts twoslash [pages/index.ts]
// https://vuejs.org/guide/extras/render-function.html
export default defineComponent({
  render () {
    return h('h1', 'インデックスページ')
  }
})
```

```tsx twoslash [pages/index.tsx]
// https://nuxt.com/docs/examples/advanced/jsx
// https://vuejs.org/guide/extras/render-function.html#jsx-tsx
export default defineComponent({
  render () {
    return <h1>インデックスページ</h1>
  }
})
```

::

`pages/index.vue` ファイルはアプリケーションの `/` ルートにマッピングされます。

[`app.vue`](/docs/guide/directory-structure/app) を使用している場合は、現在のページを表示するために [`<NuxtPage/>`](/docs/api/components/nuxt-page) コンポーネントを使用するようにしてください：

```vue [app.vue]
<template>
  <div>
    <!-- すべてのページで共有されるマークアップ、例：NavBar -->
    <NuxtPage />
  </div>
</template>
```

ページ間の[ルート遷移](/docs/getting-started/transitions)を可能にするため、ページは**単一のルート要素を持つ必要があります**。HTML コメントも要素として扱われます。

これは、ルートがサーバーレンダリングまたは静的生成されるときは、その内容を正しく表示できることを意味しますが、クライアントサイドナビゲーション中にそのルートにナビゲートすると、ルート間の遷移が失敗し、ルートがレンダリングされないことがわかります。

単一のルート要素を持つページがどのようなものかを示すいくつかの例をここに挙げます：

::code-group

```vue [pages/working.vue]
<template>
  <div>
    <!-- このページは正しく単一のルート要素のみを持っています -->
    ページコンテンツ
  </div>
</template>
```

```vue [pages/bad-1.vue]
<template>
  <!-- このページはクライアントサイドナビゲーション中のルート変更時にレンダリングされません。このコメントのためです -->
  <div>ページコンテンツ</div>
</template>
```

```vue [pages/bad-2.vue]
<template>
  <div>このページは</div>
  <div>複数のルート要素を持っており</div>
  <div>クライアントサイドナビゲーション中のルート変更時にレンダリングされません</div>
</template>
```

::

## 動的ルート

角括弧内に何かを配置すると、それは[動的ルート](https://router.vuejs.org/guide/essentials/dynamic-matching.html)パラメーターになります。複数のパラメーターと非動的テキストをファイル名やディレクトリ内で混在させることができます。

パラメーターを _任意_ にしたい場合は、二重角括弧で囲む必要があります。例えば、`~/pages/[[slug]]/index.vue` または `~/pages/[[slug]].vue` は `/` と `/test` の両方にマッチします。

```bash [ディレクトリ構造]
-| pages/
---| index.vue
---| users-[group]/
-----| [id].vue
```

上記の例では、コンポーネント内で `$route` オブジェクトを介して group/id にアクセスできます：

```vue [pages/users-[group\\]/[id\\].vue]
<template>
  <p>{{ $route.params.group }} - {{ $route.params.id }}</p>
</template>
```

`/users-admins/123` にナビゲートすると次のようにレンダリングされます：

```html
<p>admins - 123</p>
```

Composition API を使用してルートにアクセスしたい場合は、Options API の `this.$route` のようにルートにアクセスできるグローバルな [`useRoute`](/docs/api/composables/use-route) 関数があります。

```vue twoslash
<script setup lang="ts">
const route = useRoute()

if (route.params.group === 'admins' && !route.params.id) {
  console.log('警告！ユーザーが認証されていることを確認してください！')
}
</script>
```

::note
名前付き親ルートは、ネストされた動的ルートよりも優先されます。`/foo/hello` ルートの場合、`~/pages/foo.vue` は `~/pages/foo/[slug].vue` よりも優先されます。:br `/foo` と `/foo/hello` を異なるページでマッチさせるには、`~/pages/foo/index.vue` と `~/pages/foo/[slug].vue` を使用してください。
::

## キャッチオールルート

キャッチオールルートが必要な場合は、`[...slug].vue` のような名前のファイルを使用して作成します。これはそのパス下の _すべて_ のルートにマッチします。

```vue [pages/[...slug\\].vue]
<template>
  <p>{{ $route.params.slug }}</p>
</template>
```

`/hello/world` にナビゲートすると次のようにレンダリングされます：

```html
<p>["hello", "world"]</p>
```

## ネストされたルート

`<NuxtPage>` を使用して[ネストされたルート](https://next.router.vuejs.org/guide/essentials/nested-routes.html)を表示することが可能です。

例：

```bash [ディレクトリ構造]
-| pages/
---| parent/
-----| child.vue
---| parent.vue
```

このファイルツリーは次のルートを生成します：

```js
[
  {
    path: '/parent',
    component: '~/pages/parent.vue',
    name: 'parent',
    children: [
      {
        path: 'child',
        component: '~/pages/parent/child.vue',
        name: 'parent-child'
      }
    ]
  }
]
```

`child.vue` コンポーネントを表示するには、`pages/parent.vue` 内に `<NuxtPage>` コンポーネントを挿入する必要があります：

```vue {}[pages/parent.vue]
<template>
  <div>
    <h1>私は親ビューです</h1>
    <NuxtPage :foobar="123" />
  </div>
</template>
```

```vue {}[pages/parent/child.vue]
<script setup lang="ts">
const props = defineProps(['foobar'])

console.log(props.foobar)
</script>
```

### 子ルートキー

`<NuxtPage>` コンポーネントがいつ再レンダリングされるかをより細かく制御したい場合（例えば、遷移のため）、`pageKey` prop を介して文字列または関数を渡すか、`definePageMeta` を介して `key` 値を定義できます：

```vue {}[pages/parent.vue]
<template>
  <div>
    <h1>私は親ビューです</h1>
    <NuxtPage :page-key="route => route.fullPath" />
  </div>
</template>
```

または、代わりに：

```vue twoslash {}[pages/parent/child.vue]
<script setup lang="ts">
definePageMeta({
  key: route => route.fullPath
})
</script>
```

## ルートグループ

場合によっては、ファイルベースルーティングに影響を与えない方法で一連のルートをグループ化したいことがあります。この目的のために、括弧 `(` と `)` で囲まれたフォルダにファイルを配置できます。

例えば：

```bash [ディレクトリ構造]
-| pages/
---| index.vue
---| (marketing)/
-----| about.vue
-----| contact.vue
```

これにより、アプリケーションで `/`、`/about`、`/contact` ページが生成されます。`marketing` グループは URL 構造の目的では無視されます。

## ページメタデータ

アプリケーションの各ルートのメタデータを定義したい場合があります。これは `definePageMeta` マクロを使用して行うことができ、`<script>` と `<script setup>` の両方で動作します：

```vue twoslash
<script setup lang="ts">
definePageMeta({
  title: 'マイホームページ'
})
</script>
```

このデータは、アプリケーションの残りの部分から `route.meta` オブジェクトを介してアクセスできます。

```vue twoslash
<script setup lang="ts">
const route = useRoute()

console.log(route.meta.title) // マイホームページ
</script>
```

ネストされたルートを使用している場合、これらすべてのルートからのページメタデータが単一のオブジェクトにマージされます。ルートメタの詳細については、[vue-router ドキュメント](https://router.vuejs.org/guide/advanced/meta.html#route-meta-fields)を参照してください。

`defineEmits` や `defineProps`（[Vue ドキュメント](https://vuejs.org/api/sfc-script-setup.html#defineprops-defineemits)参照）と同様に、`definePageMeta` は**コンパイラーマクロ**です。コンパイル時に処理されるため、コンポーネント内で参照することはできません。代わりに、それに渡されたメタデータはコンポーネントの外に巻き上げられます。
したがって、ページメタオブジェクトはコンポーネントを参照できません。ただし、インポートされたバインディングや、ローカルで定義された**純粋関数**を参照することはできます。

::warning
リアクティブなデータや副作用を引き起こす関数を参照しないようにしてください。これは予期しない動作を引き起こす可能性があります。
::

```vue
<script setup lang="ts">
import { someData } from '~/utils/example'

function validateIdParam(route) {
  return route.params.id && !isNaN(Number(route.params.id))
}

const title = ref('')

definePageMeta({
  validate: validateIdParam,
  someData,
  title,    // これをしてはいけません。ref がコンポーネントの外に巻き上げられます
})
</script>
```

### 特別なメタデータ

もちろん、アプリケーション全体で独自の用途のためにメタデータを定義することは歓迎されます。ただし、`definePageMeta` で定義される一部のメタデータには特別な目的があります：

#### `alias`

ページエイリアスを定義できます。これにより、異なるパスから同じページにアクセスできます。[vue-router ドキュメント](https://router.vuejs.org/guide/essentials/redirect-and-alias.html#Alias)で定義されているように、文字列または文字列の配列のいずれかです。

#### `keepalive`

`definePageMeta` で `keepalive: true` を設定すると、Nuxt は自動的にページを [Vue の `<KeepAlive>` コンポーネント](https://vuejs.org/guide/built-ins/keep-alive.html#keepalive)でラップします。これは、例えば、動的な子ルートを持つ親ルートで、ルート変更間でページ状態を保持したい場合に有用です。

親ルートの状態を保持することが目標の場合は、次の構文を使用してください：`<NuxtPage keepalive />`。また、`<KeepAlive>` に渡すプロパティを設定することもできます（[完全なリスト](https://vuejs.org/api/built-in-components.html#keepalive)を参照）。

このプロパティのデフォルト値を [`nuxt.config` で設定](/docs/api/nuxt-config#keepalive)できます。

#### `key`

[上記を参照](#child-route-keys)。

#### `layout`

ルートをレンダリングするために使用されるレイアウトを定義できます。これは false（任意のレイアウトを無効にする）、文字列、または何らかの方法でリアクティブにしたい場合は ref/computed のいずれかです。[レイアウトについて詳しく](/docs/guide/directory-structure/layouts)。

#### `layoutTransition` と `pageTransition`

ページとレイアウトをラップする `<transition>` コンポーネントの遷移プロパティを定義するか、そのルートの `<transition>` ラッパーを無効にするために `false` を渡すことができます。[渡すことができるオプションのリスト](https://vuejs.org/api/built-in-components.html#transition)を参照するか、[遷移の仕組みについて詳しく](https://vuejs.org/guide/built-ins/transition.html#transition)お読みください。

これらのプロパティのデフォルト値を [`nuxt.config` で設定](/docs/api/nuxt-config#layouttransition)できます。

#### `middleware`

このページを読み込む前に適用するミドルウェアを定義できます。一致する親/子ルートで使用される他のすべてのミドルウェアとマージされます。文字列、関数（[グローバル前ガードパターン](https://router.vuejs.org/guide/advanced/navigation-guards.html#global-before-guards)に従う匿名/インラインミドルウェア関数）、または文字列/関数の配列のいずれかです。[名前付きミドルウェアについて詳しく](/docs/guide/directory-structure/middleware)。

#### `name`

このページのルートの名前を定義できます。

#### `path`

ファイル名で表現できるよりも複雑なパターンがある場合は、パスマッチャーを定義できます。詳細については、[`vue-router` ドキュメント](https://router.vuejs.org/guide/essentials/route-matching-syntax.html#custom-regex-in-params)を参照してください。

#### `props`

ページコンポーネントに渡される props としてルート `params` にアクセスできます。詳細については、[`vue-router` ドキュメント](https://router.vuejs.org/guide/essentials/passing-props)を参照してください。

### カスタムメタデータの型付け

ページにカスタムメタデータを追加する場合、型安全な方法で行いたい場合があります。`definePageMeta` が受け入れるオブジェクトの型を拡張することが可能です：

```ts [index.d.ts]
declare module '#app' {
  interface PageMeta {
    pageType?: string
  }
}

// 型を拡張する際は、何かをインポート/エクスポートすることが常に重要です
export {}
```

## ナビゲーション

アプリケーションのページ間をナビゲートするには、[`<NuxtLink>`](/docs/api/components/nuxt-link) コンポーネントを使用する必要があります。

このコンポーネントは Nuxt に含まれているため、他のコンポーネントのようにインポートする必要はありません。

`pages` フォルダ内の `index.vue` ページへの簡単なリンク：

```vue
<template>
  <NuxtLink to="/">ホームページ</NuxtLink>
</template>
```

::read-more{to="/docs/api/components/nuxt-link"}
`<NuxtLink>` の使用方法について詳しく学ぶ。
::

## プログラマティックナビゲーション

Nuxt は `navigateTo()` ユーティリティメソッドを通じてプログラマティックナビゲーションを可能にします。このユーティリティメソッドを使用することで、アプリケーション内でプログラマティックにユーザーをナビゲートできます。これは、ユーザーからの入力を受け取り、アプリケーション全体で動的にナビゲートするのに最適です。この例では、ユーザーが検索フォームを送信するときに呼び出される `navigate()` という簡単なメソッドがあります。

::note
`navigateTo` では常に `await` を確実に行うか、関数から返すことでその結果をチェーンしてください。
::

```vue twoslash
<script setup lang="ts">
const name = ref('')
const type = ref(1)

function navigate(){
  return navigateTo({
    path: '/search',
    query: {
      name: name.value,
      type: type.value
    }
  })
}
</script>
```

## クライアント専用ページ

`.client.vue` サフィックスを付けることで、ページを[クライアント専用](/docs/guide/directory-structure/components#client-components)として定義できます。このページの内容はサーバーでレンダリングされません。

## サーバー専用ページ

`.server.vue` サフィックスを付けることで、ページを[サーバー専用](/docs/guide/directory-structure/components#server-components)として定義できます。`vue-router` によって制御されるクライアントサイドナビゲーションを使用してページにナビゲートできますが、自動的にサーバーコンポーネントでレンダリングされ、ページをレンダリングするために必要なコードはクライアントサイドバンドルに含まれません。

::warning
サーバー専用ページは単一のルート要素を持つ必要があります。（HTML コメントも要素として扱われます。）
::

## 複数のページディレクトリ

デフォルトでは、すべてのページはプロジェクトのルートにある一つの `pages` ディレクトリに配置する必要があります。

ただし、[Nuxt レイヤー](/docs/getting-started/layers)を使用してアプリケーションのページのグループ化を作成できます：

```bash [ディレクトリ構造]
-| some-app/
---| nuxt.config.ts
---| pages/
-----| app-page.vue
-| nuxt.config.ts
```

```ts twoslash [some-app/nuxt.config.ts]
// some-app/nuxt.config.ts
export default defineNuxtConfig({
})
```

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['./some-app'],
})
```
