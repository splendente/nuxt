Nuxt はアプリケーション全体で使用できるカスタマイズ可能な**ルートミドルウェア**フレームワークを提供し、特定のルートにナビゲートする前に実行したいコードを抽出するのに理想的です。

ルートミドルウェアには 3 つの種類があります：

1. 匿名（またはインライン）ルートミドルウェアは、ページ内で直接定義されます。
2. 名前付きルートミドルウェアは、`middleware/` に配置され、ページで使用される際に非同期インポートで自動的に読み込まれます。
3. グローバルルートミドルウェアは、`middleware/` に `.global` サフィックス付きで配置され、すべてのルート変更で実行されます。

最初の 2 つのルートミドルウェアは [`definePageMeta`](/docs/api/utils/define-page-meta) で定義できます。

::note
ミドルウェアの名前はケバブケースに正規化されます：`myMiddleware` は `my-middleware` になります。
::

::note
ルートミドルウェアは Nuxt アプリの Vue 部分で実行されます。似た名前にもかかわらず、アプリの Nitro サーバー部分で実行される[サーバーミドルウェア](/docs/guide/directory-structure/server#server-middleware)とは完全に異なります。
::

## 使用方法

ルートミドルウェアは、現在のルートと次のルートを引数として受け取るナビゲーションガードです。

```ts twoslash [middleware/my-middleware.ts]
export default defineNuxtRouteMiddleware((to, from) => {
  if (to.params.id === '1') {
    return abortNavigation()
  }
  // 実際のアプリではおそらくすべてのルートを `/` にリダイレクトしないでしょうが
  // リダイレクト前に `to.path` をチェックすることが重要です。そうしないと
  // 無限リダイレクトループに陥る可能性があります
  if (to.path !== '/') {
    return navigateTo('/')
  }
})
```

Nuxt はミドルウェアから直接返すことができる 2 つのグローバルに利用可能なヘルパーを提供します。

1. [`navigateTo`](/docs/api/utils/navigate-to) - 指定されたルートにリダイレクトします
2. [`abortNavigation`](/docs/api/utils/abort-navigation) - オプションのエラーメッセージでナビゲーションを中止します。

`vue-router` の[ナビゲーションガード](https://router.vuejs.org/guide/advanced/navigation-guards.html#global-before-guards)とは異なり、3 番目の `next()` 引数は渡されず、**リダイレクトやルートキャンセルはミドルウェアから値を返すことで処理されます**。

可能な戻り値は：

* 何も返さない（単純な `return` または全く return しない） - ナビゲーションをブロックせず、次のミドルウェア関数があればそれに移動し、そうでなければルートナビゲーションを完了します
* `return navigateTo('/')` - 指定されたパスにリダイレクトし、サーバーサイドでリダイレクトが発生した場合はリダイレクトコードを [`302` Found](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/302) に設定します
* `return navigateTo('/', { redirectCode: 301 })` - 指定されたパスにリダイレクトし、サーバーサイドでリダイレクトが発生した場合はリダイレクトコードを [`301` Moved Permanently](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/301) に設定します
* `return abortNavigation()` - 現在のナビゲーションを停止します
* `return abortNavigation(error)` - エラーで現在のナビゲーションを拒否します

:read-more{to="/docs/api/utils/navigate-to"}
:read-more{to="/docs/api/utils/abort-navigation"}

::important
リダイレクトやナビゲーション停止には上記のヘルパー関数の使用を推奨します。[vue-router ドキュメント](https://router.vuejs.org/guide/advanced/navigation-guards.html#global-before-guards)で説明されている他の可能な戻り値も動作する可能性がありますが、将来的に破壊的変更がある可能性があります。
::

## ミドルウェアの順序

ミドルウェアは次の順序で実行されます：

1. グローバルミドルウェア
2. ページで定義されたミドルウェアの順序（配列構文で複数のミドルウェアが宣言されている場合）

例えば、次のミドルウェアとコンポーネントがあるとします：

```bash [middleware/ directory]
-| middleware/
---| analytics.global.ts
---| setup.global.ts
---| auth.ts
```

```vue twoslash [pages/profile.vue]
<script setup lang="ts">
definePageMeta({
  middleware: [
    function (to, from) {
      // カスタムインラインミドルウェア
    },
    'auth',
  ],
});
</script>
```

ミドルウェアは次の順序で実行されることが期待できます：

1. `analytics.global.ts`
2. `setup.global.ts`
3. カスタムインラインミドルウェア
4. `auth.ts`

### グローバルミドルウェアの順序付け

デフォルトでは、グローバルミドルウェアはファイル名に基づいてアルファベット順で実行されます。

ただし、特定の順序を定義したい場合もあるでしょう。例えば、前のシナリオで `setup.global.ts` が `analytics.global.ts` より前に実行される必要がある場合です。その場合は、グローバルミドルウェアに「アルファベット順」の番号を付けることを推奨します。

```bash [Directory structure]
-| middleware/
---| 01.setup.global.ts
---| 02.analytics.global.ts
---| auth.ts
```

::note
「アルファベット順」の番号付けに慣れていない場合は、ファイル名は数値としてではなく文字列としてソートされることを覚えておいてください。例えば、`10.new.global.ts` は `2.new.global.ts` より前に来るでしょう。これが例で一桁の数字に `0` を付ける理由です。
::

## ミドルウェアの実行タイミング

サイトがサーバーレンダリングまたは生成されている場合、初期ページのミドルウェアはページがレンダリングされるときとクライアントで再度実行されます。これは、ミドルウェアがブラウザー環境を必要とする場合、生成されたサイトがある場合、レスポンスを積極的にキャッシュする場合、またはローカルストレージから値を読み取りたい場合に必要になる可能性があります。

ただし、この動作を避けたい場合は次のようにできます：

```ts twoslash [middleware/example.ts]
export default defineNuxtRouteMiddleware(to => {
  // サーバーでミドルウェアをスキップ
  if (import.meta.server) return
  // クライアントサイドでミドルウェアを完全にスキップ
  if (import.meta.client) return
  // または初期クライアント読み込みでのみミドルウェアをスキップ
  const nuxtApp = useNuxtApp()
  if (import.meta.client && nuxtApp.isHydrating && nuxtApp.payload.serverRendered) return
})
```

これは、サーバーでミドルウェアでエラーを投げ、エラーページがレンダリングされた場合でも真です。ミドルウェアはブラウザーで再度実行されます。

::note
エラーページのレンダリングは完全に別のページ読み込みを意味し、登録されたミドルウェアが再度実行されます。ミドルウェアで [`useError`](/docs/getting-started/error-handling#useerror) を使用してエラーが処理されているかどうかを確認できます。
::

## ミドルウェアの動的追加

プラグイン内などから [`addRouteMiddleware()`](/docs/api/utils/add-route-middleware) ヘルパー関数を使用して、グローバルまたは名前付きルートミドルウェアを手動で追加することが可能です。

```ts twoslash
export default defineNuxtPlugin(() => {
  addRouteMiddleware('global-test', () => {
    console.log('このグローバルミドルウェアはプラグインで追加され、すべてのルート変更で実行されます')
  }, { global: true })

  addRouteMiddleware('named-test', () => {
    console.log('この名前付きミドルウェアはプラグインで追加され、同じ名前の既存のミドルウェアを上書きします')
  })
})
```

## 例

```bash [Directory Structure]
-| middleware/
---| auth.ts
```

ページファイルで、このルートミドルウェアを参照できます：

```vue twoslash
<script setup lang="ts">
definePageMeta({
  middleware: ["auth"]
  // または middleware: 'auth'
})
</script>
```

これで、そのページへのナビゲーションが完了する前に、`auth` ルートミドルウェアが実行されます。

## ビルド時でのミドルウェア設定

各ページで `definePageMeta` を使用する代わりに、`pages:extend` フック内で名前付きルートミドルウェアを追加できます。

```ts twoslash [nuxt.config.ts]
import type { NuxtPage } from 'nuxt/schema'

export default defineNuxtConfig({
  hooks: {
    'pages:extend' (pages) {
      function setMiddleware (pages: NuxtPage[]) {
        for (const page of pages) {
          if (/* 何らかの条件 */ true) {
            page.meta ||= {}
            // これはページで `definePageMeta` で設定されたミドルウェアを上書きすることに注意
            page.meta.middleware = ['named']
          }
          if (page.children) {
            setMiddleware(page.children)
          }
        }
      }
      setMiddleware(pages)
    }
  }
})
```
