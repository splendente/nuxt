Nuxt はこれらのディレクトリ内のファイルを自動的にスキャンし、Hot Module Replacement（HMR）サポートで API やサーバーハンドラーを登録します。

```bash [Directory structure]
-| server/
---| api/
-----| hello.ts      # /api/hello
---| routes/
-----| bonjour.ts    # /bonjour
---| middleware/
-----| log.ts        # すべてのリクエストをログ出力
```

各ファイルは `defineEventHandler()` または `eventHandler()`（エイリアス）で定義されたデフォルト関数をエクスポートする必要があります。

ハンドラーは JSON データ、`Promise`、または `event.node.res.end()` を使用してレスポンスを送信できます。

```ts twoslash [server/api/hello.ts]
export default defineEventHandler((event) => {
  return {
    hello: 'world'
  }
})
```

この API をページやコンポーネントから汎用的に呼び出すことができます：

```vue [pages/index.vue]
<script setup lang="ts">
const { data } = await useFetch('/api/hello')
</script>

<template>
  <pre>{{ data }}</pre>
</template>
```

## Server Routes

`~/server/api` 内のファイルは自動的にルートに `/api` プレフィックスが付与されます。

:video-accordion{title="Vue School の API ルートに関する動画を視聴する" videoId="761468863" platform="vimeo"}

`/api` プレフィックスなしでサーバールートを追加するには、`~/server/routes` ディレクトリに配置してください。

**例：**

```ts [server/routes/hello.ts]
export default defineEventHandler(() => 'Hello World!')
```

上記の例では、`/hello` ルートは <http://localhost:3000/hello> でアクセス可能になります。

::note
現在のところ、サーバールートは [pages](/docs/guide/directory-structure/pages#dynamic-routes) のような動的ルートの完全な機能をサポートしていないことに注意してください。
::

## Server Middleware

Nuxt は `~/server/middleware` 内のすべてのファイルを自動的に読み込み、プロジェクト用のサーバーミドルウェアを作成します。

ミドルウェアハンドラーは、ヘッダーの追加やチェック、リクエストのログ記録、またはイベントのリクエストオブジェクトの拡張を行うために、他のサーバールートより前にすべてのリクエストで実行されます。

::note
ミドルウェアハンドラーは何も返すべきではなく（リクエストを閉じたり応答したりもせず）、リクエストコンテキストの検査や拡張、またはエラーの投げるのみを行うべきです。
::

**例：**

```ts [server/middleware/log.ts]
export default defineEventHandler((event) => {
  console.log('New request: ' + getRequestURL(event))
})
```

```ts [server/middleware/auth.ts]
export default defineEventHandler((event) => {
  event.context.auth = { user: 123 }
})
```

## Server Plugins

Nuxt は `~/server/plugins` ディレクトリ内のすべてのファイルを自動的に読み込み、Nitro プラグインとして登録します。これにより、Nitro のランタイム動作を拡張し、ライフサイクルイベントにフックできます。

**例：**

```ts [server/plugins/nitroPlugin.ts]
export default defineNitroPlugin((nitroApp) => {
  console.log('Nitro plugin', nitroApp)
})
```

:read-more{to="https://nitro.build/guide/plugins" title="Nitro Plugins" target="_blank"}

## Server Utilities

サーバールートは便利なヘルパーセットが付属している [h3js/h3](https://github.com/h3js/h3) によって動作します。

:read-more{to="https://www.jsdocs.io/package/h3#package-index-functions" title="利用可能な H3 リクエストヘルパー" target="_blank"}

`~/server/utils` ディレクトリ内に独自のヘルパーを追加できます。

例えば、元のハンドラーをラップし、最終的なレスポンスを返す前に追加の操作を実行するカスタムハンドラーユーティリティを定義できます。

**例：**

```ts [server/utils/handler.ts]
import type { EventHandler, EventHandlerRequest } from 'h3'

export const defineWrappedResponseHandler = <T extends EventHandlerRequest, D> (
  handler: EventHandler<T, D>
): EventHandler<T, D> =>
  defineEventHandler<T>(async event => {
    try {
      // do something before the route handler
      const response = await handler(event)
      // do something after the route handler
      return { response }
    } catch (err) {
      // Error handling
      return { err }
    }
  })
```

## Recipes

### ルートパラメータ

サーバールートは `/api/hello/[name].ts` のようにファイル名内の角括弧で動的パラメータを使用でき、`event.context.params` 経由でアクセスできます。

```ts [server/api/hello/[name\\].ts]
export default defineEventHandler((event) => {
  const name = getRouterParam(event, 'name')

  return `Hello, ${name}!`
})
```

::tip{to="https://h3.dev/examples/validate-data#validate-params"}
あるいは、ランタイムと型安全性のために Zod などのスキーマバリデーターと組み合わせて `getValidatedRouterParams` を使用できます。
::

`/api/hello/nuxt` でこの API を汎用的に呼び出し、`Hello, nuxt!` を取得できるようになります。

### HTTP メソッドのマッチング

ハンドラーファイル名に `.get`、`.post`、`.put`、`.delete` などのサフィックスを付けて、リクエストの [HTTP メソッド](https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods)にマッチさせることができます。

```ts [server/api/test.get.ts]
export default defineEventHandler(() => 'Test get handler')
```

```ts [server/api/test.post.ts]
export default defineEventHandler(() => 'Test post handler')
```

上記の例では、`/test` をフェッチすると：

- **GET** メソッド：`Test get handler` を返す
- **POST** メソッド：`Test post handler` を返す
- その他のメソッド：405 エラーを返す

コードを異なる方法で構造化するために、ディレクトリ内で `index.[method].ts` を使用することもできます。これは API 名前空間の作成に便利です。

::code-group
```ts [server/api/foo/index.get.ts]
export default defineEventHandler((event) => {
  // handle GET requests for the `api/foo` endpoint
})
```
```ts [server/api/foo/index.post.ts]
export default defineEventHandler((event) => {
  // handle POST requests for the `api/foo` endpoint
})
```
```ts [server/api/foo/bar.get.ts]
export default defineEventHandler((event) => {
  // handle GET requests for the `api/foo/bar` endpoint
})
```
::

### キャッチオールルート

キャッチオールルートはフォールバックルートハンドリングに役立ちます。

例えば、`~/server/api/foo/[...].ts` という名前のファイルを作成すると、`/api/foo/bar/baz` など、どのルートハンドラーにもマッチしないすべてのリクエストに対するキャッチオールルートが登録されます。

```ts [server/api/foo/[...\\].ts]
export default defineEventHandler((event) => {
  // event.context.path to get the route path: '/api/foo/bar/baz'
  // event.context.params._ to get the route segment: 'bar/baz'
  return `Default foo handler`
})
```

`~/server/api/foo/[...slug].ts` を使用してキャッチオールルートに名前を設定し、`event.context.params.slug` 経由でアクセスできます。

```ts [server/api/foo/[...slug\\].ts]
export default defineEventHandler((event) => {
  // event.context.params.slug to get the route segment: 'bar/baz'
  return `Default foo handler`
})
```

### ボディハンドリング

```ts [server/api/submit.post.ts]
export default defineEventHandler(async (event) => {
  const body = await readBody(event)
  return { body }
})
```

::tip{to="https://unjs.io/blog/2023-08-15-h3-towards-the-edge-of-the-web#runtime-type-safe-request-utils"}
あるいは、ランタイムと型安全性のために Zod などのスキーマバリデーターと組み合わせて `readValidatedBody` を使用できます。
::

次のようにこの API を汎用的に呼び出すことができます：

```vue [app.vue]
<script setup lang="ts">
async function submit() {
  const { body } = await $fetch('/api/submit', {
    method: 'post',
    body: { test: 123 }
  })
}
</script>
```

::note
ファイル名に `submit.post.ts` を使用しているのは、リクエストボディを受け入れる `POST` メソッドのリクエストにのみマッチさせるためです。GET リクエスト内で `readBody` を使用すると、`readBody` は `405 Method Not Allowed` HTTP エラーを投げます。
::

### クエリパラメータ

サンプルクエリ `/api/query?foo=bar&baz=qux`

```ts [server/api/query.get.ts]
export default defineEventHandler((event) => {
  const query = getQuery(event)

  return { a: query.foo, b: query.baz }
})
```

::tip{to="https://unjs.io/blog/2023-08-15-h3-towards-the-edge-of-the-web#runtime-type-safe-request-utils"}
あるいは、ランタイムと型安全性のために Zod などのスキーマバリデーターと組み合わせて `getValidatedQuery` を使用できます。
::

### エラーハンドリング

エラーが投げられない場合、ステータスコード `200 OK` が返されます。

キャッチされていないエラーは `500 Internal Server Error` HTTP エラーを返します。

他のエラーコードを返すには、[`createError`](/docs/api/utils/create-error) で例外を投げます：

```ts [server/api/validation/[id\\].ts]
export default defineEventHandler((event) => {
  const id = parseInt(event.context.params.id) as number

  if (!Number.isInteger(id)) {
    throw createError({
      statusCode: 400,
      statusMessage: 'ID should be an integer',
    })
  }
  return 'All good'
})
```

### ステータスコード

他のステータスコードを返すには、[`setResponseStatus`](/docs/api/utils/set-response-status) ユーティリティを使用します。

例えば、`202 Accepted` を返すには

```ts [server/api/validation/[id\\].ts]
export default defineEventHandler((event) => {
  setResponseStatus(event, 202)
})
```

### ランタイム設定

::code-group
```ts [server/api/foo.ts]
export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig(event)

  const repo = await $fetch('https://api.github.com/repos/nuxt/nuxt', {
    headers: {
      Authorization: `token ${config.githubToken}`
    }
  })

  return repo
})
```
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    githubToken: ''
  }
})
```
```ini [.env]
NUXT_GITHUB_TOKEN='<my-super-token>'
```
::

::note
`useRuntimeConfig` への引数として `event` を渡すことはオプションですが、サーバールートにおいて実行時に[環境変数](/docs/guide/going-further/runtime-config#environment-variables)によって上書きされたランタイム設定を取得するためには、それを渡すことを推奨します。
::

### リクエストクッキー

```ts [server/api/cookies.ts]
export default defineEventHandler((event) => {

  return { cookies }
})
```

### コンテキストとヘッダーの転送

デフォルトでは、サーバールートで fetch リクエストを作成する際に、受信リクエストのヘッダーもリクエストコンテキストも転送されません。
サーバールートで fetch リクエストを作成する際にリクエストコンテキストとヘッダーを転送するには、`event.$fetch` を使用できます。

```ts [server/api/forward.ts]
export default defineEventHandler((event) => {
  return event.$fetch('/api/forwarded')
})
```

::note
**転送されるべきでない**ヘッダーはリクエストに**含まれません**。これらのヘッダーには、例えば次のものが含まれます：
`transfer-encoding`、`connection`、`keep-alive`、`upgrade`、`expect`、`host`、`accept`
::

### レスポンス後の Promise の待機

サーバーリクエストを処理する際に、クライアントへのレスポンスをブロックすべきでない非同期タスク（例えばキャッシュやログ記録）を実行する必要がある場合があります。`event.waitUntil` を使用して、レスポンスを遅らせることなくバックグラウンドで Promise を待機できます。

`event.waitUntil` メソッドはハンドラーが終了する前に待機される Promise を受け取り、サーバーがレスポンス送信後にすぐにハンドラーを終了させる場合でもタスクが完了することを保証します。これはランタイムプロバイダーと統合して、レスポンス送信後の非同期操作を処理するためのネイティブ機能を活用します。

```ts [server/api/background-task.ts]
const timeConsumingBackgroundTask = async () => {
  await new Promise((resolve) => setTimeout(resolve, 1000))
};

export default eventHandler((event) => {
  // schedule a background task without blocking the response
  event.waitUntil(timeConsumingBackgroundTask())

  // immediately send the response to the client
  return 'done'
});
```

## 高度な使用方法

### Nitro 設定

`nuxt.config` 内の `nitro` キーを使用して、[Nitro 設定](https://nitro.build/config)を直接設定できます。

::warning
これは高度なオプションです。カスタム設定は本番環境のデプロイに影響を与える可能性があります。Nuxt の semver-minor バージョンで Nitro がアップグレードされる際に設定インターフェースが時間とともに変更される可能性があります。
::

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // https://nitro.build/config
  nitro: {}
})
```

:read-more{to="/docs/guide/concepts/server-engine"}

### ネストされたルーター

```ts [server/api/hello/[...slug\\].ts]
import { createRouter, defineEventHandler, useBase } from 'h3'

const router = createRouter()

router.get('/test', defineEventHandler(() => 'Hello World'))

export default useBase('/api/hello', router.handler)
```

### ストリームの送信

::tip
これは実験的機能であり、すべての環境で利用可能です。
::

```ts [server/api/foo.get.ts]
import fs from 'node:fs'
import { sendStream } from 'h3'

export default defineEventHandler((event) => {
  return sendStream(event, fs.createReadStream('/path/to/file'))
})
```

### リダイレクトの送信

```ts [server/api/foo.get.ts]
export default defineEventHandler(async (event) => {
  await sendRedirect(event, '/path/redirect/to', 302)
})
```

### レガシーハンドラーまたはミドルウェア

```ts [server/api/legacy.ts]
export default fromNodeMiddleware((req, res) => {
  res.end('Legacy handler')
})
```

::important
レガシーサポートは [h3js/h3](https://github.com/h3js/h3) を使用して可能ですが、可能な限りレガシーハンドラーを避けることを推奨します。
::

```ts [server/middleware/legacy.ts]
export default fromNodeMiddleware((req, res, next) => {
  console.log('Legacy middleware')
  next()
})
```

::warning
`async` であるか `Promise` を返すレガシーミドルウェアと `next()` コールバックを組み合わせないでください。
::

### サーバーストレージ

Nitro はクロスプラットフォームの[ストレージレイヤー](https://nitro.build/guide/storage)を提供します。追加のストレージマウントポイントを設定するために、`nitro.storage` 、または[サーバープラグイン](#server-plugins)を使用できます。

**Redis ストレージの追加例：**

`nitro.storage` を使用：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    storage: {
      redis: {
        driver: 'redis',
        /* redis connector options */
        port: 6379, // Redis port
        host: "127.0.0.1", // Redis host
        username: "", // needs Redis >= 6
        password: "",
        db: 0, // Defaults to 0
        tls: {} // tls/ssl
      }
    }
  }
})
```

そして API ハンドラー内で：

```ts [server/api/storage/test.ts]
export default defineEventHandler(async (event) => {
  // List all keys with
  const keys = await useStorage('redis').getKeys()

  // Set a key with
  await useStorage('redis').setItem('foo', 'bar')

  // Remove a key with
  await useStorage('redis').removeItem('foo')

  return {}
})
```

::read-more{to="https://nitro.build/guide/storage" target="_blank"}
Nitro ストレージレイヤーについて詳しく読む。
::

あるいは、サーバープラグインとランタイム設定を使用してストレージマウントポイントを作成できます：

::code-group
```ts [server/plugins/storage.ts]
import redisDriver from 'unstorage/drivers/redis'

export default defineNitroPlugin(() => {
  const storage = useStorage()

  // Dynamically pass in credentials from runtime configuration, or other sources
  const driver = redisDriver({
      base: 'redis',
      host: useRuntimeConfig().redis.host,
      port: useRuntimeConfig().redis.port,
      /* other redis connector options */
    })

  // Mount driver
  storage.mount('redis', driver)
})
```

``` ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    redis: { // Default values
      host: '',
      port: 0,
      /* other redis connector options */
    }
  }
})
```
::
