## `extendPages`

Nuxt では、`pages` ディレクトリ内のファイル構造に基づいてルートが自動生成されます。ただし、これらのルートをカスタマイズしたいシナリオがある場合があります。たとえば、Nuxt によって生成されない動的ページのルートを追加する、既存のルートを削除する、またはルートの設定を変更する必要があるかもしれません。このようなカスタマイズのために、Nuxt は `extendPages` 機能を提供しており、ページ設定を拡張および変更できます。

::tip{icon="i-lucide-video" to="https://vueschool.io/lessons/extend-and-alter-nuxt-pages?friend=nuxt" target="_blank"}
extendPages についての Vue School のビデオを見る。
::

### 使用方法

```ts twoslash
import { createResolver, defineNuxtModule, extendPages } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const { resolve } = createResolver(import.meta.url)

    extendPages((pages) => {
      pages.unshift({
        name: 'prismic-preview',
        path: '/preview',
        file: resolve('runtime/preview.vue'),
      })
    })
  },
})
```

### 型

```ts
function extendPages(callback: (pages: NuxtPage[]) => void): void
```

### パラメーター

**callback**: ページ設定で呼び出される関数。要素を追加、削除、または変更することによってこの配列を変更できます。注意：提供されたページ配列を直接変更する必要があります。コピーされた配列への変更は設定に反映されません。

| プロパティ  | 型                                 | 必須     | 説明                                                                                         |
| ---------- | ---------------------------------- | -------- | -------------------------------------------------------------------------------------------- |
| `name`     | `string`                           | `false`  | ルートの名前。プログラマティックなナビゲーションとルートの識別に便利です。                    |
| `path`     | `string`                           | `false`  | ルートの URL パス。設定されていない場合、Nuxt はファイルの場所から推測します。                |
| `file`     | `string`                           | `false`  | ルートのコンポーネントとして使用される Vue ファイルへのパス。                                |
| `meta`     | `Record<string, any>`{lang="ts"}   | `false`  | ルートのカスタムメタデータ。レイアウト、ミドルウェア、またはナビゲーションガードで使用できます。|
| `alias`    | `string[] \| string`{lang="ts"}    | `false`  | ルートの1つまたは複数のエイリアスパス。複数の URL をサポートするのに便利です。                |
| `redirect` | `RouteLocationRaw`{lang="ts"}      | `false`  | ルートのリダイレクトルール。名前付きルート、オブジェクト、または文字列パスをサポートします。    |
| `children` | `NuxtPage[]`{lang="ts"}            | `false`  | レイアウトまたはビューのネストのためのこのルート下のネストした子ルート。                      |

## `extendRouteRules`

Nuxt は [Nitro](https://nitro.build/) サーバーエンジンによって動作します。Nitro を使用すると、高レベルのロジックを設定に直接組み込むことができ、これはリダイレクト、プロキシ、キャッシュ、ルートへのヘッダー追加などのアクションに便利です。この設定は、ルートパターンを特定のルート設定に関連付けることで動作します。

::tip
Nitro ルートルールについての詳細は [Nitro ドキュメント](https://nitro.build/guide/routing#route-rules) で読むことができます。
::

::tip{icon="i-lucide-video" to="https://vueschool.io/lessons/adding-route-rules-and-route-middlewares?friend=nuxt" target="_blank"}
ルートルールとルートミドルウェアの追加についての Vue School のビデオを見る。
::

### 使用方法

```ts twoslash
import { createResolver, defineNuxtModule, extendPages, extendRouteRules } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const { resolve } = createResolver(import.meta.url)

    extendPages((pages) => {
      pages.unshift({
        name: 'preview-new',
        path: '/preview-new',
        file: resolve('runtime/preview.vue'),
      })
    })

    extendRouteRules('/preview', {
      redirect: {
        to: '/preview-new',
        statusCode: 302,
      },
    })

    extendRouteRules('/preview-new', {
      cache: {
        maxAge: 60 * 60 * 24 * 7,
      },
    })
  },
})
```

### 型

```ts
function extendRouteRules(route: string, rule: NitroRouteConfig, options?: ExtendRouteRulesOptions): void
```

### パラメーター

**route**: マッチするルートパターン。\
**rule**: マッチしたルートに適用するルートルール設定。

::tip
ルートルール設定について、詳細は [Hybrid Rendering > Route Rules](/docs/guide/concepts/rendering#route-rules) で得ることができます。
::

**options**: ルート設定に渡すオブジェクト。`override` が `true` に設定されている場合、既存のルート設定を上書きします。

| 名前       | 型        | デフォルト | 説明                                         |
| ---------- | --------- | ------- | -------------------------------------------- |
| `override` | `boolean` | `false` | ルートルール設定を上書き、デフォルトは false   |

## `addRouteMiddleware`

すべてのルートまたは特定のルートで利用可能になるように、ルートミドルウェアを登録します。

ルートミドルウェアは [`addRouteMiddleware`](/docs/api/utils/add-route-middleware) composable を介してプラグインでも定義できます。

::tip
ルートミドルウェアについての詳細は [Route middleware ドキュメント](/docs/getting-started/routing#route-middleware) で読むことができます。
::

::tip{icon="i-lucide-video" to="https://vueschool.io/lessons/adding-route-rules-and-route-middlewares?friend=nuxt" target="_blank"}
ルートルールとルートミドルウェアの追加についての Vue School のビデオを見る。
::

### 使用方法

::code-group

```ts twoslash [module.ts]
import { addRouteMiddleware, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const { resolve } = createResolver(import.meta.url)

    addRouteMiddleware({
      name: 'auth',
      path: resolve('runtime/auth'),
      global: true,
    }, { prepend: true })
  },
})
```

```ts twoslash [runtime/auth.ts]
function isAuthenticated(): boolean { return false }
// ---cut---
export default defineNuxtRouteMiddleware((to, from) => {
  // isAuthenticated() is an example method verifying if a user is authenticated
  if (to.path !== '/login' && isAuthenticated() === false) {
    return navigateTo('/login')
  }
})
```

::

### 型

```ts
function addRouteMiddleware(input: NuxtMiddleware | NuxtMiddleware[], options?: AddRouteMiddlewareOptions): void
```

### パラメーター

**input**: 以下のプロパティを持つミドルウェアオブジェクトまたはミドルウェアオブジェクトの配列:

| プロパティ | 型        | 必須     | 説明                                            |
| -------- | --------- | -------- | --------------------------------------------------- |
| `name`   | `string`  | `true`   | ミドルウェアの名前。                                |
| `path`   | `string`  | `true`   | ミドルウェアへのファイルパス。                       |
| `global` | `boolean` | `false`  | `true` に設定すると、すべてのルートにミドルウェアを適用します。 |

**options**: 以下のプロパティを持つオブジェクト:

| プロパティ  | 型        | デフォルト | 説明                                                 |
| ---------- | --------- | ------- | ----------------------------------------------------------- |
| `override` | `boolean` | `false` | `true` の場合、同じ名前のミドルウェアを置き換えます。         |
| `prepend`  | `boolean` | `false` | `true` の場合、既存のミドルウェアの前にミドルウェアを追加します。 |
