island コンポーネントをレンダリングするとき、island コンポーネントのコンテンツは静的であり、したがって JS はクライアントサイドでダウンロードされません。

island コンポーネントの props を変更すると、island コンポーネントの再取得がトリガーされ、再度再レンダリングされます。

::note
アプリケーションのグローバルスタイルはレスポンスとともに送信されます。
::

::tip
Server only コンポーネントは内部で `<NuxtIsland>` を使用しています
::

## Props

- `name` : レンダリングするコンポーネントの名前。
  - **type**: `string`
  - **required**
- `lazy`: コンポーネントをノンブロッキングにします。
  - **type**: `boolean`
  - **default**: `false`
- `props`: レンダリングするコンポーネントに送信する Props。
  - **type**: `Record<string, any>`
- `source`: island をレンダリングするために呼び出すリモートソース。
  - **type**: `string`
- **dangerouslyLoadClientComponents**: リモートソースからコンポーネントをロードするために必要です。
  - **type**: `boolean`
  - **default**: `false`

::note
リモート islands は `nuxt.config` で `experimental.componentIslands` を `'local+remote'` に設定する必要があります。
リモートサーバーの JavaScript を信頼できないため、`dangerouslyLoadClientComponents` を有効にすることは強く非推奨です。
::

::note
デフォルトでは、コンポーネント islands は `~/components/islands/` ディレクトリーからスキャンされます。したがって `~/components/islands/MyIsland.vue` コンポーネントは `<NuxtIsland name="MyIsland" />` でレンダリングできます。
::

## Slots

宣言されている場合、slot を island コンポーネントに渡すことができます。

親コンポーネントが提供しているため、すべての slot はインタラクティブです。

いくつかの slot は特別なケースのために `NuxtIsland` に予約されています。

- `#fallback`: island がロードされる前（コンポーネントが lazy の場合）または `NuxtIsland` がコンポーネントの取得に失敗した場合にレンダリングされるコンテンツを指定します。

## Ref

- `refresh()`
  - **type**: `() => Promise<void>`
  - **description**: 再取得することでサーバーコンポーネントの強制再取得を行います。

## Events

- `error`
  - **parameters**:
    - **error**:
      - **type**: `unknown`
  - **description**: `NuxtIsland` が新しい island の取得に失敗したときに発行されます。
