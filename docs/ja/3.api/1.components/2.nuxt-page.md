`<NuxtPage>` は Nuxt に付属する組み込みコンポーネントです。[`pages/`](/docs/guide/directory-structure/pages) ディレクトリーにあるトップレベルまたはネストされたページを表示することができます。

::note
`<NuxtPage>` は Vue Router の [`<RouterView>`](https://router.vuejs.org/api/interfaces/RouterViewProps.html#interface-routerviewprops) のラッパーです。前者は内部状態の追加的な処理を行うため、`<RouterView>` の代わりに使用する必要があります。そうでなければ、`useRoute()` が正しくないパスを返す可能性があります。
::

`<NuxtPage>` は以下のコンポーネントを含んでいます:

```vue
<template>
  <RouterView #default="{ Component }">
    <!-- transition を使用する場合はオプション -->
    <Transition>
      <!-- keep-alive を使用する場合はオプション -->
      <KeepAlive>
        <Suspense>
          <component :is="Component" />
        </Suspense>
      </KeepAlive>
    </Transition>
  </RouterView>
</template>
```

デフォルトでは、Nuxt は `<Transition>` と `<KeepAlive>` を有効にしません。nuxt.config ファイルで有効にするか、`<NuxtPage>` に `transition` と `keepalive` プロパティーを設定することで有効にできます。特定のページを定義したい場合は、ページコンポーネント内の `definePageMeta` で設定できます。

::warning
ページコンポーネントで `<Transition>` を有効にする場合は、ページに単一のルート要素があることを確認してください。
::

`<NuxtPage>` は内部で `<Suspense>` を使用するため、ページ変更時のコンポーネントライフサイクルの動作は、一般的な Vue アプリケーションのものとは異なります。

一般的な Vue アプリケーションでは、新しいページコンポーネントは前のものが完全にアンマウントされた**後に**マウントされます。しかし、Nuxt では、Vue `<Suspense>` の実装方法により、新しいページコンポーネントは前のものがアンマウントされる**前に**マウントされます。  

## Props

- `name`: マッチしたルートレコードのコンポーネントオプションで対応する名前でコンポーネントをレンダリングするよう `<RouterView>` に指示します。
  - type: `string`
- `route`: すべてのコンポーネントが解決されたルートの場所です。
  - type: `RouteLocationNormalized`
- `pageKey`: `NuxtPage` コンポーネントがいつ再レンダリングされるかを制御します。
  - type: `string` or `function`
- `transition`: `NuxtPage` コンポーネントでレンダリングされるすべてのページのグローバル transition を定義します。
  - type: `boolean` or [`TransitionProps`](https://vuejs.org/api/built-in-components#transition)
- `keepalive`: `NuxtPage` コンポーネントでレンダリングされるページの状態保持を制御します。
  - type: `boolean` or [`KeepAliveProps`](https://vuejs.org/api/built-in-components#keepalive)

::tip
Nuxt は `/pages` ディレクトリーで見つかったすべての Vue コンポーネントファイルをスキャンしてレンダリングすることで、`name` と `route` を自動的に解決します。
::

## Example

例えば、決して変更されない key を渡すと、`<NuxtPage>` コンポーネントは一度だけレンダリングされます - 最初にマウントされたときです。

```vue [app.vue]
<template>
  <NuxtPage page-key="static" />
</template>
```

現在のルートに基づく動的な key を使用することもできます:

```html
<NuxtPage :page-key="route => route.fullPath" />
```

::warning
ここでは `$route` オブジェクトを使用しないでください。`<NuxtPage>` が `<Suspense>` でページをレンダリングする方法に問題を引き起こす可能性があります。
::

別の方法として、`pageKey` は `/pages` ディレクトリーにある Vue コンポーネントの `<script>` セクションから [`definePageMeta`](/docs/api/utils/define-page-meta) を介して `key` 値として渡すことができます。

```vue [pages/my-page.vue]
<script setup lang="ts">
definePageMeta({
  key: route => route.fullPath
})
</script>
```

## Page's Ref

ページコンポーネントの `ref` を取得するには、`ref.value.pageRef` を通してアクセスします

````vue [app.vue]
<script setup lang="ts">
const page = ref()

function logFoo () {
  page.value.pageRef.foo()
}
</script>

<template>
  <NuxtPage ref="page" />
</template>
````

````vue [my-page.vue]
<script setup lang="ts">
const foo = () => {
  console.log('foo method called')
}

defineExpose({
  foo,
})
</script>
````

## Custom Props

`<NuxtPage>` は、階層の下に渡す必要があるかもしれないカスタム props も受け取ります。

例えば、以下の例では、`foobar` の値が `NuxtPage` コンポーネントに渡され、その後ページコンポーネントに渡されます。

```vue [app.vue]
<template>
  <NuxtPage :foobar="123" />
</template>
```

ページコンポーネントで `foobar` prop にアクセスできます:

```vue [pages/page.vue]
<script setup lang="ts">
const props = defineProps<{ foobar: number }>()

console.log(props.foobar) // Outputs: 123
```

`defineProps` で prop を定義していない場合、`NuxtPage` に渡された任意の props は、ページの `attrs` から直接アクセスできます:

```vue [pages/page.vue]
<script setup lang="ts">
const attrs = useAttrs()
console.log(attrs.foobar) // Outputs: 123
</script>
```
