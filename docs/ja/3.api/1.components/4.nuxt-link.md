::note
`<NuxtLink>` は Vue Router の `<RouterLink>` コンポーネントと HTML の `<a>` タグの両方のドロップイン置換です。リンクが _internal_ か _external_ かをインテリジェントに判定し、利用可能な最適化（prefetch、デフォルト属性など）とともに適切にレンダリングします。
::

## Internal Routing

この例では、アプリケーションの別のページにリンクするために `<NuxtLink>` コンポーネントを使用します。

::code-group
```vue [pages/index.vue]
<template>
  <NuxtLink to="/about">About page</NuxtLink>
</template>
```

```html [(Renders as) index.html]
<!-- (Vue Router & Smart Prefetching) -->
<a href="/about">About page</a>
```
::

### 動的ルートへのパラメーター渡し

この例では、`~/pages/posts/[id].vue` ルートにリンクするために `id` パラメーターを渡します。

::code-group
```vue [pages/index.vue]
<template>
  <NuxtLink :to="{ name: 'posts-id', params: { id: 123 } }">
    Post 123
  </NuxtLink>
</template>
```

```html [(Renders as) index.html]
<a href="/posts/123">Post 123</a>
```
::

::tip
Nuxt DevTools の Pages パネルでルート名とそれが受け取るかもしれないパラメーターを確認してください。
::

::tip
`to` prop にオブジェクトを渡すと、`<NuxtLink>` は Vue Router のクエリパラメーターの処理を継承します。キーと値は自動的にエンコードされるため、`encodeURI` や `encodeURIComponent` を手動で呼び出す必要はありません。
::

### 静的ファイルとクロスアプリリンクの処理

デフォルトでは、`<NuxtLink>` は相対ルートに Vue Router のクライアントサイドナビゲーションを使用します。`/public` ディレクトリーの静的ファイルや同じドメインでホストされている別のアプリケーションにリンクするとき、これらはクライアントルートの一部ではないため、予期しない 404 エラーを引き起こす可能性があります。このような場合は、`<NuxtLink>` で `external` prop を使用して Vue Router の内部ルーティングメカニズムをバイパスできます。

`external` prop はリンクが外部であることを明示的に示します。`<NuxtLink>` はリンクを標準の HTML `<a>` タグとしてレンダリングします。これにより、Vue Router のロジックをバイパスしてリソースへ直接指向し、リンクが正しく動作することが保証されます。

#### 静的ファイルへのリンク

PDF や画像など、`/public` ディレクトリーの静的ファイルについては、`external` prop を使用してリンクが正しく解決されることを確認してください。

```vue [pages/index.vue]
<template>
  <NuxtLink to="/example-report.pdf" external>
    Download Report
  </NuxtLink>
</template>
```

#### クロスアプリ URL へのリンク

同じドメインの異なるアプリケーションを指す場合、`external` prop を使用することで正しい動作が保証されます。

```vue [pages/index.vue]
<template>
  <NuxtLink to="/another-app" external>
    Go to Another App
  </NuxtLink>
</template>
```

`external` prop を使用するか自動処理に依存することで、適切なナビゲーションが保証され、予期しないルーティングの問題を回避し、静的リソースやクロスアプリケーションシナリオとの互換性が向上します。

## External Routing

この例では、Web サイトにリンクするために `<NuxtLink>` コンポーネントを使用します。

```vue [app.vue]
<template>
  <NuxtLink to="https://nuxtjs.org">
    Nuxt website
  </NuxtLink>
  <!-- <a href="https://nuxtjs.org" rel="noopener noreferrer">...</a> -->
</template>
```

## `rel` と `noRel` 属性

`noopener noreferrer` の `rel` 属性は、`target` 属性を持つリンクまたは絶対リンク（例: `http://`、`https://`、または `//` で始まるリンク）にデフォルトで適用されます。
- `noopener` は古いブラウザーの[セキュリティバグ](https://mathiasbynens.github.io/rel-noopener/)を解決します。
- `noreferrer` はリンク先のサイトに `Referer` ヘッダーを送信しないことで、ユーザーのプライバシーを改善します。

これらのデフォルトは SEO に悪影響を与えず、[ベストプラクティス](https://developer.chrome.com/docs/lighthouse/best-practices/external-anchors-use-rel-noopener)と考えられています。

この動作を上書きする必要がある場合は、`rel` または `noRel` props を使用できます。

```vue [app.vue]
<template>
  <NuxtLink to="https://twitter.com/nuxt_js">
    Nuxt Twitter
  </NuxtLink>
  <!-- <a href="https://twitter.com/nuxt_js" rel="noopener noreferrer">...</a> -->

  <NuxtLink to="https://discord.nuxtjs.org" rel="noopener">
    Nuxt Discord
  </NuxtLink>
  <!-- <a href="https://discord.nuxtjs.org" rel="noopener">...</a> -->

  <NuxtLink to="/about" target="_blank">About page</NuxtLink>
  <!-- <a href="/about" target="_blank" rel="noopener noreferrer">...</a> -->
</template>
```

`noRel` prop を使用して、絶対リンクにデフォルトの `rel` 属性が追加されることを防ぐことができます。

```vue [app.vue]
<template>
  <NuxtLink to="https://github.com/nuxt" no-rel>
    Nuxt GitHub
  </NuxtLink>
  <!-- <a href="https://github.com/nuxt">...</a> -->
</template>
```

::note
`noRel` と `rel` は同時に使用できません。`rel` は無視されます。
::

## Prefetch Links

Nuxt は自動的にスマート prefetch を含みます。これはリンクが表示されたとき（デフォルト）、ビューポート内またはスクロール時に検出し、ユーザーがリンクをクリックしたときに準備ができるように、それらのページの JavaScript を prefetch します。Nuxt はブラウザーが忙しくないときのみリソースをロードし、接続がオフラインであったり 2g 接続のみの場合は prefetch をスキップします。

```vue [pages/index.vue]
<NuxtLink to="/about" no-prefetch>About page not pre-fetched</NuxtLink>
<NuxtLink to="/about" :prefetch="false">About page not pre-fetched</NuxtLink>
```

### カスタム Prefetch トリガー

`v3.13.0` 以降、`<NuxtLink>` のカスタム prefetch トリガーをサポートしています。`prefetchOn` prop を使用してリンクをいつ prefetch するかを制御できます。

```vue
<template>
  <NuxtLink prefetch-on="visibility">
    これは表示されたときに prefetch します（デフォルト）
  </NuxtLink>

  <NuxtLink prefetch-on="interaction">
    これはホバーされたときまたはフォーカスを得たときに prefetch します
  </NuxtLink>
</template>
```

- `visibility`: リンクがビューポート内で表示されたときに prefetch します。[Intersection Observer API](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API) を使用して要素とビューポートの交差を監視します。要素がスクロールして表示されたときに prefetch がトリガーされます。
- `interaction`: リンクがホバーされたりフォーカスされたりしたときに prefetch します。このアプローチは `pointerenter` と `focus` イベントをリッスンし、ユーザーがインタラクションの意図を示したときにリソースを先行して prefetch します。

オブジェクトを使用して `prefetchOn` を設定することもできます:

```vue
<template>
  <NuxtLink :prefetch-on="{ interaction: true }">
    これはホバーされたときまたはフォーカスを得たときに prefetch します
  </NuxtLink>
</template>
```

おそらく両方を有効にしたくはないでしょう！

```vue
<template>
  <NuxtLink :prefetch-on="{ visibility: true, interaction: true }">
    これはホバー/フォーカス時 - または表示されたときに prefetch します
  </NuxtLink>
</template>
```

この設定は、要素がビューポートに入ったときを監視し、`pointerenter` と `focus` イベントもリッスンします。両方のトリガーが異なる条件で同じリソースを prefetch できるため、これは不必要なリソース使用や冗長な prefetch を引き起こす可能性があります。

### クロスオリジン Prefetch を有効にする

クロスオリジン prefetch を有効にするには、`nuxt.config` で `crossOriginPrefetch` オプションを設定できます。これにより [Speculation Rules API](https://developer.mozilla.org/en-US/docs/Web/API/Speculation_Rules_API) を使用してクロスオリジン prefetch が有効になります。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    crossOriginPrefetch: true,
  },
})
```

### グローバルに prefetch を無効にする

アプリ全体ですべてのリンクの prefetch をグローバルに有効/無効にすることも可能です。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    defaults: {
      nuxtLink: {
        prefetch: false,
      },
    },
  },
})
```

## Props

### RouterLink

`external` を使用しない場合、`<NuxtLink>` は Vue Router の [`RouterLink` props](https://router.vuejs.org/api/interfaces/RouterLinkProps.html) をすべてサポートします

- `to`: Vue Router の任意の URL または [ルートロケーションオブジェクト](https://router.vuejs.org/api/#RouteLocation)
- `custom`: `<NuxtLink>` がそのコンテンツを `<a>` 要素でラップするかどうか。リンクのレンダリング方法やクリック時のナビゲーション動作を完全に制御できます。[Vue Router の `custom` prop](https://router.vuejs.org/api/interfaces/RouterLinkProps.html#Properties-custom) と同じ動作です
- `exactActiveClass`: 完全一致するアクティブリンクに適用するクラス。内部リンクで [Vue Router の `exactActiveClass` prop](https://router.vuejs.org/api/interfaces/RouterLinkProps.html#Properties-exactActiveClass) と同じ動作です。Vue Router のデフォルト (`"router-link-exact-active"`) に設定されます
- `activeClass`: アクティブリンクに適用するクラス。内部リンクで [Vue Router の `activeClass` prop](https://router.vuejs.org/api/interfaces/RouterLinkProps.html#Properties-activeClass) と同じ動作です。Vue Router のデフォルト (`"router-link-active"`) に設定されます
- `replace`: 内部リンクで [Vue Router の `replace` prop](https://router.vuejs.org/api/interfaces/RouteLocationOptions.html#Properties-replace) と同じ動作です
- `ariaCurrentValue`: 完全一致するアクティブリンクに適用する `aria-current` 属性値。内部リンクで [Vue Router の `ariaCurrentValue` prop](https://router.vuejs.org/api/interfaces/RouterLinkProps.html#Properties-ariaCurrentValue) と同じ動作です

### NuxtLink

- `href`: `to` のエイリアス。`to` と同時に使用された場合、`href` は無視されます
- `noRel`: `true` に設定された場合、外部リンクに `rel` 属性が追加されません
- `external`: Vue Router `RouterLink` の代わりにリンクを `<a>` タグとしてレンダリングすることを強制します。
- `prefetch`: 有効にすると、ビューポート内のリンクのミドルウェア、レイアウト、ペイロード（[payloadExtraction](/docs/api/nuxt-config#crossoriginprefetch) を使用している場合）を prefetch します。実験的な [crossOriginPrefetch](/docs/api/nuxt-config#crossoriginprefetch) 設定で使用されます。
- `prefetchOn`: リンクをいつ prefetch するかのカスタム制御を可能にします。可能なオプションは `interaction` と `visibility`（デフォルト）です。完全な制御のためにオブジェクトを渡すこともできます。例: `{ interaction: true, visibility: true }`。この prop は `prefetch` が有効（デフォルト）で `noPrefetch` が設定されていない場合のみ使用されます。
- `noPrefetch`: prefetch を無効にします。
- `prefetchedClass`: prefetch されたリンクに適用するクラス。

### Anchor

- `target`: リンクに適用する `target` 属性値
- `rel`: リンクに適用する `rel` 属性値。外部リンクのデフォルトは `"noopener noreferrer"` です。

::tip
デフォルトは上書きできます。変更したい場合は [デフォルトの上書き](#overwriting-defaults) を参照してください。
::

## デフォルトの上書き

### Nuxt Config で

[`nuxt.config`](/docs/api/nuxt-config#defaults) でいくつかの `<NuxtLink>` デフォルトを上書きできます

::important
これらのオプションは将来的に `app.config` や `app/` ディレクトリーなど、他の場所に移動される可能性があります。
::

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    defaults: {
      nuxtLink: {
        // デフォルト値
        componentName: 'NuxtLink',
        externalRelAttribute: 'noopener noreferrer',
        activeClass: 'router-link-active',
        exactActiveClass: 'router-link-exact-active',
        prefetchedClass: undefined, // 任意の有効な文字列クラス名を指定可能
        trailingSlash: undefined // 'append' または 'remove' を指定可能
        prefetch: true,
        prefetchOn: { visibility: true } 
      }
    }
  }
})
```

### カスタムリンクコンポーネント

`defineNuxtLink` を使用して独自のリンクコンポーネントを作成することで、`<NuxtLink>` のデフォルトを上書きできます。

```js [components/MyNuxtLink.ts]
export default defineNuxtLink({
  componentName: 'MyNuxtLink',
  /* 詳細は以下のシグネチャを参照 */
})
```

その後、新しいデフォルトで `<MyNuxtLink />` コンポーネントを通常通り使用できます。

### `defineNuxtLink` シグネチャ

```ts
interface NuxtLinkOptions {
  componentName?: string;
  externalRelAttribute?: string;
  activeClass?: string;
  exactActiveClass?: string;
  trailingSlash?: 'append' | 'remove'
  prefetch?: boolean
  prefetchedClass?: string
  prefetchOn?: Partial<{
    visibility: boolean
    interaction: boolean
  }>
}
function defineNuxtLink(options: NuxtLinkOptions): Component {}
```

- `componentName`: コンポーネントの名前。デフォルトは `NuxtLink` です。
- `externalRelAttribute`: 外部リンクに適用されるデフォルトの `rel` 属性値。デフォルトは `"noopener noreferrer"` です。無効にするには `""` に設定します
- `activeClass`: アクティブリンクに適用するデフォルトクラス。[Vue Router の `linkActiveClass` オプション](https://router.vuejs.org/api/interfaces/RouterOptions.html#Properties-linkActiveClass)と同じ動作です。Vue Router のデフォルト (`"router-link-active"`) に設定されます
- `exactActiveClass`: 完全一致するアクティブリンクに適用するデフォルトクラス。[Vue Router の `linkExactActiveClass` オプション](https://router.vuejs.org/api/interfaces/RouterOptions.html#Properties-linkExactActiveClass)と同じ動作です。Vue Router のデフォルト (`"router-link-exact-active"`) に設定されます
- `trailingSlash`: `href` に末尾スラッシュを追加または削除するオプション。設定されていないか、有効な値 `append` または `remove` と一致しない場合は無視されます。
- `prefetch`: デフォルトでリンクを prefetch するかどうか。
- `prefetchOn`: デフォルトで適用する prefetch 戦略の細かい制御。
- `prefetchedClass`: prefetch されたリンクに適用するデフォルトクラス。
