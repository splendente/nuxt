## `app.vue`

Nuxt 3 は `~/app.vue` を通じてアプリに中心的なエントリポイントを提供します。

::note
ソースディレクトリに `app.vue` ファイルがない場合、Nuxt は独自のデフォルトバージョンを使用します。
::

このファイルは、アプリが起動する際に一度実行する必要があるカスタムコードや、アプリのすべてのページに存在するコンポーネントを配置するのに適しています。例えば、レイアウトが1つしかない場合は、代わりにこれを `app.vue` に移動することができます。

:read-more{to="/docs/guide/directory-structure/app"}

:link-example{to="/docs/examples/hello-world"}

### 移行

`app.vue` ファイルを作成し、アプリのトップレベルで一度実行する必要があるロジックを含めることを検討してください。[こちらの例](/docs/guide/directory-structure/app)を確認できます。

## レイアウト

アプリで複数のページにレイアウトを使用している場合、わずかな変更が必要です。

Nuxt 2 では、`<Nuxt>` コンポーネントがレイアウト内で現在のページをレンダーするために使用されます。Nuxt 3 では、レイアウトは代わりにスロットを使用するため、そのコンポーネントを `<slot />` に置き換える必要があります。これにより、名前付きおよびスコープ付きスロットでの高度な用途も可能になります。[レイアウトの詳細](/docs/guide/directory-structure/layouts)を読む。

また、`definePageMeta` コンパイラマクロを使用してページで使用されるレイアウトを定義する方法を変更する必要があります。レイアウトはケバブケースになります。つまり、`layouts/customLayout.vue` はページで参照される際に `custom-layout` になります。

### 移行

1. `<Nuxt />` を `<slot />` に置き換える
    ```diff [layouts/custom.vue]
      <template>
        <div id="app-layout">
          <main>
    -       <Nuxt />
    +       <slot />
          </main>
        </div>
      </template>
    ```
2. [`definePageMeta`](/docs/api/utils/define-page-meta) を使用してページで使用されるレイアウトを選択する
    ```diff [pages/index.vue]
    + <script setup>
    + definePageMeta({
    +   layout: 'custom'
    + })
    - <script>
    - export default {
    -   layout: 'custom'
    - }
      </script>
    ```
3. `~/layouts/_error.vue` を `~/error.vue` に移動する。[エラーハンドリングドキュメント](/docs/getting-started/error-handling)を参照してください。このページがレイアウトを使用することを確実にしたい場合は、`error.vue` 内で直接 [`<NuxtLayout>`](/docs/guide/directory-structure/layouts) を使用できます:
    ```vue [error.vue]
    <template>
      <div>
        <NuxtLayout name="default">
          <!-- -->
        </NuxtLayout>
      </div>
    </template>
    ```

## ページ

Nuxt 3 は、ソースディレクトリに [`pages/`](/docs/guide/directory-structure/pages) ディレクトリが存在することでトリガーされるオプションの `vue-router` 統合が付属しています。ページご1つしかない場合は、より軽量なビルドのために、代わりに `app.vue` に移動することを検討できます。

### 動的ルート

Nuxt 3 で動的ルートを定義する形式は Nuxt 2 とわずかに異なるため、`pages/` 内の一部のファイルをリネームする必要があるかもしれません。

1. 以前は動的ルートパラメータを定義するために `_id` を使用していたところで、今は `[id]` を使用します。
2. 以前はキャッチオールルートを定義するために `_.vue` を使用していたところで、今は `[...slug].vue` を使用します。

### ネストされたルート

Nuxt 2 では、ネストされたルート（親と子コンポーネントを持つ）を `<Nuxt>` と `<NuxtChild>` を使用して定義していました。Nuxt 3 では、これらは単一の `<NuxtPage>` コンポーネントに置き換えられました。

### ページキーと Keep-alive Props

カスタムページキーや keep-alive props を `<Nuxt>` に渡していた場合、現在は `definePageMeta` を使用してこれらのオプションを設定します。

:read-more{to="/docs/guide/directory-structure/pages#special-metadata"}

### ページとレイアウトのトランジション

ページやレイアウトのトランジションをコンポーネントオプションで直接定義していた場合、現在は `definePageMeta` を使用してトランジションを設定する必要があります。Vue 3 以降、[-enter と -leave CSS クラスの名前が変更されました](https://v3-migration.vuejs.org/breaking-changes/transition.html)。`<Nuxt>` の `style` prop は `<slot>` で使用される際にトランジションに適用されなくなったため、スタイルを `-active` クラスに移動してください。

:read-more{to="/docs/getting-started/transitions"}

### 移行

1. 動的パラメータを持つページを新しい形式に合わせてリネームする。
2. `<Nuxt>` と `<NuxtChild>` を `<NuxtPage>` に更新する。
3. Composition API を使用している場合は、`this.$route` と `this.$router` を [`useRoute`](/docs/api/composables/use-route) と [`useRouter`](/docs/api/composables/use-router) Composable を使用するように移行することもできます。

#### Example: Dynamic Routes

::code-group

``` [Nuxt 2]
- URL: /users
- Page: /pages/users/index.vue

- URL: /users/some-user-name
- Page: /pages/users/_user.vue
- Usage: params.user

- URL: /users/some-user-name/edit
- Page: /pages/users/_user/edit.vue
- Usage: params.user

- URL: /users/anything-else
- Page: /pages/users/_.vue
- Usage: params.pathMatch
```

``` [Nuxt 3]
- URL: /users
- Page: /pages/users/index.vue

- URL: /users/some-user-name
- Page: /pages/users/[user].vue
- Usage: params.user

- URL: /users/some-user-name/edit
- Page: /pages/users/[user]/edit.vue
- Usage: params.user

- URL: /users/anything-else
- Page: /pages/users/[...slug].vue
- Usage: params.slug
```

::

#### Example: Nested Routes and `definePageMeta`

::code-group

```vue [Nuxt 2]
<template>
  <div>
    <NuxtChild keep-alive :keep-alive-props="{ exclude: ['modal'] }" :nuxt-child-key="$route.slug" />
  </div>
</template>

<script>
export default {
  transition: 'page' // or { name: 'page' }
}
</script>
```

```vue [Nuxt 3]
<template>
  <div>
    <NuxtPage />
  </div>
</template>

<script setup lang="ts">
// このコンパイラマクロは <script> と <script setup> の両方で動作します
definePageMeta({
  // 文字列や算出プロパティを渡すこともできます
  key: route => route.slug,
  transition: {
    name: 'page',
  },
  keepalive: {
    exclude: ['modal']
  },
})
</script>
```

::

## `<NuxtLink>` Component

グローバル [NuxtLink](/docs/api/components/nuxt-link) コンポーネントの構文と機能のほとんどは同じです。ショートカットの `<NLink>` 形式を使用していた場合は、`<NuxtLink>` を使用するように更新してください。

`<NuxtLink>` は現在、外部リンクを含む_すべての_リンクのドロップイン置換です。それについて、そして独自のリンクコンポーネントを提供するためにどのように拡張するかについて詳しく読むことができます。

:read-more{to="/docs/api/components/nuxt-link"}

## プログラムによるナビゲーション

Nuxt 2 から Nuxt 3 へ移行する際、ユーザーをプログラムでナビゲートする方法を更新する必要があります。Nuxt 2 では、`this.$router` で基盤となる Vue Router にアクセスできました。Nuxt 3 では、Vue Router にルートとパラメータを渡すことを可能にする `navigateTo()` ユーティリティメソッドを使用できます。

::warning
[`navigateTo`](/docs/api/utils/navigate-to) では常に `await` するか、関数から返すことでその結果をチェーンするようにしてください。
::

::code-group

```vue [Nuxt 2]
<script>
export default {
  methods: {
    navigate(){
      this.$router.push({
        path: '/search',
        query: {
          name: 'first name',
          type: '1'
        }
      })
    }
  }
}
</script>
```

```vue [Nuxt 3]
<script setup lang="ts">
function navigate(){
  return navigateTo({
    path: '/search',
    query: {
      name: 'first name',
      type: '1'
    }
  })
}
</script>
```

::
