Nuxt には、ブラウザーまたはサーバー環境でデータ取得を実行するための 2 つの composable と組み込みライブラリが付属しています：`useFetch`、[`useAsyncData`](/docs/api/composables/use-async-data)、および `$fetch` です。

簡単に言うと：

- [`$fetch`](/docs/api/utils/dollarfetch) は、ネットワークリクエストを行う最もシンプルな方法です。
- [`useFetch`](/docs/api/composables/use-fetch) は、[ユニバーサルレンダリング](/docs/guide/concepts/rendering#universal-rendering)において一度だけデータを取得する `$fetch` のラッパーです。
- [`useAsyncData`](/docs/api/composables/use-async-data) は `useFetch` と似ていますが、より細かい制御を提供します。

`useFetch` と `useAsyncData` の両方は、最後のセクションで詳しく説明する共通のオプションとパターンのセットを共有しています。

## `useFetch` と `useAsyncData` の必要性

Nuxt は、サーバーとクライアントの両方の環境でアイソモーフィック（またはユニバーサル）コードを実行できるフレームワークです。Vue コンポーネントのセットアップ関数でデータ取得を実行するために [`$fetch` 関数](/docs/api/utils/dollarfetch)を使用すると、データが 2 回取得される可能性があります。一度はサーバー上で（HTML をレンダリングするため）、もう一度はクライアント上で（HTML がハイドレートされるとき）です。これにより、ハイドレーションの問題が発生し、インタラクティブになるまでの時間が増加し、予測不可能な動作を引き起こす可能性があります。

[`useFetch`](/docs/api/composables/use-fetch) と [`useAsyncData`](/docs/api/composables/use-async-data) composable は、サーバー上で API 呼び出しが行われた場合、データがペイロードでクライアントに転送されることを保証することで、この問題を解決します。

ペイロードは、[`useNuxtApp().payload`](/docs/api/composables/use-nuxt-app#payload) を通じてアクセスできる JavaScript オブジェクトです。これは、[ハイドレーション中](/docs/guide/concepts/rendering#universal-rendering)にブラウザーでコードが実行されるときに、同じデータを再取得することを避けるためにクライアント上で使用されます。

::tip
このデータを **Payload タブ**で検査するには、[Nuxt DevTools](https://devtools.nuxt.com) を使用してください。
::

```vue [app.vue]
<script setup lang="ts">
const { data } = await useFetch('/api/data')

async function handleFormSubmit() {
  const res = await $fetch('/api/submit', {
    method: 'POST',
    body: {
      // フォームデータ
    }
  })
}
</script>

<template>
  <div v-if="data == undefined">
    データなし
  </div>
  <div v-else>
    <form @submit="handleFormSubmit">
      <!-- フォーム入力タグ -->
    </form>
  </div>
</template>
```

上記の例では、`useFetch` はリクエストがサーバーで発生し、ブラウザーに適切に転送されることを保証します。`$fetch` にはそのようなメカニズムがなく、ブラウザーからのみリクエストが行われる場合に使用する方が良いオプションです。

### Suspense

Nuxt は、すべての非同期データがビューで利用可能になる前のナビゲーションを防ぐために、Vue の [`<Suspense>`](https://vuejs.org/guide/built-ins/suspense) コンポーネントを内部で使用しています。データ取得 composable は、この機能を活用し、呼び出しごとに最適なものを使用するのに役立ちます。

::note
ページナビゲーション間にプログレスバーを追加するには、[`<NuxtLoadingIndicator>`](/docs/api/components/nuxt-loading-indicator) を追加できます。
::

## `$fetch`

Nuxt には [ofetch](https://github.com/unjs/ofetch) ライブラリが含まれており、アプリケーション全体で `$fetch` エイリアスとしてグローバルに自動インポートされます。

```vue twoslash [pages/todos.vue]
<script setup lang="ts">
async function addTodo() {
  const todo = await $fetch('/api/todos', {
    method: 'POST',
    body: {
      // TODO データ
    }
  })
}
</script>
```

::warning
`$fetch` のみを使用しても、[ネットワーク呼び出しの重複排除とナビゲーションの予防](#the-need-for-usefetch-and-useasyncdata)は提供されないことに注意してください。 :br
クライアントサイドのインタラクション（イベントベース）には `$fetch` を使用するか、初期コンポーネントデータを取得するときに [`useAsyncData`](#useasyncdata) と組み合わせて使用することをお勧めします。
::

::read-more{to="/docs/api/utils/dollarfetch"}
`$fetch` について詳しく読む。
::

### クライアントヘッダーを API に渡す

サーバー上で `useFetch` を呼び出すとき、Nuxt は [`useRequestFetch`](/docs/api/composables/use-request-fetch) を使用してクライアントヘッダーとクッキーをプロキシします（`host` などの転送されるべきではないヘッダーを除く）。

```vue
<script setup lang="ts">
const { data } = await useFetch('/api/echo');
</script>
```

```ts
// /api/echo.ts
export default defineEventHandler(event => parseCookies(event))
```

あるいは、以下の例では、[`useRequestHeaders`](/docs/api/composables/use-request-headers) を使用してサーバーサイドリクエスト（クライアントから発生）から API にクッキーをアクセスして送信する方法を示しています。アイソモーフィックな `$fetch` 呼び出しを使用することで、API エンドポイントがユーザーのブラウザーによって元々送信された同じ `cookie` ヘッダーにアクセスできることを保証します。これは `useFetch` を使用していない場合にのみ必要です。

```vue
<script setup lang="ts">
const headers = useRequestHeaders(['cookie'])

async function getCurrentUser() {
  return await $fetch('/api/me', { headers })
}
</script>
```

::tip
[`useRequestFetch`](/docs/api/composables/use-request-fetch) を使用してヘッダーを呼び出しに自動的にプロキシすることもできます。
::

::caution
外部 API にヘッダーをプロキシする前に非常に注意し、必要なヘッダーのみを含めてください。すべてのヘッダーがバイパスされても安全ではなく、望ましくない動作を引き起こす可能性があります。以下は、プロキシしてはいけない一般的なヘッダーのリストです:

- `host`、`accept`
- `content-length`、`content-md5`、`content-type`
- `x-forwarded-host`、`x-forwarded-port`、`x-forwarded-proto`
- `cf-connecting-ip`、`cf-ray`
::

## `useFetch`

[`useFetch`](/docs/api/composables/use-fetch) コンポーザブルは、setup 関数で SSR 安全なネットワーク呼び出しを行うために、内部で `$fetch` を使用しています。

```vue twoslash [app.vue]
<script setup lang="ts">
const { data: count } = await useFetch('/api/count')
</script>

<template>
  <p>ページ訪問数: {{ count }}</p>
</template>
```

このコンポーザブルは、[`useAsyncData`](/docs/api/composables/use-async-data) コンポーザブルと `$fetch` ユーティリティのラッパーです。

## `useAsyncData`

`useAsyncData` コンポーザブルは、非同期ロジックをラップし、解決されたら結果を返す責任を負います。

::tip
`useFetch(url)` は `useAsyncData(url, () => event.$fetch(url))` とほぼ同等です。:br
これは最も一般的なユースケースに対する開発者体験の糖衣構文です。（`event.fetch` について詳しくは [`useRequestFetch`](/docs/api/composables/use-request-fetch) をご覧ください。）
::

:video-accordion{title="Watch a video from Alexander Lichter to dig deeper into the difference between useFetch and useAsyncData" videoId="0X-aOpSGabA"}

[`useFetch`](/docs/api/composables/use-fetch) composable を使用するのが適切でない場合があります。たとえば、CMS やサードパーティが独自のクエリレイヤーを提供している場合です。この場合、[`useAsyncData`](/docs/api/composables/use-async-data) を使用して呼び出しをラップし、composable が提供する利点を維持できます。

```vue [pages/users.vue]
<script setup lang="ts">
const { data, error } = await useAsyncData('users', () => myGetFunction('users'))

// これも可能です：
const { data, error } = await useAsyncData(() => myGetFunction('users'))
</script>
```

::note
[`useAsyncData`](/docs/api/composables/use-async-data) の最初の引数は、2 番目の引数であるクエリ関数のレスポンスをキャッシュするために使用される一意のキーです。このキーは、クエリ関数を直接渡すことで無視することができ、その場合はキーが自動生成されます。
:br :br
自動生成されるキーは `useAsyncData` が呼び出されるファイルと行のみを考慮するため、`useAsyncData` をラップする独自のカスタム composable を作成する場合など、望ましくない動作を避けるために、常に独自のキーを作成することを推奨します。
:br :br
キーを設定することで、[`useNuxtData`](/docs/api/composables/use-nuxt-data) を使用してコンポーネント間で同じデータを共有したり、[特定のデータを更新](/docs/api/utils/refresh-nuxt-data#refresh-specific-data)したりするのに役立ちます。
::

```vue [pages/users/[id\\].vue]
<script setup lang="ts">
const { id } = useRoute().params

const { data, error } = await useAsyncData(`user:${id}`, () => {
  return myGetFunction('users', { id })
})
</script>
```

`useAsyncData` composable は、複数の `$fetch` リクエストの完了を待機してから結果を処理する優れた方法です。

```vue
<script setup lang="ts">
const { data: discounts, status } = await useAsyncData('cart-discount', async () => {
  const [coupons, offers] = await Promise.all([
    $fetch('/cart/coupons'),
    $fetch('/cart/offers')
  ])

  return { coupons, offers }
})
// discounts.value.coupons
// discounts.value.offers
</script>
```

::note
`useAsyncData` はデータの取得とキャッシュを目的としており、Pinia アクションの呼び出しなどの副作用を引き起こすものではありません。これは、null 値での繰り返し実行などの意図しない動作を引き起こす可能性があります。副作用を引き起こす必要がある場合は、[`callOnce`](/docs/api/utils/call-once) ユーティリティを使用してください。

```vue
<script setup lang="ts">
const offersStore = useOffersStore()

// これはできません
await useAsyncData(() => offersStore.getOffer(route.params.slug))
</script>
```
::

`useAsyncData` について詳しく読む。

## 戻り値

`useFetch` と `useAsyncData` は以下にリストされた同じ戻り値を持ちます。

- `data`: 渡された非同期関数の結果です。
- `refresh`/`execute`: `handler` 関数によって返されるデータを更新するために使用できる関数です。
- `clear`: `data` を `undefined`（または `options.default()` が提供されている場合はその値）に設定し、`error` を `undefined` に設定し、`status` を `idle` に設定し、現在保留中のリクエストをキャンセル済みとしてマークするために使用できる関数です。
- `error`: データ取得が失敗した場合のエラーオブジェクトです。
- `status`: データリクエストのステータスを示す文字列です（`"idle"`、`"pending"`、`"success"`、`"error"`）。

::note
`data`、`error`、`status` は `<script setup>` で `.value` によってアクセス可能な Vue ref です
::

デフォルトでは、Nuxt は `refresh` が完了するまで待ってから再実行できるようにします。

::note
サーバーでデータを取得していない場合（例えば `server: false` の場合）、ハイドレーションが完了するまでデータは取得されません。これは、クライアントサイドで `useFetch` を待機していても、`<script setup>` 内で `data` が null のままであることを意味します。
::

## オプション

[`useAsyncData`](/docs/api/composables/use-async-data) と [`useFetch`](/docs/api/composables/use-fetch) は同じオブジェクトタイプを返し、最後の引数として共通のオプションセットを受け入れます。これらは、ナビゲーションブロック、キャッシュ、実行などの composable の動作を制御するのに役立ちます。

### Lazy

デフォルトでは、データ取得 composable は Vue の Suspense を使用して新しいページにナビゲートする前に、非同期関数の解決を待ちます。この機能は、`lazy` オプションでクライアントサイドナビゲーションでは無視できます。その場合、`status` 値を使用してローディング状態を手動で処理する必要があります。

```vue twoslash [app.vue]
<script setup lang="ts">
const { status, data: posts } = useFetch('/api/posts', {
  lazy: true
})
</script>

<template>
  <!-- ローディング状態を処理する必要があります -->
  <div v-if="status === 'pending'">
    Loading ...
  </div>
  <div v-else>
    <div v-for="post in posts">
      <!-- 何かを行う -->
    </div>
  </div>
</template>
```

代わりに、同じことを実行する便利なメソッドとして [`useLazyFetch`](/docs/api/composables/use-lazy-fetch) と `useLazyAsyncData` を使用することもできます。

```vue twoslash
<script setup lang="ts">
const { status, data: posts } = useLazyFetch('/api/posts')
</script>
```

### クライアントのみの取得

デフォルトでは、データ取得 composable はクライアントとサーバーの両方の環境で非同期関数を実行します。`server` オプションを `false` に設定すると、クライアントサイドでのみ呼び出しが実行されます。初期ロード時は、ハイドレーションが完了する前にデータは取得されないため、保留状態を処理する必要がありますが、その後のクライアントサイドナビゲーションでは、ページをロードする前にデータが待機されます。

`lazy` オプションと組み合わせると、最初のレンダリングで必要でないデータ（例えば、SEO に敏感でないデータ）に役立ちます。

```ts twoslash
/* この呼び出しはハイドレーション前に実行されます */
const articles = await useFetch('/api/article')

/* この呼び出しはクライアントでのみ実行されます */
const { status, data: comments } = useFetch('/api/comments', {
  lazy: true,
  server: false
})
```

`useFetch` composable は、setup メソッドで呼び出されるか、ライフサイクルフック内の関数のトップレベルで直接呼び出されることを意図しています。そうでない場合は、[`$fetch` メソッド](#fetch) を使用してください。

### ペイロードサイズの最小化

`pick` オプションは、composable から返されるフィールドのみを選択することで、HTML ドキュメントに保存されるペイロードサイズを最小化するのに役立ちます。

```vue
<script setup lang="ts">
/* テンプレートで使用されるフィールドのみを選択 */
const { data: mountain } = await useFetch('/api/mountains/everest', {
  pick: ['title', 'description']
})
</script>

<template>
  <h1>{{ mountain.title }}</h1>
  <p>{{ mountain.description }}</p>
</template>
```

より多くの制御が必要な場合や複数のオブジェクトをマップする場合は、`transform` 関数を使用してクエリの結果を変更できます。

```ts
const { data: mountains } = await useFetch('/api/mountains', {
  transform: (mountains) => {
    return mountains.map(mountain => ({ title: mountain.title, description: mountain.description }))
  }
})
```

::note
`pick` と `transform` の両方とも、不要なデータが最初に取得されることを防ぎません。しかし、サーバーからクライアントに転送されるペイロードに不要なデータが追加されることを防ぎます。
::

### キャッシュと再取得

#### キー

[`useFetch`](/docs/api/composables/use-fetch) と [`useAsyncData`](/docs/api/composables/use-async-data) は、同じデータの再取得を防ぐためにキーを使用します。

- [`useFetch`](/docs/api/composables/use-fetch) は提供された URL をキーとして使用します。また、最後の引数として渡される `options` オブジェクトで `key` 値を提供することもできます。
- [`useAsyncData`](/docs/api/composables/use-async-data) は、最初の引数が文字列の場合はそれをキーとして使用します。最初の引数がクエリを実行するハンドラー関数の場合、`useAsyncData` のインスタンスのファイル名と行番号に固有のキーが自動生成されます。

::tip
キーによってキャッシュされたデータを取得するには、[`useNuxtData`](/docs/api/composables/use-nuxt-data) を使用できます
::

:video-accordion{title="Watch a video from Vue School on caching data with the key option" videoId="1026410044" platform="vimeo"}

#### 共有状態とオプションの一貫性

複数のコンポーネントが `useAsyncData` または `useFetch` で同じキーを使用する場合、同じ `data`、`error`、`status` ref を共有します。これによりコンポーネント間での一貫性が保証されますが、一部のオプションは一貫している必要があります。

同じキーを持つすべての呼び出しで、以下のオプションは**一貫している必要があります**：
- `handler` 関数
- `deep` オプション
- `transform` 関数
- `pick` 配列
- `getCachedData` 関数
- `default` 値

```ts
// ❌ これは開発時に警告を発生させます
const { data: users1 } = useAsyncData('users', () => $fetch('/api/users'), { deep: false })
const { data: users2 } = useAsyncData('users', () => $fetch('/api/users'), { deep: true })
```

以下のオプションは警告を発生させることなく**安全に異なることができます**：
- `server`
- `lazy`
- `immediate`
- `dedupe`
- `watch`

```ts
// ✅ これは許可されています
const { data: users1 } = useAsyncData('users', () => $fetch('/api/users'), { immediate: true })
const { data: users2 } = useAsyncData('users', () => $fetch('/api/users'), { immediate: false })
```

独立したインスタンスが必要な場合は、異なるキーを使用してください：

```ts
// これらは完全に独立したインスタンスです
const { data: users1 } = useAsyncData('users-1', () => $fetch('/api/users'))
const { data: users2 } = useAsyncData('users-2', () => $fetch('/api/users'))
```

#### リアクティブキー

キーとして computed ref、通常の ref、またはゲッター関数を使用できます。これにより、依存関係が変更されたときに自動的に更新される動的なデータ取得が可能になります：

```ts
// computed プロパティをキーとして使用
const userId = ref('123')
const { data: user } = useAsyncData(
  computed(() => `user-${userId.value}`),
  () => fetchUser(userId.value)
)

// userId が変更されると、データは自動的に再取得され、
// 他のコンポーネントが使用していない場合は古いデータがクリーンアップされます
userId.value = '456'
```

#### リフレッシュと実行

データを手動で取得または更新したい場合は、composable が提供する `execute` または `refresh` 関数を使用します。

```vue twoslash
<script setup lang="ts">
const { data, error, execute, refresh } = await useFetch('/api/users')
</script>

<template>
  <div>
    <p>{{ data }}</p>
    <button @click="() => refresh()">Refresh data</button>
  </div>
</template>
```

`execute` 関数は `refresh` のエイリアスで、まったく同じように動作しますが、取得が[即座ではない](#not-immediate)場合により意味的です。

::tip
キャッシュされたデータをグローバルに再取得または無効化するには、[`clearNuxtData`](/docs/api/utils/clear-nuxt-data) と [`refreshNuxtData`](/docs/api/utils/refresh-nuxt-data) をご覧ください。
::

#### クリア

何らかの理由で提供されたデータをクリアしたい場合、`clearNuxtData` に渡す特定のキーを知る必要なく、composable が提供する `clear` 関数を使用できます。

```vue twoslash
<script setup lang="ts">
const { data, clear } = await useFetch('/api/users')

const route = useRoute()
watch(() => route.path, (path) => {
  if (path === '/') clear()
})
</script>
```

#### Watch

アプリケーション内の他のリアクティブ値が変更されるたびに取得関数を再実行するには、`watch` オプションを使用します。1 つまたは複数の _監視可能な_ 要素に使用できます。

```vue twoslash
<script setup lang="ts">
const id = ref(1)

const { data, error, refresh } = await useFetch('/api/users', {
  /* id を変更すると再取得がトリガーされます */
  watch: [id]
})
</script>
```

**リアクティブ値を監視しても取得される URL は変更されない**ことに注意してください。たとえば、関数が呼び出された時点で URL が構築されるため、これはユーザーの同じ初期 ID を取得し続けます。

```vue
<script setup lang="ts">
const id = ref(1)

const { data, error, refresh } = await useFetch(`/api/users/${id.value}`, {
  watch: [id]
})
</script>
```

リアクティブ値に基づいて URL を変更する必要がある場合は、代わりに [computed URL](#computed-url) を使用することを検討してください。

#### Computed URL

リアクティブ値から URL を計算し、これらが変更されるたびにデータを更新する必要がある場合があります。回避策を講じる代わりに、各パラメーターをリアクティブ値として追加できます。Nuxt は自動的にリアクティブ値を使用し、変更されるたびに再取得します。

```vue
<script setup lang="ts">
const id = ref(null)

const { data, status } = useLazyFetch('/api/user', {
  query: {
    user_id: id
  }
})
</script>
```

より複雑な URL 構築の場合、URL 文字列を返す [computed getter](https://vuejs.org/guide/essentials/computed.html) としてコールバックを使用できます。

依存関係が変更されるたびに、新しく構築された URL を使用してデータが取得されます。これを [not-immediate](#not-immediate) と組み合わせることで、取得前にリアクティブ要素が変更されるまで待つことができます。

```vue
<script setup lang="ts">
const id = ref(null)

const { data, status } = useLazyFetch(() => `/api/users/${id.value}`, {
  immediate: false
})

const pending = computed(() => status.value === 'pending');
</script>

<template>
  <div>
    <!-- 取得中は入力を無効にする -->
    <input v-model="id" type="number" :disabled="pending"/>

    <div v-if="status === 'idle'">
      ユーザー ID を入力してください
    </div>

    <div v-else-if="pending">
      Loading ...
    </div>

    <div v-else>
      {{ data }}
    </div>
  </div>
</template>
```

他のリアクティブ値が変更されたときに強制的に更新する必要がある場合は、[他の値を監視](#watch)することもできます。

### 即座ではない

`useFetch` composable は呼び出された瞬間にデータの取得を開始します。`immediate: false` を設定することで、たとえばユーザーのインタラクションを待つためにこれを防ぐことができます。

その場合、取得ライフサイクルを処理するための `status` と、データ取得を開始するための `execute` の両方が必要になります。

```vue
<script setup lang="ts">
const { data, error, execute, status } = await useLazyFetch('/api/comments', {
  immediate: false
})
</script>

<template>
  <div v-if="status === 'idle'">
    <button @click="execute">Get data</button>
  </div>

  <div v-else-if="status === 'pending'">
    Loading comments...
  </div>

  <div v-else>
    {{ data }}
  </div>
</template>
```

より細かい制御のために、`status` 変数は以下のようになります：

- `idle` 取得が開始されていないとき
- `pending` 取得が開始されたがまだ完了していないとき
- `error` 取得が失敗したとき
- `success` 取得が正常に完了したとき

## ヘッダーとクッキーの受け渡し

ブラウザーで `$fetch` を呼び出すとき、`cookie` などのユーザーヘッダーは API に直接送信されます。

通常、サーバーサイドレンダリング中は、セキュリティ上の考慮により、`$fetch` はユーザーのブラウザークッキーを含めず、fetch レスポンスからのクッキーも渡しません。

ただし、サーバー上で相対 URL で `useFetch` を呼び出すとき、Nuxt は [`useRequestFetch`](/docs/api/composables/use-request-fetch) を使用してヘッダーとクッキーをプロキシします（`host` など転送されるべきではないヘッダーを除く）。

### SSR レスポンスでサーバーサイド API 呼び出しからクッキーを渡す

反対方向、つまり内部リクエストからクライアントにクッキーを渡す/プロキシしたい場合は、これを自分で処理する必要があります。

```ts [composables/fetch.ts]
import { appendResponseHeader } from 'h3'
import type { H3Event } from 'h3'

export const fetchWithCookie = async (event: H3Event, url: string) => {
  /* サーバーエンドポイントからレスポンスを取得 */
  const res = await $fetch.raw(url)
  /* レスポンスからクッキーを取得 */
  const cookies = res.headers.getSetCookie()
  /* 各クッキーを受信リクエストに添付 */
  for (const cookie of cookies) {
    appendResponseHeader(event, 'set-cookie', cookie)
  }
  /* レスポンスのデータを返す */
  return res._data
}
```

```vue
<script setup lang="ts">
// この composable は自動的にクッキーをクライアントに渡します
const event = useRequestEvent()

const { data: result } = await useAsyncData(() => fetchWithCookie(event!, '/api/with-cookie'))

onMounted(() => console.log(document.cookie))
</script>
```

## Options API サポート

Nuxt は Options API 内で `asyncData` 取得を実行する方法を提供します。これを機能させるには、コンポーネント定義を `defineNuxtComponent` でラップする必要があります。

```vue
<script>
export default defineNuxtComponent({
  /* fetchKey オプションを使用して一意のキーを提供 */
  fetchKey: 'hello',
  async asyncData () {
    return {
      hello: await $fetch('/api/hello')
    }
  }
})
</script>
```

::note
`<script setup>` または `<script setup lang="ts">` を使用することが、Nuxt で Vue コンポーネントを宣言する推奨方法です。
::

## サーバーからクライアントへのデータシリアライゼーション

`useAsyncData` と `useLazyAsyncData` を使用してサーバーで取得したデータをクライアントに転送する際（[Nuxt ペイロード](/docs/api/composables/use-nuxt-app#payload)を利用する他のものも含む）、ペイロードは [`devalue`](https://github.com/Rich-Harris/devalue) でシリアライズされます。これにより、基本的な JSON だけでなく、正規表現、Date、Map、Set、`ref`、`reactive`、`shallowRef`、`shallowReactive`、`NuxtError` などのより高度な種類のデータもシリアライズおよび復元/デシリアライズして転送できます。

Nuxt でサポートされていない型に対して独自のシリアライザー/デシリアライザーを定義することも可能です。詳細は [`useNuxtApp`](/docs/api/composables/use-nuxt-app#payload) ドキュメントをご覧ください。

::note
これは `$fetch` または `useFetch` で取得されたサーバールートから渡されるデータには_適用されない_ことに注意してください。詳細については次のセクションを参照してください。
::

## API ルートからのデータシリアライゼーション

`server` ディレクトリからデータを取得する際、レスポンスは `JSON.stringify` を使用してシリアライズされます。ただし、シリアライゼーションは JavaScript のプリミティブ型のみに制限されているため、Nuxt は `$fetch` と [`useFetch`](/docs/api/composables/use-fetch) の戻り値の型を実際の値に合わせて変換するために最善を尽くします。

::read-more{icon="i-simple-icons-mdnwebdocs" to="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/stringify#description" target="_blank"}
`JSON.stringify` の制限について詳しく学ぶ。
::

### Example

```ts [server/api/foo.ts]
export default defineEventHandler(() => {
  return new Date()
})
```

```vue [app.vue]
<script setup lang="ts">
// Date オブジェクトを返したにもかかわらず、`data` の型は string として推論されます
const { data } = await useFetch('/api/foo')
</script>
```

### カスタムシリアライザー関数

シリアライゼーション動作をカスタマイズするには、返されるオブジェクトに `toJSON` 関数を定義できます。`toJSON` メソッドを定義すると、Nuxt は関数の戻り値の型を尊重し、型の変換を試みません。

```ts [server/api/bar.ts]
export default defineEventHandler(() => {
  const data = {
    createdAt: new Date(),

    toJSON() {
      return {
        createdAt: {
          year: this.createdAt.getFullYear(),
          month: this.createdAt.getMonth(),
          day: this.createdAt.getDate(),
        },
      }
    },
  }
  return data
})

```

```vue [app.vue]
<script setup lang="ts">
// `data` の型は以下として推論されます
// {
//   createdAt: {
//     year: number
//     month: number
//     day: number
//   }
// }
const { data } = await useFetch('/api/bar')
</script>
```

### 代替シリアライザーの使用

Nuxt は現在、`JSON.stringify` の代替シリアライザーをサポートしていません。ただし、ペイロードを通常の文字列として返し、型安全性を維持するために `toJSON` メソッドを利用できます。

以下の例では、シリアライザーとして [superjson](https://github.com/blitz-js/superjson) を使用しています。

```ts [server/api/superjson.ts]
import superjson from 'superjson'

export default defineEventHandler(() => {
  const data = {
    createdAt: new Date(),

    // 型変換の回避策
    toJSON() {
      return this
    }
  }

  // superjson を使用して出力を文字列にシリアライズ
  return superjson.stringify(data) as unknown as typeof data
})
```

```vue [app.vue]
<script setup lang="ts">
import superjson from 'superjson'

// `date` は { createdAt: Date } として推論され、Date オブジェクトのメソッドを安全に使用できます
const { data } = await useFetch('/api/superjson', {
  transform: (value) => {
    return superjson.parse(value as unknown as string)
  },
})
</script>
```

## レシピ

### POST リクエストによる SSE （Server-Sent Events）の利用

::tip
GET リクエストで SSE を利用する場合は、[`EventSource`](https://developer.mozilla.org/en-US/docs/Web/API/EventSource) または VueUse composable [`useEventSource`](https://vueuse.org/core/useEventSource/) を使用できます。
::

POST リクエストで SSE を利用する場合は、接続を手動で処理する必要があります。以下の方法で実行できます：

```ts
// SSE エンドポイントに POST リクエストを送信
const response = await $fetch<ReadableStream>('/chats/ask-ai', {
  method: 'POST',
  body: {
    query: "Hello AI, how are you?",
  },
  responseType: 'stream',
})

// TextDecoderStream を使用してレスポンスから新しい ReadableStream を作成し、データをテキストとして取得
const reader = response.pipeThrough(new TextDecoderStream()).getReader()

// データのチャンクを取得しながら読み取り
while (true) {
  const { value, done } = await reader.read()

  if (done)
    break

  console.log('Received:', value)
}
```

### 並列リクエストの実行

リクエストが互いに依存しない場合、`Promise.all()` を使用して並列で実行し、パフォーマンスを向上させることができます。

```ts
const { data } = await useAsyncData(() => {
  return Promise.all([
    $fetch("/api/comments/"), 
    $fetch("/api/author/12")
  ]);
});

const comments = computed(() => data.value?.[0]);
const author = computed(() => data.value?.[1]);
```
