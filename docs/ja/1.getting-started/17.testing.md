Nuxt は、`@nuxt/test-utils` を介して Nuxt アプリケーションのエンドツーエンドテストと単体テストのファーストクラスサポートを提供します。これは、現在 [Nuxt 自体で使用しているテスト](https://github.com/nuxt/nuxt/tree/main/test) とモジュールエコシステム全体のテストを支えるテストユーティリティと設定のライブラリです。

:video-accordion{title="Watch a video from Alexander Lichter about getting started with @nuxt/test-utils" videoId="yGzwk9xi9gU"}

## Installation

他のテストの依存関係を管理できるようにするために、`@nuxt/test-utils` はさまざまなオプションのピア依存関係を提供しています。例えば：

- ランタイム Nuxt 環境用に `happy-dom` と `jsdom` から選択できます
- エンドツーエンドテストランナー用に `vitest`、`cucumber`、`jest`、`playwright` から選択できます
- `playwright-core` は、組み込みのブラウザテストユーティリティを使用したい場合のみ必要です（`@playwright/test` をテストランナーとして使用していない場合）

::code-group{sync="pm"}
```bash [npm]
npm i --save-dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
```bash [yarn]
yarn add --dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
```bash [pnpm]
pnpm add -D @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
```bash [bun]
bun add --dev @nuxt/test-utils vitest @vue/test-utils happy-dom playwright-core
```
::

## 単体テスト

現在、[Nuxt](https://nuxt.com) ランタイム環境が必要なコードの単体テスト用の環境を提供しています。現在は _`vitest` のみサポート_ しています（他のランタイムを追加する貢献は歓迎します）。

### セットアップ

1. `nuxt.config` ファイルに `@nuxt/test-utils/module` を追加します（オプション）。開発時に単体テストの実行をサポートする Vitest 統合を Nuxt DevTools に追加します。

   ```ts twoslash
   export default defineNuxtConfig({
     modules: [
       '@nuxt/test-utils/module'
     ]
   })
   ```

2. 以下の内容で `vitest.config.ts` を作成します：

   ```ts twoslash
   import { defineVitestConfig } from '@nuxt/test-utils/config'

   export default defineVitestConfig({
     // 必要な任意のカスタム Vitest 設定
   })
   ```

::tip
vitest 設定で `@nuxt/test-utils` をインポートする場合、`package.json` で `"type": "module"` を指定するか、vitest 設定ファイルを適切にリネームする必要があります。
> 例：`vitest.config.m{ts,js}`
::

::tip
`.env.test` ファイルを使用してテスト用の環境変数を設定することができます。
::

### Nuxt ランタイム環境の使用

デフォルトでは、`@nuxt/test-utils` はデフォルトの Vitest 環境を変更しないため、きめ細かなオプトインができ、Nuxt テストを他の単体テストと一緒に実行できます。

テストファイル名に `.nuxt.` を追加する（例：`my-file.nuxt.test.ts` または `my-file.nuxt.spec.ts`）か、テストファイルに直接 `@vitest-environment nuxt` をコメントとして追加することで、Nuxt 環境をオプトインできます。

   ```ts twoslash
   // @vitest-environment nuxt
   import { test } from 'vitest'

   test('my test', () => {
     // ... Nuxt 環境でテスト！
   })
   ```

代わりに、Vitest 設定で `environment: 'nuxt'` を設定して、**すべてのテスト** で Nuxt 環境を有効にすることもできます。

```ts twoslash
// vitest.config.ts
import { fileURLToPath } from 'node:url'
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environment: 'nuxt',
    // オプションで Nuxt 固有の環境オプションを設定できます
    // environmentOptions: {
    //   nuxt: {
    //     rootDir: fileURLToPath(new URL('./playground', import.meta.url)),
    //     domEnvironment: 'happy-dom', // 'happy-dom' (デフォルト) または 'jsdom'
    //     overrides: {
    //       // 渡したい他の Nuxt 設定
    //     }
    //   }
    // }
  }
})
```

デフォルトで `environment: 'nuxt'` を設定している場合、必要に応じてテストファイルごとに [デフォルト環境](https://vitest.dev/guide/environment.html#test-environment) をオプトアウトできます。

```ts twoslash
// @vitest-environment node
import { test } from 'vitest'

test('my test', () => {
  // ... Nuxt 環境ではないテスト！
})
```

::warning
Nuxt 環境でテストを実行する場合、[`happy-dom`](https://github.com/capricorn86/happy-dom) または [`jsdom`](https://github.com/jsdom/jsdom) 環境で実行されます。テストの実行前に、グローバル Nuxt アプリが初期化されます（例えば、`app.vue` で定義したプラグインやコードの実行など）。

これは、テストでグローバル状態を変更しないように特に注意する必要がある（または、必要な場合は、後でリセットする）ことを意味します。
::

### 🎭 組み込みモック

`@nuxt/test-utils` は DOM 環境用のいくつかの組み込みモックを提供します。

#### `intersectionObserver`

デフォルト `true`、IntersectionObserver API 用の機能のないダミークラスを作成します

#### `indexedDB`

デフォルト `false`、[`fake-indexeddb`](https://github.com/dumbmatter/fakeIndexedDB) を使用して IndexedDB API の機能的なモックを作成します

これらは `vitest.config.ts` ファイルの `environmentOptions` セクションで設定できます：

```ts twoslash
import { defineVitestConfig } from '@nuxt/test-utils/config'

export default defineVitestConfig({
  test: {
    environmentOptions: {
      nuxt: {
        mock: {
          intersectionObserver: true,
          indexedDb: true,
        }
      }
    }
  }
})
```

### 🛠️ ヘルパー

`@nuxt/test-utils` は Nuxt アプリのテストをより簡単にするためのヘルパーを多数提供します。

#### `mountSuspended`

`mountSuspended` を使用すると、Nuxt 環境内で任意の Vue コンポーネントをマウントでき、非同期セットアップと Nuxt プラグインからのインジェクションへのアクセスが可能になります。

::note
内部的には、`mountSuspended` は `@vue/test-utils` の `mount` をラップしているため、渡すことができるオプションやこのユーティリティの使用方法について詳しくは、[Vue Test Utils ドキュメント](https://test-utils.vuejs.org/guide/)をご覧ください。
::

例えば：

```ts twoslash
// @noErrors
import { it, expect } from 'vitest'
import type { Component } from 'vue'
declare module '#components' {
  export const SomeComponent: Component
}
// ---cut---
// tests/components/SomeComponents.nuxt.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import { SomeComponent } from '#components'

it('can mount some component', async () => {
    const component = await mountSuspended(SomeComponent)
    expect(component.text()).toMatchInlineSnapshot(
        '"This is an auto-imported component"'
    )
})

```

```ts twoslash
// @noErrors
import { it, expect } from 'vitest'
// ---cut---
// tests/components/SomeComponents.nuxt.spec.ts
import { mountSuspended } from '@nuxt/test-utils/runtime'
import App from '~/app.vue'

// tests/App.nuxt.spec.ts
it('can also mount an app', async () => {
    const component = await mountSuspended(App, { route: '/test' })
    expect(component.html()).toMatchInlineSnapshot(`
      "<div>This is an auto-imported component</div>
      <div> I am a global component </div>
      <div>/</div>
      <a href="/test"> Test link </a>"
    `)
})
```

#### `renderSuspended`

`renderSuspended` を使用すると、`@testing-library/vue` を使用して Nuxt 環境内で任意の Vue コンポーネントをレンダリングでき、非同期セットアップと Nuxt プラグインからのインジェクションへのアクセスが可能になります。

これは Testing Library のユーティリティ（例：`screen` や `fireEvent`）と一緒に使用する必要があります。これらを使用するには、プロジェクトに [@testing-library/vue](https://testing-library.com/docs/vue-testing-library/intro) をインストールしてください。

さらに、Testing Library はクリーンアップのためのテストグローバルにも依存しています。[Vitest 設定](https://vitest.dev/config/#globals) でこれらを有効にする必要があります。

渡されたコンポーネントは `<div id="test-wrapper"></div>` 内でレンダリングされます。

例:

```ts twoslash
// @noErrors
import { it, expect } from 'vitest'
import type { Component } from 'vue'
declare module '#components' {
  export const SomeComponent: Component
}
// ---cut---
// tests/components/SomeComponents.nuxt.spec.ts
import { renderSuspended } from '@nuxt/test-utils/runtime'
import { SomeComponent } from '#components'
import { screen } from '@testing-library/vue'

it('can render some component', async () => {
  await renderSuspended(SomeComponent)
  expect(screen.getByText('This is an auto-imported component')).toBeDefined()
})
```

```ts twoslash
// @noErrors
import { it, expect } from 'vitest'
// ---cut---
// tests/App.nuxt.spec.ts
import { renderSuspended } from '@nuxt/test-utils/runtime'
import App from '~/app.vue'

it('can also render an app', async () => {
  const html = await renderSuspended(App, { route: '/test' })
  expect(html).toMatchInlineSnapshot(`
    "<div id="test-wrapper">
      <div>This is an auto-imported component</div>
      <div> I am a global component </div>
      <div>Index page</div><a href="/test"> Test link </a>
    </div>"
  `)
})
```

#### `mockNuxtImport`

`mockNuxtImport` を使用すると、Nuxt の自動インポート機能をモックできます。たとえば、`useStorage` をモックするには、次のようにします:

```ts twoslash
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport('useStorage', () => {
  return () => {
    return { value: 'mocked storage' }
  }
})

// ここにテストを記述
```

::note
`mockNuxtImport` はテストファイルごとにモックされたインポートごとに 1 回しか使用できません。これは実際には `vi.mock` に変換されるマクロであり、[Vitest ドキュメント](https://vitest.dev/api/vi.html#vi-mock) で説明されているように `vi.mock` は巻き上げられます。
::

Nuxt インポートをモックし、テスト間で異なる実装を提供する必要がある場合は、[`vi.hoisted`](https://vitest.dev/api/vi.html#vi-hoisted) を使用してモックを作成・公開し、そのモックを `mockNuxtImport` で使用することで実現できます。これによりモックされたインポートにアクセスでき、テスト間で実装を変更できます。実行間のモック状態の変更を元に戻すために、各テストの前または後で [モックを復元](https://vitest.dev/api/mock.html#mockrestore) するよう注意してください。

```ts twoslash
import { vi } from 'vitest'
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

const { useStorageMock } = vi.hoisted(() => {
  return {
    useStorageMock: vi.fn(() => {
      return { value: 'mocked storage'}
    })
  }
})

mockNuxtImport('useStorage', () => {
  return useStorageMock
})

// その後、テスト内で
useStorageMock.mockImplementation(() => {
  return { value: 'something else' }
})
```

#### `mockComponent`

`mockComponent` を使用すると、Nuxt のコンポーネントをモックできます。
最初の引数は、PascalCase のコンポーネント名またはコンポーネントの相対パスです。
2 番目の引数は、モックされたコンポーネントを返すファクトリ関数です。

たとえば、`MyComponent` をモックするには:

```ts twoslash
import { mockComponent } from '@nuxt/test-utils/runtime'

mockComponent('MyComponent', {
  props: {
    value: String
  },
  setup(props) {
    // ...
  }
})

// 相対パスやエイリアスも使用可能
mockComponent('~/components/my-component.vue', async () => {
  // またはファクトリ関数
  return defineComponent({
    setup(props) {
      // ...
    }
  })
})

// または SFC を使用してモックコンポーネントにリダイレクトできます
mockComponent('MyComponent', () => import('./MockComponent.vue'))

// ここにテストを記述
```

> **注意**: ファクトリ関数は巻き上げられるため、ローカル変数を参照することはできません。Vue API やその他の変数にアクセスする必要がある場合は、ファクトリ関数内でインポートする必要があります。

```ts twoslash
import { mockComponent } from '@nuxt/test-utils/runtime'

mockComponent('MyComponent', async () => {
  const { ref, h } = await import('vue')

  return defineComponent({
    setup(props) {
      const counter = ref(0)
      return () => h('div', null, counter.value)
    }
  })
})
```

#### `registerEndpoint`

`registerEndpoint` を使用すると、モックデータを返す Nitro エンドポイントを作成できます。API にリクエストしてデータを表示するコンポーネントをテストしたい場合に便利です。

最初の引数はエンドポイント名（例: `/test/`）です。
2 番目の引数は、モックデータを返すファクトリ関数です。

たとえば、`/test/` エンドポイントをモックするには:

```ts twoslash
import { registerEndpoint } from '@nuxt/test-utils/runtime'

registerEndpoint('/test/', () => ({
  test: 'test-field'
}))
```

デフォルトでは、リクエストは `GET` メソッドを使用して行われます。関数の代わりに 2 番目の引数としてオブジェクトを設定することで、別のメソッドを使用できます。

```ts twoslash
import { registerEndpoint } from '@nuxt/test-utils/runtime'

registerEndpoint('/test/', {
  method: 'POST',
  handler: () => ({ test: 'test-field' })
})
```

> **注意**: コンポーネント内のリクエストが外部 API に行く場合、`baseURL` を使用してから [Nuxt Environment Override Config](/docs/getting-started/configuration#environment-overrides) (`$test`) を使用して空にすることで、すべてのリクエストが Nitro サーバーに行くようになります。

#### エンドツーエンドテストとの競合

`@nuxt/test-utils/runtime` と `@nuxt/test-utils/e2e` は異なるテスト環境で実行する必要があるため、同じファイルで使用することはできません。

`@nuxt/test-utils` のエンドツーエンドテストと単体テストの両方の機能を使用したい場合は、テストを別々のファイルに分割できます。その後、特別な `// @vitest-environment nuxt` コメントでファイルごとにテスト環境を指定するか、ランタイム単体テストファイルに `.nuxt.spec.ts` 拡張子を付けて名前を付けます。

`app.nuxt.spec.ts`

```ts twoslash
import { mockNuxtImport } from '@nuxt/test-utils/runtime'

mockNuxtImport('useStorage', () => {
  return () => {
    return { value: 'mocked storage' }
  }
})

```

`app.e2e.spec.ts`

```ts twoslash
import { setup, $fetch } from '@nuxt/test-utils/e2e'

await setup({
  setupTimeout: 10000,
})

// ...
```

### `@vue/test-utils` の使用

Nuxt での単体テストに `@vue/test-utils` を単独で使用したい場合、かつ Nuxt のコンポーザブル、自動インポート、またはコンテキストに依存しないコンポーネントのみをテストしている場合は、以下の手順に従って設定できます。

1. 必要な依存関係をインストールします

   ::code-group{sync="pm"}
   ```bash [npm]
   npm i --save-dev vitest @vue/test-utils happy-dom @vitejs/plugin-vue
   ```
   ```bash [yarn]
   yarn add --dev vitest @vue/test-utils happy-dom @vitejs/plugin-vue
   ```
   ```bash [pnpm]
   pnpm add -D vitest @vue/test-utils happy-dom @vitejs/plugin-vue
   ```
   ```bash [bun]
   bun add --dev vitest @vue/test-utils happy-dom @vitejs/plugin-vue
   ```
   ::

2. 以下の内容で `vitest.config.ts` を作成します：

   ```ts
   import { defineConfig } from 'vitest/config'
   import vue from '@vitejs/plugin-vue'

   export default defineConfig({
     plugins: [vue()],
     test: {
       environment: 'happy-dom',
     },
   });
   ```

3. `package.json` にテスト用の新しいコマンドを追加します

   ```json
   "scripts": {
     "build": "nuxt build",
     "dev": "nuxt dev",
     ...
     "test": "vitest"
   },
   ```

4. 以下の内容でシンプルな `<HelloWorld>` コンポーネント `components/HelloWorld.vue` を作成します：

   ```vue
   <template>
     <p>Hello world</p>
   </template>
   ```

5. 新しく作成したこのコンポーネントのためのシンプルな単体テスト `~/components/HelloWorld.spec.ts` を作成します

   ```ts twoslash
   import { describe, it, expect } from 'vitest'
   import { mount } from '@vue/test-utils'

   import HelloWorld from './HelloWorld.vue'

   describe('HelloWorld', () => {
     it('component renders Hello world properly', () => {
       const wrapper = mount(HelloWorld)
       expect(wrapper.text()).toContain('Hello world')
     })
   })
   ```

6. vitest コマンドを実行します

   ::code-group{sync="pm"}
   ```bash [npm]
   npm run test
   ```
   ```bash [yarn]
   yarn test
   ```
   ```bash [pnpm]
   pnpm run test
   ```
   ```bash [bun]
   bun run test
   ```
   ::

おめでとうございます。Nuxt で `@vue/test-utils` を使用した単体テストを始める準備が整いました！ハッピーテスティング！

## エンドツーエンドテスト

エンドツーエンドテストでは、テストランナーとして [Vitest](https://github.com/vitest-dev/vitest)、[Jest](https://jestjs.io)、[Cucumber](https://cucumber.io/)、[Playwright](https://playwright.dev/) をサポートしています。

### セットアップ

`@nuxt/test-utils/e2e` ヘルパーメソッドを利用する各 `describe` ブロックでは、開始前にテストコンテキストを設定する必要があります。

```ts twoslash [test/my-test.spec.ts]
import { describe, test } from 'vitest'
import { setup, $fetch } from '@nuxt/test-utils/e2e'

describe('My test', async () => {
  await setup({
    // test context options
  })

  test('my test', () => {
    // ...
  })
})
```

裏側では、`setup` は Nuxt テスト環境を正しく設定するために、`beforeAll`、`beforeEach`、`afterEach`、`afterAll` で多数のタスクを実行します。

`setup` メソッドには以下のオプションを使用してください。

#### Nuxt 設定

- `rootDir`: テスト対象の Nuxt アプリがあるディレクトリへのパス。
  - Type: `string`
  - Default: `'.'`
- `configFile`: 設定ファイルの名前。
  - Type: `string`
  - Default: `'nuxt.config'`

<!--
- `config`: Object with configuration overrides.
  - Type: `NuxtConfig`
  - Default: `{}` -->

#### タイミング

- `setupTimeout`: `setupTest` がその作業を完了するために許可される時間（ミリ秒）（渡されるオプションによっては、Nuxt アプリケーションのビルドやファイル生成が含まれる可能性があります）。
  - Type: `number`
  - Default: `60000`

#### 機能

- `build`: 別途ビルドステップを実行するかどうか。
  - Type: `boolean`
  - Default: `true`（`browser` または `server` が無効になっているか、`host` が提供されている場合は `false`）

- `server`: テストスイート内のリクエストに応答するサーバーを起動するかどうか。
  - Type: `boolean`
  - Default: `true`（`host` が提供されている場合は `false`）

- `port`: 提供された場合、起動されたテストサーバーのポートをこの値に設定します。
  - Type: `number | undefined`
  - Default: `undefined`

- `host`: 提供された場合、新しいサーバーをビルド・実行する代わりにテストターゲットとして使用する URL。アプリケーションのデプロイされたバージョンに対して、または既に実行中のローカルサーバーに対して「本物の」エンドツーエンドテストを実行するのに便利です（テスト実行時間の大幅な短縮を提供する可能性があります）。[以下のターゲットホストエンドツーエンドの例](#target-host-end-to-end-example)をご覧ください。
  - Type: `string`
  - Default: `undefined`

- `browser`: 裏側では、Nuxt テストユーティリティは [`playwright`](https://playwright.dev) を使用してブラウザーテストを実行します。このオプションが設定されている場合、ブラウザーが起動され、後続のテストスイートで制御できます。
  - Type: `boolean`
  - Default: `false`
- `browserOptions`
  - Type: 以下のプロパティを持つ `object`
    - `type`: 起動するブラウザーのタイプ - `chromium`、`firefox`、`webkit` のいずれか
    - `launch`: ブラウザー起動時に playwright に渡されるオプションの `object`。[完全な API リファレンス](https://playwright.dev/docs/api/class-browsertype#browser-type-launch)をご覧ください。
- `runner`: テストスイートのランナーを指定します。現在、[Vitest](https://vitest.dev) が推奨されています。
  - Type: `'vitest' | 'jest' | 'cucumber'`
  - Default: `'vitest'`

##### ターゲット `host` エンドツーエンドの例

エンドツーエンドテストの一般的なユースケースは、通常本番環境で使用されるのと同じ環境で実行されているデプロイされたアプリケーションに対してテストを実行することです。

ローカル開発や自動デプロイパイプラインの場合、別途ローカルサーバーに対してテストを実行する方がより効率的であり、テストフレームワークにテスト間のリビルドを許可するよりも通常高速です。

エンドツーエンドテストに別途ターゲットホストを利用するには、単純に `setup` 関数の `host` プロパティに希望の URL を提供します。

```ts
import { setup, createPage } from '@nuxt/test-utils/e2e'
import { describe, it, expect } from 'vitest'

describe('login page', async () => {
  await setup({
    host: 'http://localhost:8787',
  })

  it('displays the email and password fields', async () => {
    const page = await createPage('/login')
    expect(await page.getByTestId('email').isVisible()).toBe(true)
    expect(await page.getByTestId('password').isVisible()).toBe(true)
  })
})
```

### API

#### `$fetch(url)`

サーバーレンダリングされたページの HTML を取得します。

```ts twoslash
import { $fetch } from '@nuxt/test-utils/e2e'

const html = await $fetch('/')
```

#### `fetch(url)`

サーバーレンダリングされたページのレスポンスを取得します。

```ts twoslash
import { fetch } from '@nuxt/test-utils/e2e'

const res = await fetch('/')
const { body, headers } = res
```

#### `url(path)`

指定されたページの完全な URL を取得します（テストサーバーが実行されているポートを含む）。

```ts twoslash
import { url } from '@nuxt/test-utils/e2e'

const pageUrl = url('/page')
// 'http://localhost:6840/page'
```

### ブラウザーでのテスト

`@nuxt/test-utils` 内で Playwright を使用した組み込みサポートを提供しており、プログラマティックにまたは Playwright テストランナー経由で利用できます。

#### `createPage(url)`

`vitest`、`jest`、または `cucumber` 内で、`createPage` で設定された Playwright ブラウザーインスタンスを作成し、（オプションで）実行中のサーバーからのパスを指定できます。利用可能な API メソッドについて詳しくは、[Playwright ドキュメント](https://playwright.dev/docs/api/class-page)をご覧ください。

```ts twoslash
import { createPage } from '@nuxt/test-utils/e2e'

const page = await createPage('/page')
// `page` 変数からすべての Playwright API にアクセスできます
```

#### Playwright テストランナーでのテスト

[Playwright テストランナー](https://playwright.dev/docs/intro)内での Nuxt テストに対してファーストクラスサポートも提供しています。

::code-group{sync="pm"}
```bash [npm]
npm i --save-dev @playwright/test @nuxt/test-utils
```
```bash [yarn]
yarn add --dev @playwright/test @nuxt/test-utils
```
```bash [pnpm]
pnpm add -D @playwright/test @nuxt/test-utils
```
```bash [bun]
bun add --dev @playwright/test @nuxt/test-utils
```
::

このセクションの前部で言及した `setup()` 関数と同じ設定詳細で、グローバル Nuxt 設定を提供できます。

```ts [playwright.config.ts]
import { fileURLToPath } from 'node:url'
import { defineConfig, devices } from '@playwright/test'
import type { ConfigOptions } from '@nuxt/test-utils/playwright'

export default defineConfig<ConfigOptions>({
  use: {
    nuxt: {
      rootDir: fileURLToPath(new URL('.', import.meta.url))
    }
  },
  // ...
})
```

::read-more{title="See full example config" to="https://github.com/nuxt/test-utils/blob/main/examples/app-playwright/playwright.config.ts" target="_blank"}
::

あなたのテストファイルは、`@nuxt/test-utils/playwright` から直接 `expect` と `test` を使用する必要があります：

```ts [tests/example.test.ts]
import { expect, test } from '@nuxt/test-utils/playwright'

test('test', async ({ page, goto }) => {
  await goto('/', { waitUntil: 'hydration' })
  await expect(page.getByRole('heading')).toHaveText('Welcome to Playwright!')
})
```

代わりに、テストファイル内で直接 Nuxt サーバーを設定することもできます：

```ts [tests/example.test.ts]
import { expect, test } from '@nuxt/test-utils/playwright'

test.use({
  nuxt: {
    rootDir: fileURLToPath(new URL('..', import.meta.url))
  }
})

test('test', async ({ page, goto }) => {
  await goto('/', { waitUntil: 'hydration' })
  await expect(page.getByRole('heading')).toHaveText('Welcome to Playwright!')
})
```
