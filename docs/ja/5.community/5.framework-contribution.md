[一般的な貢献ガイド](/docs/community/contribution)を読んだ後、[`nuxt/nuxt`](https://github.com/nuxt/nuxt) リポジトリへの貢献についての具体的なポイントを以下に示します。

## Monorepo ガイド

- `packages/kit`: Nuxt モジュール作成用ツールキット、[`@nuxt/kit`](https://npmjs.com/package/@nuxt/kit) として公開。
- `packages/nuxt`: Nuxt のコア、[`nuxt`](https://npmjs.com/package/nuxt) として公開。
- `packages/schema`: クロスバージョン Nuxt 型定義とデフォルト、[`@nuxt/schema`](https://npmjs.com/package/@nuxt/schema) として公開。
- `packages/rspack`: Nuxt 用の [Rspack](https://rspack.dev) バンドラー、[`@nuxt/rspack-builder`](https://npmjs.com/package/@nuxt/rspack-builder) として公開。
- `packages/vite`: Nuxt 用の [Vite](https://vite.dev) バンドラー、[`@nuxt/vite-builder`](https://npmjs.com/package/@nuxt/vite-builder) として公開。
- `packages/webpack`: Nuxt 用の [webpack](https://webpack.js.org) バンドラー、[`@nuxt/webpack-builder`](https://npmjs.com/package/@nuxt/webpack-builder) として公開。

## セットアップ

Nuxt に貢献するためには、ローカル環境をセットアップする必要があります。

1. [`nuxt/nuxt`](https://github.com/nuxt/nuxt) リポジトリをあなたの GitHub アカウントに[フォーク](https://help.github.com/articles/fork-a-repo)し、それをローカルデバイスに[クローン](https://help.github.com/articles/cloning-a-repository)します。
2. 最新の [Node.js](https://nodejs.org/en) (20.x) を使用していることを確認します。
3. `pnpm` と `yarn` を使用するために [Corepack](https://github.com/nodejs/corepack) を有効にします。
    ```bash [Terminal]
    corepack enable
    ```
4. pnpm で依存関係をインストールするために `pnpm install --frozen-lockfile` を実行します：
    ```bash [Terminal]
    pnpm install --frozen-lockfile
    ```
    ::note
    依存関係を追加する場合は、`pnpm add` を使用してください。:br
    `pnpm-lock.yaml` ファイルがすべての Nuxt 依存関係の真実の情報源です。
    ::
5. パッシブ開発システムをアクティベートします。
    ```bash [Terminal]
    pnpm dev:prepare
    ```
6. 作業して変更をコミットできるブランチをチェックアウトします：
    ```bash [Terminal]
    git checkout -b my-new-branch
    ```

その後、プルリクエストを提出する前に [プレイグラウンド](#playground) で変更をテストし、変更を[テスト](#testing)してください。

### プレイグラウンド

プルリクエストで作業している間、おそらく変更が正しく動作しているかどうかを確認したいでしょう。

`playground/` のサンプルアプリを修正して、以下を実行できます：

```bash [Terminal]
pnpm dev
```

::important
ブランチにコミットしないように注意してくださいが、PR の説明にサンプルコードを追加すると役立つ可能性があります。これにより、レビューアーや他の Nuxt ユーザーがあなたが構築した機能を深く理解するのに役立ちます。
::

### テスト

すべての新機能には対応するユニットテストがあるべきです（可能な場合）。このリポジトリの `test/` ディレクトリは現在進行中ですが、すでにあるものの例に従って新しいテストを作成するよう最善を尽くしてください。

PR を作成したり、レビュー準備完了としてマークする前に、以下を実行してすべてのテストが成功することを確認してください：

```bash [Terminal]
pnpm test
```

### リント

すでにお気づきかもしれませんが、コーディング標準を強制するために ESLint を使用しています。

変更をコミットする前に、コードスタイルが正しいことを確認するために、以下を実行してください：

```bash [Terminal]
pnpm lint
```

::note
`pnpm lint --fix` を使用して、ほとんどのスタイル変更を修正できます。:br
まだエラーが残っている場合は、手動で修正する必要があります。
::

### ドキュメント

新しい機能を追加したり、リファクタリングしたり、他の方法で Nuxt の動作を変更したりする場合は、おそらく変更を文書化したいでしょう。同じ PR にドキュメントへの変更を含めてください。最初のコミットでドキュメントを書く必要はありません（しかし、プルリクエストが十分に成熟したらすぐに書いてください）。

::important
[ドキュメントスタイルガイド](/docs/community/contribution#documentation-style-guide)に従って変更を行うようにしてください。
::

### 最終チェックリスト

PR を提出する際、記入する必要があるシンプルなテンプレートがあります。チェックリストの適切な「答え」をすべてチェックしてください。

## ドキュメントガイド

ドキュメントやエラーメッセージを改善できる範囲を見つけた場合は、ぜひ PR を開いてください - たとえタイポを修正するだけでも！

::important
[ドキュメントスタイルガイド](/docs/community/contribution#documentation-style-guide)に従って変更を行うようにしてください。
::

### 簡単な編集

タイポを見つけたり、文章を書き直したい場合は、**Community** セクションの右側にある **Edit this page** リンクをクリックできます。

GitHub インターフェースで直接変更して、プルリクエストを開いてください。

### より長い編集

ドキュメントの内容は [nuxt/nuxt](https://github.com/nuxt/nuxt) リポジトリの `docs/` ディレクトリ内にあり、Markdown で書かれています。

::note
ドキュメントをローカルでプレビューするには、[nuxt/nuxt.com](https://github.com/nuxt/nuxt.com) リポジトリの手順に従ってください。
::

::note
VS Code 用の [MDC 拡張機能](https://marketplace.visualstudio.com/items?itemName=Nuxt.mdc)をインストールすることをお勧めします。
::

### ドキュメントのリント

ドキュメントの一貫性を保つために、[MarkdownLint](https://github.com/DavidAnson/markdownlint) と [case police](https://github.com/antfu/case-police) を使用してドキュメントをリントしています。

```bash [Terminal]
pnpm lint:docs
```

::note
`pnpm lint:docs:fix` を実行して、リントの問題をハイライトして解決することもできます。
::

### PR を開く

PR のタイトルが [conventional commits](https://www.conventionalcommits.org) ガイドラインに従っていることを確認してください。

```bash [PR タイトルの例]
docs: update the section about the nuxt.config.ts file
```
