title: 自動インポート
description: "Nuxt はコンポーネント、コンポーザブル、ヘルパー関数、Vue API を自動インポートします。"
---

Nuxt はコンポーネント、コンポーザブル、[Vue.js API](https://vuejs.org/api) を自動インポートし、明示的にインポートすることなくアプリケーション全体で使用できます。

```vue twoslash [app.vue]
<script setup lang="ts">
const count = ref(1) // ref は自動インポートされます
</script>
```

独断的なディレクトリ構造のおかげで、Nuxt は [`components/`](/docs/guide/directory-structure/components)、[`composables/`](/docs/guide/directory-structure/composables)、[`utils/`](/docs/guide/directory-structure/utils) を自動インポートできます。

従来のグローバル宣言とは異なり、Nuxt は型付け、IDE の補完、ヒントを保持し、**本番コードで使用されるものだけを含めます**。

::note
ドキュメントでは、明示的にインポートされていないすべての関数は Nuxt によって自動インポートされ、コード内でそのまま使用できます。自動インポートされるコンポーネント、コンポーザブル、ユーティリティのリファレンスは [API セクション](/docs/api) で見つけることができます。
::

::note
[`server`](/docs/guide/directory-structure/server) ディレクトリでは、Nuxt は `server/utils/` からエクスポートされた関数や変数を自動インポートします。
::

::note
`nuxt.config` ファイルの [`imports`](/docs/api/nuxt-config#imports) セクションを設定することで、カスタムフォルダーやサードパーティパッケージからエクスポートされた関数も自動インポートできます。
::

## 組み込み自動インポート

Nuxt は、[データ取得](/docs/getting-started/data-fetching)、[アプリコンテキスト](/docs/api/composables/use-nuxt-app)、[ランタイム設定](/docs/guide/going-further/runtime-config) へのアクセス、[状態](/docs/getting-started/state-management) の管理、コンポーネントやプラグインの定義を行うための関数やコンポーザブルを自動インポートします。

```vue twoslash
<script setup lang="ts">
/* useFetch() is auto-imported */
const { data, refresh, status } = await useFetch('/api/hello')
</script>
```

Vue は `ref` や `computed` などのリアクティビティ API、およびライフサイクルフックやヘルパーを公開しており、これらは Nuxt によって自動インポートされます。

```vue twoslash
<script setup lang="ts">
/* ref() と computed() は自動インポートされます */
const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### Vue と Nuxt のコンポーザブル

<!-- TODO: move to separate page with https://github.com/nuxt/nuxt/issues/14723 and add more information -->

Vue と Nuxt が提供する組み込みの Composition API コンポーザブルを使用する場合、その多くが正しい _コンテキスト_ で呼び出されることに依存していることに注意してください。

コンポーネントのライフサイクル中、Vue は現在のコンポーネントの一時インスタンスをグローバル変数で追跡し（同様に、Nuxt は `nuxtApp` の一時インスタンスを追跡）、同じティックでそれを解除します。これはサーバーレンダリング時に不可欠であり、リクエスト間の状態汚染（二人のユーザー間で共有参照が漏洩すること）や异なるコンポーネント間の漏洩を防ぐためです。

つまり（非常に稀な例外を除いて）、Nuxt プラグイン、Nuxt ルートミドルウェア、または Vue の setup 関数の外ではこれらを使用できません。さらに、これらは同期的に使用する必要があります。つまり、`<script setup>` ブロック内、`defineNuxtComponent` で宣言されたコンポーネントの setup 関数内、`defineNuxtPlugin` 内、または `defineNuxtRouteMiddleware` 内を除いて、コンポーザブルを呼び出す前に `await` を使用することはできません。これらの場所では、`await` の後でも同期コンテキストを保つための変換を実行します。

`Nuxt instance is unavailable` のようなエラーメッセージが表示された場合、Vue または Nuxt のライフサイクルの間違った場所で Nuxt コンポーザブルを呼び出していることを意味します。

:video-accordion{title="Alexander Lichter が 'Nuxt instance is unavailable' エラーを回避する方法について説明している動画を見る" videoId="ofuKRZLtOdY"}

::tip
非 SFC コンポーネント内で Nuxt コンテキストを必要とするコンポーザブルを使用する場合、`defineComponent` の代わりに `defineNuxtComponent` でコンポーネントをラップする必要があります
::

::read-more{to="/docs/guide/going-further/experimental-features#asynccontext" icon="i-lucide-star"}
非同期関数で Nuxt コンポーザブルを使用するための `asyncContext` 実験的機能をチェックしてください。
::

::read-more{to="https://github.com/nuxt/nuxt/issues/14269#issuecomment-1397352832" target="_blank"}
この GitHub コメントで詳細な説明をご覧ください。
::

**動作しないコードの例:**

```ts twoslash [composables/example.ts]
// コンポーザブル外でランタイム設定にアクセスしようとしています
const config = useRuntimeConfig()

export const useMyComposable = () => {
  // ここでランタイム設定にアクセス
}
```

**動作するコードの例:**

```ts twoslash [composables/example.ts]
export const useMyComposable = () => {
  // コンポーザブルがライフサイクルの正しい場所で呼び出されているため、
  // useRuntimeConfig はここで動作します
  const config = useRuntimeConfig()

  // ...
}
```

## ディレクトリベースの自動インポート

Nuxt は定義されたディレクトリに作成されたファイルを直接自動インポートします：

- `components/` は [Vue コンポーネント](/docs/guide/directory-structure/components) 用です。
- `composables/` は [Vue コンポーザブル](/docs/guide/directory-structure/composables) 用です。
- `utils/` はヘルパー関数やその他のユーティリティ用です。

:link-example{to="/docs/examples/features/auto-imports"}

::warning
**自動インポートされた `ref` と `computed` はコンポーネントの `<template>` でアンラップされません。** :br
これは、テンプレートのトップレベルではない ref を Vue がどのように処理するかに起因しています。詳細は [Vue のドキュメント](https://vuejs.org/guide/essentials/reactivity-fundamentals.html#caveat-when-unwrapping-in-templates) で読むことができます。
::

### 明示的インポート

Nuxt はすべての自動インポートを `#imports` エイリアスで公開しており、必要に応じてインポートを明示的にするために使用できます：

<!-- TODO:twoslash: Twoslash does not support tsconfig paths yet -->

```vue
<script setup lang="ts">
import { ref, computed } from '#imports'

const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### 自動インポートの無効化

コンポーザブルやユーティリティの自動インポートを無効化したい場合は、`nuxt.config` ファイルで `imports.autoImport` を `false` に設定できます。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    autoImport: false
  }
})
```

これにより自動インポートが完全に無効化されますが、`#imports` からの [明示的インポート](#explicit-imports) を使用することは可能です。

### 自動インポートの部分的無効化

`ref` のようなフレームワーク固有の関数は自動インポートされたままにしておいて、自分のコード（例：カスタムコンポーザブル）の自動インポートを無効化したい場合は、`nuxt.config.ts` ファイルで `imports.scan` オプションを `false` に設定できます：

```ts
export default defineNuxtConfig({
  imports: {
    scan: false
  }
})
```

この設定では：
- `ref`、`computed`、`watch` などのフレームワーク関数は手動インポートを必要とせずに動作します。
- コンポーザブルなどのカスタムコードは、ファイル内で手動でインポートする必要があります。

::warning
**注意:** この設定には特定の制限があります：
- プロジェクトをレイヤーで構造化している場合、自動インポートに依存するのではなく、各レイヤーからコンポーザブルを明示的にインポートする必要があります。
- これはレイヤーシステムのオーバーライド機能を壊します。`imports.scan: false` を使用する場合は、この副作用を理解し、それに応じてアーキテクチャを調整してください。
::

## 自動インポートされるコンポーネント

Nuxt は `~/components` ディレクトリからコンポーネントを自動インポートしますが、これはコンポーザブルやユーティリティ関数の自動インポートとは別々に設定されます。

:read-more{to="/docs/guide/directory-structure/components"}

独自の `~/components` ディレクトリからのコンポーネントの自動インポートを無効化するには、`components.dirs` を空の配列に設定できます（ただし、これはモジュールによって追加されたコンポーネントには影響しないことに注意してください）。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: {
    dirs: []
  }
})
```

## サードパーティパッケージからの自動インポート

Nuxt はサードパーティパッケージからの自動インポートも許可しています。

::tip
そのパッケージの Nuxt モジュールを使用している場合、モジュールがすでにそのパッケージの自動インポートを設定している可能性があります。
::

たとえば、`vue-i18n` パッケージからの `useI18n` コンポーザブルの自動インポートを次のように有効化できます：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    presets: [
      {
        from: 'vue-i18n',
        imports: ['useI18n']
      }
    ]
  }
})
```
