## 公開

設定と環境変数をアプリの他の部分に公開するには、[`runtimeConfig`](/docs/api/nuxt-config#runtimeconfig) オプションを使用して、[`nuxt.config`](/docs/guide/directory-structure/nuxt-config) ファイルでランタイム設定を定義する必要があります。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // サーバーサイドでのみ利用可能なプライベートキー
    apiSecret: '123',
    // public 内のキーはクライアントサイドにも公開されます
    public: {
      apiBase: '/api'
    }
  }
})
```

`apiBase` を `runtimeConfig.public` に追加すると、Nuxt はそれを各ページのペイロードに追加します。サーバーとブラウザの両方で `apiBase` にユニバーサルにアクセスできます。

```ts
const runtimeConfig = useRuntimeConfig()

console.log(runtimeConfig.apiSecret)
console.log(runtimeConfig.public.apiBase)
```

::tip
パブリックランタイム設定は Vue テンプレートで `$config.public` でアクセスできます。
::

### シリアライゼーション

ランタイム設定は Nitro に渡される前にシリアライズされます。つまり、シリアライズしてからデシリアライズできないもの（関数、Sets、Maps など）は、`nuxt.config` に設定してはいけません。

`nuxt.config` からアプリケーションにシリアライズ不可能なオブジェクトや関数を渡す代わりに、このコードを Nuxt または Nitro プラグインやミドルウェアに配置できます。

### 環境変数

設定を提供する最も一般的な方法は、[環境変数](https://medium.com/chingu/an-introduction-to-environment-variables-and-how-to-use-them-f602f66d15fa)を使用することです。

::note
Nuxt CLI は開発、ビルド、生成時に `.env` ファイルを読み取るための組み込みサポートを持っています。しかし、ビルドされたサーバーを実行するときは、**`.env` ファイルは読み取られません**。
:read-more{to="/docs/guide/directory-structure/env"}
::

ランタイム設定値は、**ランタイム時に一致する環境変数によって自動的に置き換えられます**。

主要な要件が 2 つあります：

1. 必要な変数は `nuxt.config` で定義されている必要があります。これにより、任意の環境変数がアプリケーションコードに公開されないことが保証されます。

1. 特別に名前が付けられた環境変数のみがランタイム設定プロパティをオーバーライドできます。つまり、`NUXT_` で始まり、`_` を使用してキーと大文字小文字の変更を分隔する大文字の環境変数です。

::warning
`runtimeConfig` 値のデフォルトを*異なる名前の環境変数*に設定すること（たとえば `myVar` を `process.env.OTHER_VARIABLE` に設定）は、ビルド時にのみ動作し、ランタイム時には壊れます。
`runtimeConfig` オブジェクトの構造と一致する環境変数を使用することをお勧めします。
::

::tip{icon="i-lucide-video" to="https://youtu.be/_FYV5WfiWvs" target="_blank"}
runtimeConfig を使用する際に開発者が犯す主要なミスを紹介する Alexander Lichter の動画を視聴してください。
::

#### 例

```ini [.env]
NUXT_API_SECRET=api_secret_token
NUXT_PUBLIC_API_BASE=https://nuxtjs.org
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: '', // NUXT_API_SECRET 環境変数でオーバーライド可能
    public: {
      apiBase: '', // NUXT_PUBLIC_API_BASE 環境変数でオーバーライド可能
    }
  },
})
```

## 読み取り

### Vue アプリ

Nuxt アプリの Vue 部分では、ランタイム設定にアクセスするために [`useRuntimeConfig()`](/docs/api/composables/use-runtime-config) を呼び出す必要があります。

::important
動作はクライアントサイドとサーバーサイドで異なります：

- クライアントサイドでは、`runtimeConfig.public` と `runtimeConfig.app`（Nuxt が内部で使用）のキーのみが利用可能で、オブジェクトは書き込み可能でリアクティブです。

- サーバーサイドでは、ランタイム設定全体が利用可能ですが、コンテキストの共有を避けるために読み取り専用です。
::

```vue [pages/index.vue]
<script setup lang="ts">
const config = useRuntimeConfig()

console.log('ランタイム設定:', config)
if (import.meta.server) {
  console.log('API シークレット:', config.apiSecret)
}
</script>

<template>
  <div>
    <div>開発者コンソールを確認してください！</div>
  </div>
</template>
```

::caution
**セキュリティの注意：** ランタイム設定キーをレンダリングしたり `useState` に渡したりしてクライアントサイドに公開しないよう注意してください。
::

### プラグイン

（カスタム）プラグイン内でランタイム設定を使用したい場合は、`defineNuxtPlugin` 関数内で [`useRuntimeConfig()`](/docs/api/composables/use-runtime-config) を使用できます。

```ts [plugins/config.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const config = useRuntimeConfig()

  console.log('API ベース URL:', config.public.apiBase)
});
```

### サーバールート

`useRuntimeConfig` を使用してサーバールート内でもランタイム設定にアクセスできます。

```ts [server/api/test.ts]
export default defineEventHandler(async (event) => {
  const { apiSecret } = useRuntimeConfig(event)
  const result = await $fetch('https://my.api.com/test', {
    headers: {
      Authorization: `Bearer ${apiSecret}`
    }
  })
  return result
})
```

::note
`useRuntimeConfig` の引数として `event` を渡すことは任意ですが、サーバールートでランタイム時に[環境変数](/docs/guide/going-further/runtime-config#environment-variables)によってオーバーライトされたランタイム設定を取得するために渡すことをお勧めします。
::

## ランタイム設定の型付け

Nuxt は [unjs/untyped](https://github.com/unjs/untyped) を使用して、提供されたランタイム設定から TypeScript インターフェースを自動的に生成しようとします。

しかし、ランタイム設定を手動で型付けすることもできます：

```ts [index.d.ts]
declare module 'nuxt/schema' {
  interface RuntimeConfig {
    apiSecret: string
  }
  interface PublicRuntimeConfig {
    apiBase: string
  }
}
// 型を拡張する際には、何かをインポート/エクスポートすることが常に重要です
export {}
```

::note
`nuxt/schema` は、エンドユーザーがプロジェクトで Nuxt が使用するスキーマのバージョンにアクセスするための便宜として提供されています。モジュール作成者は代わりに `@nuxt/schema` を拡張すべきです。
::
