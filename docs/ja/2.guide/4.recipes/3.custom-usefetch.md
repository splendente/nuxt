Nuxt で作業する際、フロントエンドを作成して外部 API を取得する場合、API からの取得にデフォルトオプションを設定したい場合があります。

[`$fetch`](/docs/api/utils/dollarfetch) ユーティリティ関数（[`useFetch`](/docs/api/composables/use-fetch) Composable で使用）は、意図的にグローバルに設定可能ではありません。これは、アプリケーション全体でフェッチ動作の一貫性を保ち、他の統合（モジュールなど）が `$fetch` などのコアユーティリティの動作に依存できるようにするために重要です。

しかし、Nuxt は API 用のカスタムフェッチャーを作成する方法を提供します（呼び出す API が複数ある場合は複数のフェッチャー）。

## カスタム `$fetch`

[Nuxt プラグイン](/docs/guide/directory-structure/plugins)でカスタム `$fetch` インスタンスを作成しましょう。

::note
`$fetch` は [ofetch](https://github.com/unjs/ofetch) の設定されたインスタンスで、Nuxt サーバーのベース URL の追加や SSR 中の直接関数呼び出し（HTTP ラウンドトリップの回避）をサポートします。
::

ここでは以下を想定します：
- メイン API は https://api.nuxt.com
- [nuxt-auth-utils](https://github.com/atinux/nuxt-auth-utils) を使用してセッションに JWT トークンを保存
- API が `401` ステータスコードで応答した場合、ユーザーを `/login` ページにリダイレクト

```ts [plugins/api.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const { session } = useUserSession()

  const api = $fetch.create({
    baseURL: 'https://api.nuxt.com',
    onRequest({ request, options, error }) {
      if (session.value?.token) {
        // これは ofetch >= 1.4.0 に依存することに注意 - ロックファイルの更新が必要な場合があります
        options.headers.set('Authorization', `Bearer ${session.value?.token}`)
      }
    },
    async onResponseError({ response }) {
      if (response.status === 401) {
        await nuxtApp.runWithContext(() => navigateTo('/login'))
      }
    }
  })

  // useNuxtApp().$api として公開
  return {
    provide: {
      api
    }
  }
})
```

この Nuxt プラグインにより、`$api` が `useNuxtApp()` から公開され、Vue コンポーネントから直接 API 呼び出しができるようになります：

```vue [app.vue]
<script setup>
const { $api } = useNuxtApp()
const { data: modules } = await useAsyncData('modules', () => $api('/modules'))
</script>
```

::callout
[`useAsyncData`](/docs/api/composables/use-async-data) でラップすることで、**サーバーサイドレンダリング時の二重データフェッチを防ぎます**（ハイドレーション時のサーバーとクライアント）。
::

## カスタム `useFetch`/`useAsyncData`

`$api` に必要なロジックが含まれたので、`useAsyncData` + `$api` の使用を置き換える `useAPI` Composable を作成しましょう：

```ts [composables/useAPI.ts]
import type { UseFetchOptions } from 'nuxt/app'

export function useAPI<T>(
  url: string | (() => string),
  options?: UseFetchOptions<T>,
) {
  return useFetch(url, {
    ...options,
    $fetch: useNuxtApp().$api as typeof $fetch
  })
}
```

新しい Composable を使用して、きれいでクリーンなコンポーネントにしましょう：

```vue [app.vue]
<script setup>
const { data: modules } = await useAPI('/modules')
</script>
```

返されるエラーの型をカスタマイズしたい場合も可能です：

```ts
import type { FetchError } from 'ofetch'
import type { UseFetchOptions } from 'nuxt/app'

interface CustomError {
  message: string
  statusCode: number
}

export function useAPI<T>(
  url: string | (() => string),
  options?: UseFetchOptions<T>,
) {
  return useFetch<T, FetchError<CustomError>>(url, {
    ...options,
    $fetch: useNuxtApp().$api
  })
}
```

::note
この例ではカスタム `useFetch` の使用方法を示していますが、カスタム `useAsyncData` でも同じ構造です。
