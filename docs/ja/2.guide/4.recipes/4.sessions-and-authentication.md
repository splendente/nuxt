## イントロダクション

このレシピでは、クライアントサイドとサーバーサイドのセッションデータ管理のための便利なユーティリティを提供する [Nuxt Auth Utils](https://github.com/Atinux/nuxt-auth-utils) を使用して、フルスタック Nuxt アプリで認証を設定します。

このモジュールはセッションデータを保存するためにセキュアおよびシールされた Cookie を使用するため、セッションデータを保存するためのデータベースを設定する必要がありません。

## nuxt-auth-utils のインストール

`nuxt` CLI を使用して `nuxt-auth-utils` モジュールをインストールします。

```bash [Terminal]
npx nuxt module add auth-utils
```

::callout
このコマンドは `nuxt-auth-utils` を依存関係としてインストールし、`nuxt.config.ts` の `modules` セクションに追加します
::

## Cookie 暗号化キー

`nuxt-auth-utils` はセッションデータを保存するためにシールされた Cookie を使用するため、セッション Cookie は `NUXT_SESSION_PASSWORD` 環境変数の秘密キーを使用して暗号化されます。

::note
設定されていない場合、この環境変数は開発モードで実行するときに `.env` に自動的に追加されます。
::

```ini [.env]
NUXT_SESSION_PASSWORD=a-random-password-with-at-least-32-characters
```

::important
デプロイ前に、この環境変数を本番環境に追加する必要があります。
::

## ログイン API ルート

このレシピでは、静的データに基づいてユーザーをサインインするためのシンプルな API ルートを作成します。

リクエストボディでメールとパスワードを受け取る POST リクエストを受け入れる `/api/login` API ルートを作成しましょう。

```ts [server/api/login.post.ts]
import { z } from 'zod'

const bodySchema = z.object({
  email: z.string().email(),
  password: z.string().min(8)
})

export default defineEventHandler(async (event) => {
  const { email, password } = await readValidatedBody(event, bodySchema.parse)

  if (email === 'admin@admin.com' && password === 'iamtheadmin') {
    // Cookie にユーザーセッションを設定
    // このサーバーユーティリティは auth-utils モジュールによって自動インポートされます
    await setUserSession(event, {
      user: {
        name: 'John Doe'
      }
    })
    return {}
  }
  throw createError({
    statusCode: 401,
    message: 'Bad credentials'
  })
})
```

::callout
プロジェクトに `zod` 依存関係をインストールすることを忘れないでください（`npm i zod`）。
::

::tip{to="https://github.com/atinux/nuxt-auth-utils#server-utils"}
`nuxt-auth-utils` が公開する `setUserSession` サーバーヘルパーについて詳しく読む。
::

## ログインページ

このモジュールは、アプリケーションでユーザーが認証されているかどうかを知るための Vue Composable を公開します：

```vue
<script setup>
const { loggedIn, session, user, clear, fetch } = useUserSession()
</script>
```

ログインデータを `/api/login` ルートに送信するフォームを持つログインページを作成しましょう。

```vue [pages/login.vue]
<script setup lang="ts">
const { loggedIn, user, fetch: refreshSession } = useUserSession()
const credentials = reactive({
  email: '',
  password: '',
})
async function login() {
  $fetch('/api/login', {
    method: 'POST',
    body: credentials
  })
  .then(async () => {
    // クライアントサイドでセッションを更新し、ホームページにリダイレクト
    await refreshSession()
    await navigateTo('/')
  })
  .catch(() => alert('Bad credentials'))
}
</script>

<template>
  <form @submit.prevent="login">
    <input v-model="credentials.email" type="email" placeholder="Email" />
    <input v-model="credentials.password" type="password" placeholder="Password" />
    <button type="submit">Login</button>
  </form>
</template>
```

## API ルートの保護

サーバールートを保護することは、データの安全性を確保するための鍵です。クライアントサイドミドルウェアはユーザーにとって有用ですが、サーバーサイドの保護がないとデータにアクセスされる可能性があります。機密データを持つルートを保護することは重要で、ユーザーがログインしていない場合は 401 エラーを返す必要があります。

`auth-utils` モジュールは、ユーザーがログインしていてアクティブなセッションを持っていることを確認するための `requireUserSession` ユーティリティ関数を提供します。

認証されたユーザーのみがアクセスできる `/api/user/stats` ルートの例を作成しましょう。

```ts [server/api/user/stats.get.ts]
export default defineEventHandler(async (event) => {
  // ユーザーがログインしていることを確認
  // リクエストが有効なユーザーセッションから来ていない場合、401 エラーがスローされます
  const { user } = await requireUserSession(event)

  // TODO: ユーザーに基づいて統計情報を取得

  return {}
});
```

## アプリルートの保護

サーバーサイドルートが配置されていることでデータは安全ですが、他に何もしないと、未認証ユーザーが `/users` ページにアクセスしようとしたときに奇妙なデータを取得する可能性があります。クライアントサイドでルートを保護し、ユーザーをログインページにリダイレクトするための[クライアントサイドミドルウェア](https://nuxt.com/docs/guide/directory-structure/middleware)を作成する必要があります。

`nuxt-auth-utils` は、ユーザーがログインしているかどうかをチェックし、ログインしていない場合にリダイレクトするために使用する便利な `useUserSession` Composable を提供します。

`/middleware` ディレクトリにミドルウェアを作成します。サーバーとは異なり、クライアントサイドミドルウェアはすべてのエンドポイントに自動的に適用されるわけではなく、適用したい場所を指定する必要があります。

```typescript [middleware/authenticated.ts]
export default defineNuxtRouteMiddleware(() => {
  const { loggedIn } = useUserSession()

  // 認証されていない場合、ユーザーをログイン画面にリダイレクト
  if (!loggedIn.value) {
    return navigateTo('/login')
  }
})
```

## ホームページ

ルートを保護するアプリミドルウェアができたので、認証されたユーザー情報を表示するホームページで使用できます。ユーザーが認証されていない場合は、ログインページにリダイレクトされます。

保護したいルートにミドルウェアを適用するために [`definePageMeta`](/docs/api/utils/define-page-meta) を使用します。

```vue [pages/index.vue]
<script setup lang="ts">
definePageMeta({
  middleware: ['authenticated'],
})
  
const { user, clear: clearSession } = useUserSession()

async function logout() {
  await clearSession()
  await navigateTo('/login')
}
</script>

<template>
  <div>
    <h1>Welcome {{ user.name }}</h1>
    <button @click="logout">Logout</button>
  </div>
</template>
```

セッションをクリアしてユーザーをログインページにリダイレクトするログアウトボタンも追加しました。

## まとめ

Nuxt アプリで非常に基本的なユーザー認証とセッション管理を正常に設定できました。また、認証されたユーザーのみがアクセスできるように、サーバーとクライアントサイドの機密ルートを保護しました。

次のステップとして、以下ができます：
- [20以上のサポートされた OAuth プロバイダー](https://github.com/atinux/nuxt-auth-utils?tab=readme-ov-file#supported-oauth-providers)を使用した認証を追加
- ユーザーを保存するためのデータベースを追加。[Nitro SQL Database](https://nitro.build/guide/database) または [NuxtHub SQL Database](https://hub.nuxt.com/docs/features/database) を参照
- [パスワードハッシュ化](https://github.com/atinux/nuxt-auth-utils?tab=readme-ov-file#password-hashing)を使用してメールとパスワードでユーザー登録を許可
- [WebAuthn / Passkeys](https://github.com/atinux/nuxt-auth-utils?tab=readme-ov-file#webauthn-passkey) のサポートを追加

OAuth 認証、データベース、CRUD 操作を持つ Nuxt アプリの完全な例は、オープンソースの [atidone リポジトリ](https://github.com/atinux/atidone)をチェックしてください。
