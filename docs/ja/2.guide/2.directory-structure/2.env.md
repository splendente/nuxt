このファイルは、シークレットをリポジトリにプッシュすることを避けるために、[`.gitignore`](/docs/guide/directory-structure/gitignore) ファイルに追加すべきです。
::

## 開発、ビルド、生成時

Nuxt CLI は開発モード、および [`nuxt build`](/docs/api/commands/build) と [`nuxt generate`](/docs/api/commands/generate) を実行する際に、組み込みの [dotenv](https://github.com/motdotla/dotenv) サポートを持っています。

プロセス環境変数に加えて、プロジェクトルートディレクトリに `.env` ファイルがある場合、**開発、ビルド、生成時に**自動的に読み込まれます。そこで設定された環境変数は、`nuxt.config` ファイルやモジュール内でアクセス可能になります。

```ini [.env]
MY_ENV_VARIABLE=hello
```

::note
`.env` から変数を削除したり、`.env` ファイルを完全に削除したりしても、すでに設定されている値はアンセットされないことに注意してください。
::

## カスタムファイル

異なるファイルを使用したい場合（例えば `.env.local` や `.env.production` を使用する場合）、Nuxt CLI を使用する際に `--dotenv` フラグを渡すことで実現できます。

```bash [Terminal]
npx nuxt dev --dotenv .env.local
```

開発モードで `.env` を更新すると、`process.env` に新しい値を適用するために Nuxt インスタンスが自動的に再起動されます。

::important
アプリケーションコードでは、プレーンな環境変数の代わりに [ランタイム設定](/docs/guide/going-further/runtime-config) を使用すべきです。
::

## 本番環境

**サーバーがビルドされた後**、サーバーを実行する際の環境変数の設定はあなたの責任です。

この時点では `.env` ファイルは読み込まれません。これを行う方法は環境ごとに異なります。

この設計決定は、サーバーレスプラットフォームや Cloudflare Workers のようなエッジネットワークなど、伝統的なファイルシステムが利用できない可能性のあるさまざまなデプロイ環境での互換性を保証するために行われました。

本番環境では `.env` ファイルが使用されないため、ホスティング環境が提供するツールと方法を使用して環境変数を明示的に設定する必要があります。一般的なアプローチをいくつか紹介します：

* ターミナルを使用して環境変数を引数として渡すことができます：

   `$ DATABASE_HOST=mydatabaseconnectionstring node .output/server/index.mjs`

* `.bashrc` や `.profile` などのシェル設定ファイルで環境変数を設定できます。

* Vercel、Netlify、AWS などの多くのクラウドサービスプロバイダーは、ダッシュボード、CLI ツール、または設定ファイルを介して環境変数を設定するインターフェースを提供しています。

## 本番環境プレビュー

ローカル本番環境プレビューの目的では、[`nuxt preview`](/docs/api/commands/preview) の使用を推奨します。このコマンドを使用すると、便宜上 `.env` ファイルが `process.env` に読み込まれます。このコマンドはパッケージディレクトリに依存関係がインストールされている必要があることに注意してください。

または、ターミナルを使用して環境変数を引数として渡すこともできます。例えば、Linux や macOS では：

```bash [Terminal]
DATABASE_HOST=mydatabaseconnectionstring node .output/server/index.mjs
```

純粹な静的サイトの場合、プロジェクトがプリレンダリングされた後にランタイム設定を設定することはできないことに注意してください。

:read-more{to="/docs/guide/going-further/runtime-config"}

::note
ビルド時に設定された環境変数を使用したいが、将来的な更新は気にしない（またはアプリ_内_でリアクティブに更新するだけでよい）場合は、`appConfig` の方が適している可能性があります。`appConfig` は `nuxt.config`（環境変数を使用）とプロジェクト内の `~/app.config.ts` ファイルの両方で定義できます。
:read-more{to="/docs/guide/directory-structure/app-config"}
::
