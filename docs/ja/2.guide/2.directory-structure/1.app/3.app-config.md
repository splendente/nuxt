Nuxt は `app.config` 設定ファイルを提供し、ライフサイクル内やnuxtプラグインを使用してランタイムで更新でき、HMR（ホットモジュール置換）で編集できる機能とともに、アプリケーション内でリアクティブな設定を公開します。

`app.config.ts` ファイルを使用してランタイムアプリ設定を簡単に提供できます。`.ts`、`.js`、または `.mjs` のいずれかの拡張子を持つことができます。

```ts twoslash [app.config.ts]
export default defineAppConfig({
  foo: 'bar'
})
```

::caution
`app.config` ファイル内に秘密の値を入れないでください。これはユーザークライアントバンドルに公開されます。
::

::note
カスタム [`srcDir`](/docs/api/nuxt-config#srcdir) を設定する場合は、新しい `srcDir` パスのルートに `app.config` ファイルを配置するようにしてください。
::

## 使用方法

アプリケーションの残りの部分に設定と環境変数を公開するには、`app.config` ファイルで設定を定義する必要があります。

```ts twoslash [app.config.ts]
export default defineAppConfig({
  theme: {
    primaryColor: '#ababab'
  }
})
```

[`useAppConfig`](/docs/api/composables/use-app-config) コンポーザブルを使用して、ページのサーバーレンダリング時とブラウザーの両方で `theme` にユニバーサルにアクセスできるようになりました。

```vue [pages/index.vue]
<script setup lang="ts">
const appConfig = useAppConfig()

console.log(appConfig.theme)
</script>
```

[`updateAppConfig`](/docs/api/utils/update-app-config) ユーティリティを使用して、ランタイムで `app.config` を更新できます。

```vue [pages/index.vue]
<script setup>
const appConfig = useAppConfig() // { foo: 'bar' }

const newAppConfig = { foo: 'baz' }

updateAppConfig(newAppConfig)

console.log(appConfig) // { foo: 'baz' }
</script>
```

::read-more{to="/docs/api/utils/update-app-config"}
`updateAppConfig` ユーティリティについて詳しく読む。
::

## App Config の型付け

Nuxt は提供されたアプリ設定から TypeScript インターフェースを自動的に生成しようとするため、自分で型付けする必要はありません。

ただし、自分で型付けしたい場合があります。型付けできるものは 2 つあります。

### App Config 入力

`AppConfigInput` は、アプリ設定を設定する際の有効な _入力_ オプションを宣言するモジュール作成者によって使用される場合があります。これは `useAppConfig()` の型には影響しません。

```ts [index.d.ts]
declare module 'nuxt/schema' {
  interface AppConfigInput {
    /** テーマ設定 */
    theme?: {
      /** プライマリアプリカラー */
      primaryColor?: string
    }
  }
}

// 型を拡張する際は、何かをインポート/エクスポートすることが常に重要です
export {}
```

### App Config 出力

[`useAppConfig()`](/docs/api/composables/use-app-config) を呼び出した結果を型付けしたい場合は、`AppConfig` を拡張する必要があります。

::warning
`AppConfig` を型付けする際は注意してください。実際に定義されたアプリ設定から Nuxt が推論する型を上書きしてしまいます。
::

```ts [index.d.ts]
declare module 'nuxt/schema' {
  interface AppConfig {
    // これは既存の推論された `theme` プロパティを完全に置き換えます
    theme: {
      // 文字列リテラル型など、Nuxt が推論できるよりも具体的な型を追加するために
      // この値を型付けしたい場合があります
      primaryColor?: 'red' | 'blue'
    }
  }
}

// 型を拡張する際は、何かをインポート/エクスポートすることが常に重要です
export {}
```

## マージ戦略

Nuxt は、アプリケーションの[レイヤー](/docs/getting-started/layers)内で `AppConfig` に対してカスタムマージ戦略を使用します。

この戦略は [Function Merger](https://github.com/unjs/defu#function-merger) を使用して実装されており、値として配列を持つ `app.config` のすべてのキーに対してカスタムマージ戦略を定義できます。

::note
関数マージャーは拡張レイヤーでのみ使用でき、プロジェクトのメイン `app.config` では使用できません。
::

使用方法の例を以下に示します：

::code-group

```ts twoslash [layer/app.config.ts]
export default defineAppConfig({
  // デフォルト配列値
  array: ['hello'],
})
```

```ts twoslash [app.config.ts]
export default defineAppConfig({
  // マージャー関数を使用してデフォルト配列値を上書き
  array: () => ['bonjour'],
})
```

::

## 既知の制限

Nuxt v3.3 の時点で、`app.config.ts` ファイルは Nitro と共有されており、これにより以下の制限が生じます：

1. `app.config.ts` で Vue コンポーネントを直接インポートできません。
2. 一部の自動インポートが Nitro コンテキストで利用できません。

これらの制限は、Nitro が完全な Vue コンポーネントサポートなしでアプリ設定を処理するために発生します。

回避策として Nitro 設定で Vite プラグインを使用することは可能ですが、このアプローチは推奨されません：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    vite: {
      plugins: [vue()]
    }
  }
})
```

::warning
この回避策を使用すると、予期しない動作やバグにつながる可能性があります。Vue プラグインは、Nitro コンテキストで利用できない多くのプラグインの一つです。
::

関連する課題：
- [Issue #19858](https://github.com/nuxt/nuxt/issues/19858)
- [Issue #19854](https://github.com/nuxt/nuxt/issues/19854)

::note
Nitro v3 では、アプリ設定のサポートを削除することでこれらの制限を解決する予定です。
進捗は[このプルリクエスト](https://github.com/nitrojs/nitro/pull/2521)で追跡できます。
::
