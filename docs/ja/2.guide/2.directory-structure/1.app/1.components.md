Nuxt は、このディレクトリ内のすべてのコンポーネント（および使用しているモジュールによって登録されたコンポーネント）を自動的にインポートします。

```bash [Directory Structure]
-| components/
---| AppHeader.vue
---| AppFooter.vue
```

```html [app.vue]
<template>
  <div>
    <AppHeader />
    <NuxtPage />
    <AppFooter />
  </div>
</template>
```

## コンポーネント名

次のようなネストされたディレクトリにコンポーネントがある場合：

```bash [Directory Structure]
-| components/
---| base/
-----| foo/
-------| Button.vue
```

... コンポーネントの名前は、重複セグメントを削除した独自のパスディレクトリとファイル名に基づきます。したがって、コンポーネントの名前は次のようになります：

```html
<BaseFooButton />
```

::note
明確さのために、コンポーネントのファイル名がその名前と一致することを推奨します。つまり、上記の例では、`Button.vue` を `BaseFooButton.vue` に名前変更できます。
::

パスではなく名前のみに基づいてコンポーネントを自動インポートしたい場合は、設定オブジェクトの拡張形式を使用して `pathPrefix` オプションを `false` に設定する必要があります：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    {
      path: '~/components',
      pathPrefix: false, // [!code ++]
    },
  ],
});
```

これは Nuxt 2 で使用されていたのと同じ戦略でコンポーネントを登録します。例えば、`~/components/Some/MyComponent.vue` は `<SomeMyComponent>` ではなく `<MyComponent>` として使用できます。

## 動的コンポーネント

Vue の `<component :is="someComputedComponent">`{lang=vue} 構文を使用したい場合は、Vue が提供する `resolveComponent` ヘルパーを使用するか、`#components` からコンポーネントを直接インポートして `is` prop に渡す必要があります。

例えば：

```vue [pages/index.vue]
<script setup lang="ts">
import { SomeComponent } from '#components'

const MyButton = resolveComponent('MyButton')
</script>

<template>
  <component :is="clickable ? MyButton : 'div'" />
  <component :is="SomeComponent" />
</template>
```

::important
`resolveComponent` を使用して動的コンポーネントを処理する場合は、コンポーネントの名前以外は何も挿入しないでください。名前はリテラル文字列であり、変数であったり変数を含んではいけません。文字列はコンパイル段階で静的に解析されます。
::

:video-accordion{title="Daniel Roe の resolveComponent() に関する短いビデオを視聴する" videoId="4kq8E5IUM2U"}

その他の方法として（推奨されませんが）、すべてのコンポーネントをグローバルに登録することもできます。これにより、すべてのコンポーネントに対して非同期チャンクが作成され、アプリケーション全体で利用可能になります。

```diff
  export default defineNuxtConfig({
    components: {
+     global: true,
+     dirs: ['~/components']
    },
  })
```

`~/components/global` ディレクトリに配置するか、ファイル名に `.global.vue` サフィックスを使用することで、一部のコンポーネントを選択的にグローバル登録することもできます。上記のとおり、各グローバルコンポーネントは別々のチャンクでレンダリングされるため、この機能を使いすぎないよう注意してください。

::note
`global` オプションはコンポーネントディレクトリごとに設定することもできます。
::

## 動的インポート

コンポーネントを動的にインポートする（コンポーネントの遅延読み込みとも呼ばれる）には、コンポーネントの名前に `Lazy` プレフィックスを付けるだけです。これはコンポーネントが必ずしも必要でない場合に特に便利です。

`Lazy` プレフィックスを使用することで、適切なタイミングまでコンポーネントコードの読み込みを遅らせることができ、JavaScript バンドルサイズの最適化に役立ちます。

```vue [pages/index.vue]
<script setup lang="ts">
const show = ref(false)
</script>

<template>
  <div>
    <h1>Mountains</h1>
    <LazyMountainsList v-if="show" />
    <button v-if="!show" @click="show = true">Show List</button>
  </div>
</template>
```

## 遅延（またはレイジー）ハイドレーション

レイジーコンポーネントはアプリのチャンクサイズを制御するのに適していますが、条件付きレンダリングされない限り依然として積極的に読み込まれるため、必ずしもランタイムパフォーマンスを向上させるわけではありません。実際のアプリケーションでは、一部のページに多くのコンテンツと多くのコンポーネントが含まれることがあり、そのほとんどはページが読み込まれた直後にインタラクティブである必要がありません。すべてを積極的に読み込ませるとパフォーマンスに悪影響を与える可能性があります。

アプリを最適化するために、一部のコンポーネントのハイドレーションを、それらが表示されるまで、またはブラウザーがより重要なタスクを完了するまで遅らせたい場合があります。

Nuxt はレイジー（または遅延）ハイドレーションを使用してこれをサポートし、コンポーネントがインタラクティブになるタイミングを制御できます。

### ハイドレーション戦略

Nuxt はさまざまな組み込みハイドレーション戦略を提供します。レイジーコンポーネントごとに使用できる戦略は一つだけです。

::warning
現在、Nuxt の組み込みレイジーハイドレーションは単一ファイルコンポーネント（SFC）でのみ動作し、テンプレートで prop を定義する必要があります（`v-bind` で props のオブジェクトを展開するのではなく）。また、`#components` からの直接インポートでは動作しません。
::

#### `hydrate-on-visible`

コンポーネントがビューポート内で表示されたときにハイドレートします。

```vue [pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-visible />
  </div>
</template>
```

::read-more{to="https://developer.mozilla.org/en-US/docs/Web/API/IntersectionObserver/IntersectionObserver" title="IntersectionObserver オプション"}
`hydrate-on-visible` のオプションについて詳しく読む。
::

::note
内部的には、これは Vue の組み込み [`hydrateOnVisible` 戦略](https://vuejs.org/guide/components/async.html#hydrate-on-visible)を使用します。
::

#### `hydrate-on-idle`

ブラウザーがアイドル状態のときにコンポーネントをハイドレートします。これはコンポーネントを可能な限り早く読み込みたいが、重要なレンダリングパスをブロックしたくない場合に適しています。

最大タイムアウトとして機能する数値を渡すこともできます。

```vue [pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-idle />
  </div>
</template>
```

::note
内部的には、これは Vue の組み込み [`hydrateOnIdle` 戦略](https://vuejs.org/guide/components/async.html#hydrate-on-idle)を使用します。
::

#### `hydrate-on-interaction`

指定されたインタラクション（例：クリック、マウスオーバー）の後にコンポーネントをハイドレートします。

```vue [pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-interaction="mouseover" />
  </div>
</template>
```

イベントまたはイベントのリストを渡さない場合、デフォルトで `pointerenter`、`click`、`focus` でハイドレートします。

::note
内部的には、これは Vue の組み込み [`hydrateOnInteraction` 戦略](https://vuejs.org/guide/components/async.html#hydrate-on-interaction)を使用します。
::

#### `hydrate-on-media-query`

ウィンドウがメディアクエリにマッチしたときにコンポーネントをハイドレートします。

```vue [pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-media-query="(max-width: 768px)" />
  </div>
</template>
```

::note
内部的には、これは Vue の組み込み [`hydrateOnMediaQuery` 戦略](https://vuejs.org/guide/components/async.html#hydrate-on-media-query)を使用します。
::

#### `hydrate-after`

指定された遅延（ミリ秒単位）の後にコンポーネントをハイドレートします。

```vue [pages/index.vue]
<template>
  <div>
    <LazyMyComponent :hydrate-after="2000" />
  </div>
</template>
```

#### `hydrate-when`

ブール条件に基づいてコンポーネントをハイドレートします。

```vue [pages/index.vue]
<template>
  <div>
    <LazyMyComponent :hydrate-when="isReady" />
  </div>
</template>
<script setup lang="ts">
const isReady = ref(false)
function myFunction() {
  // trigger custom hydration strategy...
  isReady.value = true
}
</script>
```

#### `hydrate-never`

コンポーネントを絶対にハイドレートしません。

```vue [pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-never />
  </div>
</template>
```

### ハイドレーションイベントの監視

すべての遅延ハイドレーションコンポーネントは、ハイドレートされたときに `@hydrated` イベントを発行します。

```vue [pages/index.vue]
<template>
  <div>
    <LazyMyComponent hydrate-on-visible @hydrated="onHydrate" />
  </div>
</template>

<script setup lang="ts">
function onHydrate() {
  console.log("Component has been hydrated!")
}
</script>
```

### 注意事項とベストプラクティス

遅延ハイドレーションはパフォーマンスのメリットを提供できますが、正しく使用することが重要です：

1. **ビューポート内コンテンツを優先する：** 重要なファーストビューコンテンツには遅延ハイドレーションを使用しないでください。すぐに必要でないコンテンツに最適です。

2. **条件付きレンダリング：** レイジーコンポーネントで `v-if="false"` を使用している場合、遅延ハイドレーションは必要ない可能性があります。通常のレイジーコンポーネントを使用するだけです。

3. **共有状態：** 複数のコンポーネント間での共有状態（`v-model`）に注意してください。一つのコンポーネントでモデルを更新すると、そのモデルにバインドされたすべてのコンポーネントでハイドレーションがトリガーされる可能性があります。

4. **各戦略の意図された使用例を使用する：** 各戦略は特定の目的のために最適化されています。
    * `hydrate-when` は必ずしもハイドレートする必要がないコンポーネントに最適です。
    * `hydrate-after` は特定の時間待つことができるコンポーネント用です。
    * `hydrate-on-idle` はブラウザーがアイドル状態のときにハイドレートできるコンポーネント用です。

5. **インタラクティブコンポーネントで `hydrate-never` を避ける：** コンポーネントがユーザーインタラクションを必要とする場合、絶対にハイドレートしないように設定すべきではありません。

## 直接インポート

Nuxt の自動インポート機能をバイパスしたい場合やその必要がある場合は、`#components` からコンポーネントを明示的にインポートすることもできます。

```vue [pages/index.vue]
<script setup lang="ts">
import { NuxtLink, LazyMountainsList } from '#components'

const show = ref(false)
</script>

<template>
  <div>
    <h1>Mountains</h1>
    <LazyMountainsList v-if="show" />
    <button v-if="!show" @click="show = true">Show List</button>
    <NuxtLink to="/">Home</NuxtLink>
  </div>
</template>
```

## カスタムディレクトリ

デフォルトでは、`~/components` ディレクトリのみがスキャンされます。他のディレクトリを追加したい場合、またはこのディレクトリのサブフォルダ内でコンポーネントのスキャン方法を変更したい場合は、設定に追加ディレクトリを追加できます：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    // ~/calendar-module/components/event/Update.vue => <EventUpdate />
    { path: '~/calendar-module/components' },

    // ~/user-module/components/account/UserDeleteDialog.vue => <UserDeleteDialog />
    { path: '~/user-module/components', pathPrefix: false },

    // ~/components/special-components/Btn.vue => <SpecialBtn />
    { path: '~/components/special-components', prefix: 'Special' },

    // It's important that this comes last if you have overrides you wish to apply
    // to sub-directories of `~/components`.
    //
    // ~/components/Btn.vue => <Btn />
    // ~/components/base/Btn.vue => <BaseBtn />
    '~/components'
  ]
})
```

::note
ネストされたディレクトリは順番にスキャンされるため、最初に追加する必要があります。
::

## npm パッケージ

npm パッケージからコンポーネントを自動インポートしたい場合は、[ローカルモジュール](/docs/guide/directory-structure/modules)で [`addComponent`](/docs/api/kit/components#addcomponent) を使用して登録できます。

::code-group

```ts twoslash [~/modules/register-component.ts]
import { addComponent, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup() {
    // import { MyComponent as MyAutoImportedComponent } from 'my-npm-package'
    addComponent({
      name: 'MyAutoImportedComponent',
      export: 'MyComponent',
      filePath: 'my-npm-package',
    })
  },
})
```

```vue [app.vue]
<template>
  <div>
    <!--  the component uses the name we specified and is auto-imported  -->
    <MyAutoImportedComponent />
  </div>
</template>
```

::

## コンポーネントの拡張子

デフォルトでは、[`nuxt.config.ts` の extensions キー](/docs/api/nuxt-config#extensions)で指定された拡張子を持つすべてのファイルがコンポーネントとして扱われます。
コンポーネントとして登録されるファイル拡張子を制限する必要がある場合は、コンポーネントディレクトリ宣言の拡張形式とその `extensions` キーを使用できます：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: [
    {
      path: '~/components',
      extensions: ['.vue'], // [!code ++]
    }
  ]
})
```

## クライアントコンポーネント

コンポーネントがクライアントサイドでのみレンダリングされることを意図している場合は、コンポーネントに `.client` サフィックスを追加できます。

```bash [Directory Structure]
| components/
--| Comments.client.vue
```

```vue [pages/example.vue]
<template>
  <div>
    <!-- this component will only be rendered on client side -->
    <Comments />
  </div>
</template>
```

::note
この機能は Nuxt の自動インポートと `#components` インポートでのみ動作します。これらのコンポーネントを実際のパスから明示的にインポートしても、クライアント専用コンポーネントには変換されません。
::

::important
`.client` コンポーネントはマウントされた後にのみレンダリングされます。`onMounted()` を使用してレンダリングされたテンプレートにアクセスするには、`onMounted()` フックのコールバックで `await nextTick()` を追加してください。
::

::read-more{to="/docs/api/components/client-only"}
`<ClientOnly>` コンポーネントでも同様の結果を得ることができます。
::

## サーバーコンポーネント

サーバーコンポーネントは、クライアントサイドアプリ内で個別のコンポーネントをサーバーレンダリングできます。静的サイトを生成している場合でも、Nuxt 内でサーバーコンポーネントを使用することが可能です。これにより、動的コンポーネント、サーバーレンダリングされた HTML、さらには静的なマークアップのチャンクを混在させた複雑なサイトを構築することが可能になります。

サーバーコンポーネントは単独で使用するか、[クライアントコンポーネント](#paired-with-a-client-component)とペアで使用することができます。

:video-accordion{title="Nuxt サーバーコンポーネントに関する Learn Vue の動画を視聴する" videoId="u1yyXe86xJM"}

::tip{icon="i-lucide-newspaper" to="https://roe.dev/blog/nuxt-server-components" target="_blank"}
Daniel Roe の Nuxt サーバーコンポーネントガイドを読む。
::

### スタンドアロンサーバーコンポーネント

スタンドアロンサーバーコンポーネントは常にサーバーでレンダリングされ、Islands コンポーネントとしても知られています。

props が更新されると、ネットワークリクエストが発生し、レンダリングされた HTML がその場で更新されます。

サーバーコンポーネントは現在実験的であり、使用するには nuxt.config で 'component islands' 機能を有効にする必要があります：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    componentIslands: true
  }
})
```

これで `.server` サフィックスでサーバー専用コンポーネントを登録し、アプリケーションのどこでも自動的に使用できるようになります。

```bash [Directory Structure]
-| components/
---| HighlightedMarkdown.server.vue
```

```vue [pages/example.vue]
<template>
  <div>
    <!--
      this will automatically be rendered on the server, meaning your markdown parsing + highlighting
      libraries are not included in your client bundle.
     -->
    <HighlightedMarkdown markdown="# Headline" />
  </div>
</template>
```

Server-only components use [`<NuxtIsland>`](/docs/api/components/nuxt-island) under the hood, meaning that `lazy` prop and `#fallback` slot are both passed down to it.

::warning
Server components (and islands) must have a single root element. (HTML comments are considered elements as well.)
::

::warning
Props are passed to server components via URL query parameters, and are therefore limited by the possible length of a URL, so be careful not to pass enormous amounts of data to server components via props.
::

::warning
Be careful when nesting islands within other islands as each island adds some extra overhead.
::

::warning
Most features for server-only components and island components, such as slots and client components, are only available for single file components.
::

#### サーバーコンポーネント内のクライアントコンポーネント

::note
この機能には、設定内で `experimental.componentIslands.selectiveClient` を true にする必要があります。
::

クライアントサイドで読み込みたいコンポーネントに `nuxt-client` 属性を設定することで、コンポーネントを部分的にハイドレートできます。

```vue [components/ServerWithClient.vue]
<template>
  <div>
    <HighlightedMarkdown markdown="# Headline" />
    <!-- Counter will be loaded and hydrated client-side -->
    <Counter nuxt-client :count="5" />
  </div>
</template>
```

::note
This only works within a server component. Slots for client components are working only with `experimental.componentIsland.selectiveClient` set to `'deep'` and since they are rendered server-side, they are not interactive once client-side.
::

#### サーバーコンポーネントコンテキスト

サーバー専用または island コンポーネントをレンダリングするとき、`<NuxtIsland>` は `NuxtIslandResponse` を返す fetch リクエストを発行します。（これはサーバーでレンダリングされる場合は内部リクエスト、クライアントサイドナビゲーションでレンダリングされる場合はネットワークタブで確認できるリクエストです。）

これは次のことを意味します：

* `NuxtIslandResponse` を作成するために、サーバーサイドで新しい Vue アプリが作成されます。
* コンポーネントをレンダリングする間に新しい 'island コンテキスト' が作成されます。
* アプリの他の部分から 'island コンテキスト' にアクセスすることはできず、island コンポーネントからアプリの他の部分のコンテキストにアクセスすることもできません。つまり、サーバーコンポーネントまたは island はアプリの他の部分から_分離_されています。
* プラグインに `env: { islands: false }` が設定されていない限り（オブジェクト構文プラグインで実行可能）、island をレンダリングするときにプラグインが再実行されます。

island コンポーネント内では、`nuxtApp.ssrContext.islandContext` を介してその island コンテキストにアクセスできます。island コンポーネントはまだ実験的としてマークされているため、このコンテキストの形式は変更される可能性があることに注意してください。

::note
スロットはインタラクティブにでき、`display: contents;` が設定された `<div>` でラップされます。
::

### クライアントコンポーネントとのペア

この場合、`.server` + `.client` コンポーネントはコンポーネントの 2 つの '半分' であり、サーバーサイドとクライアントサイドでのコンポーネントの別々の実装のための高度な使用例で使用できます。

```bash [Directory Structure]
-| components/
---| Comments.client.vue
---| Comments.server.vue
```

```vue [pages/example.vue]
<template>
  <div>
    <!-- this component will render Comments.server on the server then Comments.client once mounted in the browser -->
    <Comments />
  </div>
</template>
```

## ライブラリ作成者

自動ツリーシェイキングとコンポーネント登録を備えた Vue コンポーネントライブラリの作成は非常に簡単です。✨

Nuxt モジュール内でコンポーネントディレクトリを登録するために、`@nuxt/kit` が提供する [`addComponentsDir`](/docs/api/kit/components#addcomponentsdir) メソッドを使用できます。

次のようなディレクトリ構造を想像してください：

```bash [Directory Structure]
-| node_modules/
---| awesome-ui/
-----| components/
-------| Alert.vue
-------| Button.vue
-----| nuxt.ts
-| pages/
---| index.vue
-| nuxt.config.ts
```

そして `awesome-ui/nuxt.ts` で `addComponentsDir` フックを使用できます：

```ts twoslash
import { createResolver, defineNuxtModule, addComponentsDir } from '@nuxt/kit'

export default defineNuxtModule({
  setup() {
    const resolver = createResolver(import.meta.url)

    // Add ./components dir to the list
    addComponentsDir({
      path: resolver.resolve('./components'),
      prefix: 'awesome',
    })
  },
})
```

これで完了です！これでプロジェクトで、`nuxt.config` ファイルで UI ライブラリを Nuxt モジュールとしてインポートできます：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['awesome-ui/nuxt']
})
```

... そして `pages/index.vue` でモジュールコンポーネント（`awesome-` プレフィックス付き）を直接使用できます：

```vue
<template>
  <div>
    My <AwesomeButton>UI button</AwesomeButton>!
    <awesome-alert>Here's an alert!</awesome-alert>
  </div>
</template>
```

使用される場合のみコンポーネントを自動的にインポートし、`node_modules/awesome-ui/components/` でコンポーネントを更新するときに HMR もサポートします。
