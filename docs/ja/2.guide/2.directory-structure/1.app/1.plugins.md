Nuxt は `plugins/` ディレクトリ内のファイルを自動的に読み取り、Vue アプリケーションの作成時にロードします。

::note
内部のすべてのプラグインは自動登録されるため、`nuxt.config` に個別に追加する必要はありません。
::

::note
ファイル名に `.server` または `.client` サフィックスを使用して、サーバーサイドまたはクライアントサイドでのみプラグインを読み込むことができます。
::

## 登録されるプラグイン

ディレクトリのトップレベルのファイル（または任意のサブディレクトリ内のインデックスファイル）のみがプラグインとして自動登録されます。

```bash [ディレクトリ構造]
-| plugins/
---| foo.ts      // スキャンされる
---| bar/
-----| baz.ts    // スキャンされない
-----| foz.vue   // スキャンされない
-----| index.ts  // 現在スキャンされるが非推奨
```

`foo.ts` と `bar/index.ts` のみが登録されます。

サブディレクトリ内のプラグインを追加するには、`nuxt.config.ts` で [`plugins`](/docs/api/nuxt-config#plugins-1) オプションを使用できます：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  plugins: [
    '~/plugins/bar/baz',
    '~/plugins/bar/foz'
  ]
})
```

## プラグインの作成

プラグインに渡される唯一の引数は [`nuxtApp`](/docs/api/composables/use-nuxt-app) です。

```ts twoslash [plugins/hello.ts]
export default defineNuxtPlugin(nuxtApp => {
  // nuxtApp で何かを行う
})
```

### オブジェクト構文プラグイン

より高度な使用例では、オブジェクト構文を使用してプラグインを定義することも可能です。例えば：

```ts twoslash [plugins/hello.ts]
export default defineNuxtPlugin({
  name: 'my-plugin',
  enforce: 'pre', // または 'post'
  async setup (nuxtApp) {
    // これは通常の関数プラグインと同等です
  },
  hooks: {
    // ここで Nuxt アプリランタイムフックを直接登録できます
    'app:created'() {
      const nuxtApp = useNuxtApp()
      // フック内で何かを行う
    }
  },
  env: {
    // サーバー専用または island コンポーネントをレンダリングする際にプラグインを実行したくない場合は、この値を `false` に設定します。
    islands: true
  }
})
```

:video-accordion{title="Alexander Lichter による Nuxt プラグインのオブジェクト構文に関する動画を視聴する" videoId="2aXZyXB1QGQ"}

::note
オブジェクト構文を使用している場合、プロパティは静的に解析されてより最適化されたビルドが生成されます。そのため、実行時にそれらを定義すべきではありません。:br
例えば、`enforce: import.meta.server ? 'pre' : 'post'` を設定すると、Nuxt がプラグインに対して行うことができる将来の最適化を無効にしてしまいます。
Nuxt はオブジェクト構文を使用する際にフックリスナーを静的に事前読み込みするため、プラグイン登録の順序を気にすることなくフックを定義できます。
::

## 登録順序

ファイル名に「アルファベット順」の番号を付けることで、プラグインが登録される順序を制御できます。

```bash [ディレクトリ構造]
plugins/
 | - 01.myPlugin.ts
 | - 02.myOtherPlugin.ts
```

この例では、`02.myOtherPlugin.ts` は `01.myPlugin.ts` によって注入されたものにアクセスできます。

これは、別のプラグインに依存するプラグインがある状況で有用です。

::note
「アルファベット順」の番号付けに慣れていない場合は、ファイル名は数値ではなく文字列としてソートされることを覚えておいてください。例えば、`10.myPlugin.ts` は `2.myOtherPlugin.ts` よりも前に来るでしょう。これが例で一桁の数字に `0` を付ける理由です。
::

## 読み込み戦略

### 並列プラグイン

デフォルトでは、Nuxt はプラグインを順次読み込みます。プラグインを `parallel` として定義することで、Nuxt は次のプラグインを読み込む前にそのプラグインの実行終了を待ちません。

```ts twoslash [plugins/my-plugin.ts]
export default defineNuxtPlugin({
  name: 'my-plugin',
  parallel: true,
  async setup (nuxtApp) {
    // 次のプラグインはすぐに実行されます
  }
})
```

### 依存関係を持つプラグイン

プラグインが実行前に別のプラグインを待つ必要がある場合は、`dependsOn` 配列にプラグイン名を追加できます。

```ts twoslash [plugins/depending-on-my-plugin.ts]
export default defineNuxtPlugin({
  name: 'depends-on-my-plugin',
  dependsOn: ['my-plugin'],
  async setup (nuxtApp) {
    // このプラグインは実行前に `my-plugin` の実行終了を待ちます
  }
})
```

## コンポーザブルの使用

Nuxt プラグイン内で[コンポーザブル](/docs/guide/directory-structure/composables)と[ユーティリティ](/docs/guide/directory-structure/utils)を使用できます：

```ts [plugins/hello.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const foo = useFoo()
})
```

ただし、いくつかの制限と違いがあることに注意してください：

::important
**コンポーザブルが後で登録される別のプラグインに依存している場合、動作しない可能性があります。**:br

プラグインは順次呼び出され、他のすべてより前に実行されます。まだ呼び出されていない別のプラグインに依存するコンポーザブルを使用する可能性があります。
::

::important
**コンポーザブルが Vue.js ライフサイクルに依存している場合、動作しません。**:br

通常、Vue.js コンポーザブルは現在のコンポーネントインスタンスにバインドされますが、プラグインは [`nuxtApp`](/docs/api/composables/use-nuxt-app) インスタンスにのみバインドされます。
::

## ヘルパーの提供

[`NuxtApp`](/docs/api/composables/use-nuxt-app) インスタンスでヘルパーを提供したい場合は、プラグインから `provide` キー下で返してください。

::code-group
```ts twoslash [plugins/hello.ts]
export default defineNuxtPlugin(() => {
  return {
    provide: {
      hello: (msg: string) => `Hello ${msg}!`
    }
  }
})
```
```ts twoslash [plugins/hello-object-syntax.ts]
export default defineNuxtPlugin({
  name: 'hello',
  setup () {
    return {
      provide: {
        hello: (msg: string) => `Hello ${msg}!`
      }
    }
  }
})
```
::

その後、コンポーネントでヘルパーを使用できます：

```vue [components/Hello.vue]
<script setup lang="ts">
// または、ここでも使用できます
const { $hello } = useNuxtApp()
</script>

<template>
  <div>
    {{ $hello('world') }}
  </div>
</template>
```

::important
グローバル名前空間を汚染することを避け、メインバンドルエントリを小さく保つために、ヘルパーを提供する代わりに [`composables`](/docs/guide/directory-structure/composables) を使用することを強く推奨します。
::

::warning
**プラグインが `ref` や `computed` を提供する場合、コンポーネントの `<template>` で展開されません。**:br
これは、テンプレートのトップレベルではない ref に対する Vue の動作によるものです。詳細については、[Vue ドキュメント](https://vuejs.org/guide/essentials/reactivity-fundamentals.html#caveat-when-unwrapping-in-templates)をお読みください。
::

## プラグインの型付け

プラグインからヘルパーを返す場合、それらは自動的に型付けされます。`useNuxtApp()` の戻り値とテンプレート内で型付けされていることがわかります。

::note
別のプラグイン _内で_ 提供されたヘルパーを使用する必要がある場合は、[`useNuxtApp()`](/docs/api/composables/use-nuxt-app) を呼び出して型付けされたバージョンを取得できます。ただし、一般的には、プラグインの順序が確実でない限り、これは避けるべきです。
::

高度な使用例では、次のように注入されたプロパティの型を宣言できます：

```ts [index.d.ts]
declare module '#app' {
  interface NuxtApp {
    $hello (msg: string): string
  }
}

declare module 'vue' {
  interface ComponentCustomProperties {
    $hello (msg: string): string
  }
}

export {}
```

::note
WebStorm を使用している場合、[この課題](https://youtrack.jetbrains.com/issue/WEB-59818/VUE-TypeScript-WS-PS-does-not-correctly-display-type-of-globally-injected-properties)が解決されるまで `@vue/runtime-core` を拡張する必要がある場合があります。
::

## Vue プラグイン

Google Analytics タグを追加するための [vue-gtag](https://github.com/MatteoGabriele/vue-gtag) などの Vue プラグインを使用したい場合は、Nuxt プラグインを使用して行うことができます。

まず、Vue プラグインの依存関係をインストールします：

::code-group{sync="pm"}
```bash [npm]
npm install --save-dev vue-gtag-next
```
```bash [yarn]
yarn add --dev vue-gtag-next
```
```bash [pnpm]
pnpm add -D vue-gtag-next
```
```bash [bun]
bun add -D vue-gtag-next
```
::

次にプラグインファイルを作成します：

```ts [plugins/vue-gtag.client.ts]
import VueGtag, { trackRouter } from 'vue-gtag-next'

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(VueGtag, {
    property: {
      id: 'GA_MEASUREMENT_ID'
    }
  })
  trackRouter(useRouter())
})
```

## Vue ディレクティブ

同様に、プラグインでカスタム Vue ディレクティブを登録できます。

```ts twoslash [plugins/my-directive.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.directive('focus', {
    mounted (el) {
      el.focus()
    },
    getSSRProps (binding, vnode) {
      // ここで SSR 固有の props を提供できます
      return {}
    }
  })
})
```

::warning
Vue ディレクティブを登録する場合は、片側でのみレンダリングする場合を除き、クライアントサイドとサーバーサイドの両方で登録する _必要があります_。ディレクティブがクライアントサイドからのみ意味を持つ場合は、常に `~/plugins/my-directive.client.ts` に移動し、`~/plugins/my-directive.server.ts` でサーバー用の「スタブ」ディレクティブを提供できます。
::
