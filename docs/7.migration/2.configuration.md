## `nuxt.config`

Nuxt アプリの開始点は依然として `nuxt.config` ファイルです。

::note
Nuxt 設定は [`unjs/jiti`](https://github.com/unjs/jiti) と [`unjs/c12`](https://github.com/unjs/c12) を使用して読み込まれます。
::

### 移行

1. 型付き設定スキーマを提供する新しい `defineNuxtConfig` 関数に移行する必要があります。

   ::code-group

   ```ts [Nuxt 2]
   export default {
     // ...
   }
   ```

   ```ts [Nuxt 3]
   export default defineNuxtConfig({
     // ...
   })
   ```

   ::

1. `router.extendRoutes` を使用していた場合は、新しい `pages:extend` フックに移行できます:

   ::code-group

   ```ts [Nuxt 2]
   export default {
     router: {
       extendRoutes (routes) {
         //
       }
     }
   }
   ```

   ```ts [Nuxt 3]
   export default defineNuxtConfig({
     hooks: {
       'pages:extend' (routes) {
         //
       }
     }
   })
   ```

   ::

1. `router.routeNameSplitter` を使用していた場合は、新しい `pages:extend` フックでルート名生成ロジックを更新することで同じ結果を得ることができます:

   ::code-group

   ```ts [Nuxt 2]
   export default {
     router: {
       routeNameSplitter: '/'
     }
   }
   ```

   ```ts [Nuxt 3]
   import { createResolver } from '@nuxt/kit'

   export default defineNuxtConfig({
     hooks: {
       'pages:extend' (routes) {
         const routeNameSplitter = '/'
         const root = createResolver(import.meta.url).resolve('./pages')

         function updateName(routes) {
           if (!routes) return

           for (const route of routes) {
             const relativePath = route.file.substring(root.length + 1)
             route.name = relativePath.slice(0, -4).replace(/\/index$/, '').replace(/\//g, routeNameSplitter)

             updateName(route.children)
           }
         }
         updateName(routes)
       },
     },
   })
   ```

   ::

#### ESM 構文

Nuxt 3 は [ESM ネイティブフレームワーク](/docs/guide/concepts/esm)です。[`unjs/jiti`](https://github.com/unjs/jiti) は `nuxt.config` ファイルを読み込む際に半互換性を提供しますが、このファイルでは `require` や `module.exports` の使用を避けてください。

1. `module.exports` を `export default` に変更します
1. `const lib = require('lib')` を `import lib from 'lib'` に変更します

#### 非同期設定

Nuxt の読み込み動作をより予測可能にするため、非同期設定構文は非推奨となりました。非同期操作には Nuxt フックの使用を検討してください。

#### Dotenv

Nuxt は `.env` ファイルの読み込みを組み込みでサポートしています。`nuxt.config` から直接インポートすることは避けてください。

## モジュール

Nuxt と Nuxt モジュールは現在ビルド時間のみです。

### 移行

1. すべての `buildModules` を `modules` に移動します。
2. モジュールの Nuxt 3 互換性を確認します。
3. ディレクトリを指しているローカルモジュールがある場合は、エントリファイルを指すように更新する必要があります:

```diff
  export default defineNuxtConfig({
    modules: [
-     '~/modules/my-module'
+     '~/modules/my-module/index'
    ]
  })
```

::tip
モジュール作成者の場合は、[モジュール互換性についての詳細情報](/docs/migration/module-authors)と[モジュール作成者ガイド](/docs/guide/going-further/modules)を確認できます。
::

## ディレクトリの変更

`static/`（静的アセットを格納するための）は `public/` に名前が変更されました。`static` ディレクトリを `public` に名前変更するか、`nuxt.config` で `dir.public` を設定して名前を保持することができます。

:read-more{to="/docs/guide/directory-structure/public"}

## TypeScript

Nuxt の TypeScript 統合を使用すると、アプリケーションの移行がはるかに簡単になります。これはアプリケーションを TypeScript で書く必要があるという意味ではなく、Nuxt がエディターに自動型ヒントを提供するだけです。

Nuxt の TypeScript サポートについては[ドキュメント](/docs/guide/concepts/typescript)で詳しく読むことができます。

::note
Nuxt は `nuxt typecheck` コマンドで [`vue-tsc`](https://github.com/vuejs/language-tools/tree/master/packages/tsc) を使用してアプリの型チェックを実行できます。
::

### 移行

1. 以下の内容で `tsconfig.json` を作成します:

   ```json
   {
     "files": [],
     "references": [
       {
         "path": "./.nuxt/tsconfig.app.json"
       },
       {
         "path": "./.nuxt/tsconfig.server.json"
       },
       {
         "path": "./.nuxt/tsconfig.node.json"
       }
     ]
   }
   ```

1. `npx nuxt prepare` を実行して tsconfig ファイルを生成します。
1. [ドキュメント](/docs/getting-started/introduction#prerequisites)の指示に従って Volar をインストールします。

## Vue の変更

推奨される Vue ベストプラクティスに多数の変更があり、Vue 2 と 3 の間には多数の破壊的変更があります。

[Vue 3 移行ガイド](https://v3-migration.vuejs.org)、特に[破壊的変更リスト](https://v3-migration.vuejs.org/breaking-changes)を読むことをお勧めします。

現在、Nuxt 3 で [Vue 3 移行ビルド](https://v3-migration.vuejs.org/migration-build.html)を使用することはできません。

## Vuex

Nuxt はもはや Vuex 統合を提供していません。代わりに、Vue の公式推奨は `pinia` を使用することで、[Nuxt モジュール](https://pinia.vuejs.org/ssr/nuxt.html)を通じて組み込み Nuxt サポートを持っています。[pinia についての詳細はこちら](https://pinia.vuejs.org)で確認できます。

pinia でグローバル状態管理を提供する簡単な方法は以下の通りです:

[`@pinia/nuxt`](/modules/pinia) モジュールをインストールします:

```bash [Terminal]
yarn add pinia @pinia/nuxt
```

nuxt 設定でモジュールを有効にします:

```ts [nuxt.config.ts]
import { defineNuxtConfig } from 'nuxt/config';

export default defineNuxtConfig({
  modules: ['@pinia/nuxt']
})
```

アプリケーションのルートに `store` フォルダを作成します:

```ts [store/index.ts]
import { defineStore } from 'pinia'

export const useMainStore = defineStore('main', {
  state: () => ({
    counter: 0,
  }),
  actions: {
    increment() {
      // `this` はストアインスタンスです
      this.counter++
    },
  },
})
```

ストアをグローバル化するための[プラグイン](/docs/guide/directory-structure/plugins)ファイルを作成します:

```ts [plugins/pinia.ts]
import { useMainStore } from '~/store'

export default defineNuxtPlugin(({ $pinia }) => {
  return {
    provide: {
      store: useMainStore($pinia)
    }
  }
})
```

Vuex を使い続けたい場合は、[これらの手順](https://vuex.vuejs.org/guide/migrating-to-4-0-from-3-x.html)に従って手動で Vuex 4 に移行できます。

これが完了したら、Nuxt アプリに以下のプラグインを追加する必要があります:

```ts [plugins/vuex.ts]
import store from '~/store'

export default defineNuxtPlugin(nuxtApp => {
  nuxtApp.vueApp.use(store);
})
```

大きなアプリの場合、この移行には多くの作業が含まれる可能性があります。Vuex の更新でも障害が生じる場合は、コミュニティモジュール: [nuxt3-vuex-module](https://github.com/vedmant/nuxt3-vuex#nuxt3-vuex-module) の使用を検討してください。これは箱から出してすぐに動作するはずです。
