## プラグイン

プラグインは現在異なる形式を持ち、1つの引数 (`nuxtApp`) のみを受け取ります。

::code-group

```js [Nuxt 2]
export default (ctx, inject) => {
  inject('injected', () => 'my injected function')
})
```

```ts [Nuxt 3]
export default defineNuxtPlugin(nuxtApp => {
  // 現在 `nuxtApp.$injected` で利用可能
  nuxtApp.provide('injected', () => 'my injected function')

  // 自動型サポート付きのこの形式を代わりに使用することもできます
  return {
    provide: {
      injected: () => 'my injected function'
    }
  }
})
```

::

:read-more{to="/docs/guide/directory-structure/plugins"}

::read-more{to="/docs/api/composables/use-nuxt-app"}
`nuxtApp` の形式について詳しく読む。
::

### 移行

1. プラグインを `defineNuxtPlugin` ヘルパー関数を使用するように移行します。
2. `plugins/` フォルダにある `nuxt.config` の plugins 配列のエントリを削除します。このディレクトリの最上位レベルのすべてのファイル（およびサブディレクトリ内のインデックスファイル）は自動的に登録されます。`mode` を `client` または `server` に設定する代わりに、ファイル名でこれを示すことができます。例えば、`~/plugins/my-plugin.client.ts` はクライアントサイドでのみ読み込まれます。

## ルートミドルウェア

ルートミドルウェアは異なる形式を持ちます。

::code-group

```js [Nuxt 2]
export default function ({ store, redirect }) {
  // ユーザーが認証されていない場合
  if (!store.state.authenticated) {
    return redirect('/login')
  }
}
```

```ts [Nuxt 3]
export default defineNuxtRouteMiddleware((to, from) => {
  const auth = useState('auth')
  if (!auth.value.authenticated) {
    return navigateTo('/login')
  }
})
```

::

Nuxt 2 と同様に、`~/middleware` フォルダに配置されたルートミドルウェアは自動的に登録されます。その後、コンポーネント内で名前によって指定できます。ただし、これはコンポーネントオプションとしてではなく、`definePageMeta` で行われます。

`navigateTo` は多数のルートヘルパー関数の1つです。

:read-more{to="/docs/guide/directory-structure/middleware"}

### 移行

1. ルートミドルウェアを `defineNuxtRouteMiddleware` ヘルパー関数を使用するように移行します。
1. 任意のグローバルミドルウェア（`nuxt.config` 内のものなど）は、`~/middleware` フォルダに `.global` 拡張子付きで配置できます。例：`~/middleware/auth.global.ts`。
