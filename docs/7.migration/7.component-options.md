## `asyncData` and `fetch`

Nuxt 3 は [API からデータを取得する](/docs/getting-started/data-fetching)ための新しいオプションを提供します。

### Isomorphic Fetch

Nuxt 2 では、データを取得するために `@nuxtjs/axios` や `@nuxt/http` を使用したり、または単に polyfill されたグローバル `fetch` を使用したりしていたかもしれません。

Nuxt 3 では、[Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch) と同じ API を持つグローバルに利用可能な `fetch` メソッド、または [unjs/ofetch](https://github.com/unjs/ofetch) を使用した [`$fetch`](/docs/api/utils/dollarfetch) メソッドを使用できます。これには以下を含む多くの利点があります:

1. サーバーで実行されている場合は[直接 API 呼び出し](/docs/guide/concepts/server-engine#direct-api-calls)を、クライアントで実行されている場合は API へのクライアントサイド呼び出しを「スマートに」処理します。（サードパーティ API の呼び出しも処理できます。）

2. さらに、レスポンスの自動パースやデータの文字列化などの便利機能が付属しています。

[直接 API 呼び出し](/docs/guide/concepts/server-engine#direct-api-calls)や[データ取得](/docs/getting-started/data-fetching)について詳しく読むことができます。

### Composable

Nuxt 3 はデータ取得のための新しい Composable を提供します: [`useAsyncData`](/docs/api/composables/use-async-data) と `useFetch`。これらにはそれぞれ「lazy」バリアント（`useLazyAsyncData` と `useLazyFetch`）があり、クライアントサイドナビゲーションをブロックしません。

Nuxt 2 では、以下のような構文でコンポーネント内でデータを取得しました:

```ts
export default {
  async asyncData({ params, $http }) {
    const post = await $http.$get(`https://api.nuxtjs.dev/posts/${params.id}`)
    return { post }
  },
  // または代替的に
  fetch () {
    this.post = await $http.$get(`https://api.nuxtjs.dev/posts/${params.id}`)
  }
}
```

メソッドやテンプレート内では、コンポーネントが提供する他のデータと同様に `post` 変数を使用できました。

Nuxt 3 では、`setup()` メソッドや `<script setup>` タグ内で Composable を使用してこのデータ取得を実行できます:

```vue
<script setup lang="ts">
// `defineProps()`、`useRoute()` などで、どこでも params を定義します
const { data: post, refresh } = await useAsyncData('post', () => $fetch(`https://api.nuxtjs.dev/posts/${params.id}`) )
// または代わりに - useFetch はシンプルなフェッチを実行する際の useAsyncData の便利ラッパーです
const { data: post, refresh } = await useFetch(`https://api.nuxtjs.dev/posts/${params.id}`)
</script>
```

Nuxt 3 テンプレート内で `post` を使用したり、`refresh` を呼び出してデータを更新したりできます。

::note
名前にもかかわらず、[`useFetch`](/docs/api/composables/use-fetch) は `fetch()` フックの直接的な置き換えではありません。むしろ、[`useAsyncData`](/docs/api/composables/use-async-data) が両方のフックを置き換え、よりカスタマイズ可能です。これは単にエンドポイントからデータを取得する以上のことができます。[`useFetch`](/docs/api/composables/use-fetch) は、単にエンドポイントからデータを取得するための [`useAsyncData`](/docs/api/composables/use-async-data) の便利ラッパーです。
::

### 移行

1. ページ/コンポーネント内の `asyncData` フックを [`useAsyncData`](/docs/api/composables/use-async-data) または [`useFetch`](/docs/api/composables/use-fetch) に置き換える。
2. コンポーネント内の `fetch` フックを [`useAsyncData`](/docs/api/composables/use-async-data) または [`useFetch`](/docs/api/composables/use-fetch) に置き換える。

## `key`

現在、[`definePageMeta`](/docs/api/utils/define-page-meta) コンパイラマクロ内でキーを定義できます。

```diff [pages/index.vue]
- <script>
- export default {
-   key: 'index'
-   // またはメソッド
-   // key: route => route.fullPath
- }
+ <script setup>
+ definePageMeta({
+   key: 'index'
+   // またはメソッド
+   // key: route => route.fullPath
+ })
</script>
```

## `scrollToTop`

この機能は Nuxt 3 ではまだサポートされていません。`vue-router` のデフォルトスクロール動作を上書きしたい場合は、`~/router.options.ts` で実行できます（詳細は[ドキュメント](/docs/guide/recipes/custom-routing#router-options)を参照）。
`key` と同様に、[`definePageMeta`](/docs/api/utils/define-page-meta) コンパイラマクロ内で指定します。

```diff [pages/index.vue]
- <script>
- export default {
-   scrollToTop: false
- }
+ <script setup>
+ definePageMeta({
+   scrollToTop: false
+ })
</script>
```

## `validate`

Nuxt 3 の validate フックは、1つの引数 `route` だけを受け取ります。Nuxt 2 と同様に、ブール値を返すことができます。false を返して他のマッチが見つからない場合、これは 404 を意味します。また、`statusCode`/`statusMessage` を持つオブジェクトを直接返して、即座にエラーで応答することもできます（他のマッチはチェックされません）。

```diff [pages/users/[id\\].vue]
- <script>
- export default {
-   async validate({ params }) {
-     return /^\d+$/.test(params.id)
-   }
- }
+ <script setup>
+ definePageMeta({
+   validate: async (route) => {
+     const nuxtApp = useNuxtApp()
+     return /^\d+$/.test(route.params.id)
+   }
+ })
  </script>
```

## `watchQuery`

これは Nuxt 3 ではサポートされていません。代わりに、watcher を直接使用してデータの再取得をトリガーできます。

```vue [pages/users/[id\\].vue]
<script setup lang="ts">
const route = useRoute()
const { data, refresh } = await useFetch('/api/user')
watch(() => route.query, () => refresh())
</script>
```
