Nuxt の中核機能の一つは、ファイルシステムルーターです。[`pages/`](/docs/guide/directory-structure/pages) ディレクトリ内のすべての Vue ファイルは、ファイルの内容を表示する対応する URL（またはルート）を作成します。各ページに動的インポートを使用することで、Nuxt はコード分割を活用して、リクエストされたルートに必要最小限の JavaScript を提供します。

## ページ

Nuxt ルーティングは [vue-router](https://router.vuejs.org) をベースとしており、[`pages/` ディレクトリ](/docs/guide/directory-structure/pages) に作成されたファイル名に基づいて、すべてのコンポーネントからルートを生成します。

このファイルシステムルーティングは、動的およびネストされたルートを作成するために命名規則を使用します:

::code-group

```bash [Directory Structure]
-| pages/
---| about.vue
---| index.vue
---| posts/
-----| [id].vue
```

```json [Generated Router File]
{
  "routes": [
    {
      "path": "/about",
      "component": "pages/about.vue"
    },
    {
      "path": "/",
      "component": "pages/index.vue"
    },
    {
      "path": "/posts/:id",
      "component": "pages/posts/[id].vue"
    }
  ]
}
```

::

## ナビゲーション

[`<NuxtLink>`](/docs/api/components/nuxt-link) コンポーネントは、ページ間をリンクします。これは、`href` 属性にページのルートが設定された `<a>` タグをレンダリングします。アプリケーションがハイドレートされると、ブラウザーの URL を更新することで JavaScript でページ遷移が実行されます。これにより、フルページリフレッシュが防止され、アニメーション遷移が可能になります。

[`<NuxtLink>`](/docs/api/components/nuxt-link) がクライアント側でビューポートに入ると、Nuxt は自動的にリンク先ページのコンポーネントとペイロード（生成されたページ）を事前に取得し、ナビゲーションの高速化を実現します。

```vue [pages/app.vue]
<template>
  <header>
    <nav>
      <ul>
        <li><NuxtLink to="/about">About</NuxtLink></li>
        <li><NuxtLink to="/posts/1">Post 1</NuxtLink></li>
        <li><NuxtLink to="/posts/2">Post 2</NuxtLink></li>
      </ul>
    </nav>
  </header>
</template>
```

:read-more{to="/docs/api/components/nuxt-link"}

## ルートパラメーター

[`useRoute()`](/docs/api/composables/use-route) コンポーザブルは、Vue コンポーネントの `<script setup>` ブロックまたは `setup()` メソッドで使用して、現在のルートの詳細にアクセスできます。

```vue twoslash [pages/posts/[id\\].vue]
<script setup lang="ts">
const route = useRoute()

// /posts/1 にアクセスすると、route.params.id は 1 になります
console.log(route.params.id)
</script>
```

:read-more{to="/docs/api/composables/use-route"}

## ルートミドルウェア

Nuxt は、アプリケーション全体で使用できるカスタマイズ可能なルートミドルウェアフレームワークを提供し、特定のルートにナビゲートする前に実行したいコードを抽出するのに理想的です。

::note
ルートミドルウェアは、Nuxt アプリの Vue 部分内で実行されます。名前が似ていますが、アプリの Nitro サーバー部分で実行されるサーバーミドルウェアとは完全に異なります。
::

ルートミドルウェアには 3 つの種類があります:

1. 匿名（またはインライン）ルートミドルウェア: 使用されるページで直接定義されます。
2. 名前付きルートミドルウェア: [`middleware/`](/docs/guide/directory-structure/middleware) ディレクトリに配置され、ページで使用される際に非同期インポートを通して自動的に読み込まれます。（**注意**: ルートミドルウェア名は kebab-case に正規化されるため、`someMiddleware` は `some-middleware` になります。）
3. グローバルルートミドルウェア: [`middleware/`](/docs/guide/directory-structure/middleware) ディレクトリに（`.global` サフィックス付きで）配置され、すべてのルート変更時に自動的に実行されます。

`/dashboard` ページを保護する `auth` ミドルウェアの例:

::code-group

```ts twoslash [middleware/auth.ts]
function isAuthenticated(): boolean { return false }
// ---cut---
export default defineNuxtRouteMiddleware((to, from) => {
  // isAuthenticated() はユーザーが認証されているかを確認するサンプルメソッドです
  if (isAuthenticated() === false) {
    return navigateTo('/login')
  }
})
```

```vue twoslash [pages/dashboard.vue]
<script setup lang="ts">
definePageMeta({
  middleware: 'auth'
})
</script>

<template>
  <h1>ダッシュボードへようこそ</h1>
</template>
```

::

## ルート検証

Nuxt は、検証したい各ページの [`definePageMeta()`](/docs/api/utils/define-page-meta) の `validate` プロパティを通じてルート検証を提供します。

`validate` プロパティは引数として `route` を受け取ります。このページでレンダリングするために有効なルートかどうかを決定するためにブール値を返すことができます。`false` を返すと、404 エラーが発生します。また、`statusCode`/`statusMessage` を含むオブジェクトを直接返して、返されるエラーをカスタマイズすることもできます。

より複雑なユースケースがある場合は、代わりに匿名ルートミドルウェアを使用できます。

```vue twoslash [pages/posts/[id\\].vue]
<script setup lang="ts">
definePageMeta({
  validate: async (route) => {
    // id が数字で構成されているかチェック
    return typeof route.params.id === 'string' && /^\d+$/.test(route.params.id)
  }
})
</script>
```
