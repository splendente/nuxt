Nuxt はフルスタックフレームワークです。つまり、さまざまなコンテキストで発生する可能性のある、予防不可能なユーザーランタイムエラーのソースがいくつかあります：

- Vue レンダリングライフサイクル中のエラー（SSR & CSR）
- サーバーとクライアントの起動エラー（SSR + CSR）
- Nitro サーバーライフサイクル中のエラー（[`server/`](/docs/guide/directory-structure/server) ディレクトリ）
- JS チャンクのダウンロードエラー

::tip
**SSR** は **Server-Side Rendering** を、**CSR** は **Client-Side Rendering** を表します。
::

## Vue エラー

[`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle.html#onerrorcaptured) を使用して Vue エラーにフックすることができます。

さらに、Nuxt は、エラーがトップレベルまで伝播された場合に呼び出される [`vue:error`](/docs/api/advanced/hooks#app-hooks-runtime) フックを提供します。

エラーレポートフレームワークを使用している場合は、[`vueApp.config.errorHandler`](https://vuejs.org/api/application.html#app-config-errorhandler) を通じてグローバルハンドラーを提供できます。これは、処理されている場合でも、すべての Vue エラーを受け取ります。

```ts twoslash [plugins/error-handler.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.config.errorHandler = (error, instance, info) => {
    // handle error, e.g. report to a service
  }

  // Also possible
  nuxtApp.hook('vue:error', (error, instance, info) => {
    // handle error, e.g. report to a service
  })
})
```

::note
`vue:error` フックは [`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle.html#onerrorcaptured) ライフサイクルフックに基づいていることに注意してください。
::

## スタートアップエラー

Nuxt アプリケーションの起動時にエラーがある場合、Nuxt は `app:error` フックを呼び出します。

これには以下が含まれます：
- [Nuxt プラグイン](/docs/guide/directory-structure/plugins)の実行
- `app:created` と `app:beforeMount` フックの処理
- Vue アプリを HTML にレンダリング（SSR 中）
- アプリのマウント（クライアントサイド）。このケースは `onErrorCaptured` または `vue:error` で処理する必要があります
- `app:mounted` フックの処理

## Nitro サーバーエラー

現在、これらのエラーに対してサーバーサイドハンドラーを定義することはできませんが、エラーページをレンダリングすることはできます。[エラーページのレンダリング](#error-page) セクションを参照してください。

## JS チャンクのエラー

ネットワーク接続の失敗や新しいデプロイメント（古いハッシュ化された JS チャンク URL を無効にする）により、チャンク読み込みエラーが発生する可能性があります。Nuxt は、ルートナビゲーション中にチャンクの読み込みが失敗したときにハードリロードを実行することで、チャンク読み込みエラーを処理する組み込みサポートを提供します。

`experimental.emitRouteChunkError` を `false`（これらのエラーへのフッキングを完全に無効にする）または `manual`（自分で処理したい場合）に設定することで、この動作を変更できます。チャンク読み込みエラーを手動で処理したい場合は、アイデアのために[自動実装](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/plugins/chunk-reload.client.ts)を確認してください。

## エラーページ

::note
Nuxt が致命的なエラー（サーバー上の未処理エラー、またはクライアント上で `fatal: true` で作成されたエラー）に遷遇した場合、JSON レスポンス（`Accept: application/json` ヘッダーでリクエストされた場合）をレンダリングするか、フルスクリーンエラーページをトリガーします。
::

エラーは以下のサーバーライフサイクル中に発生する可能性があります：
- Nuxt プラグインの処理
- Vue アプリを HTML にレンダリング
- サーバー API ルートがエラーをスロー

クライアントサイドでも以下の場合に発生する可能性があります：
- Nuxt プラグインの処理
- アプリケーションのマウント前（`app:beforeMount` フック）
- `onErrorCaptured` または `vue:error` フックでエラーが処理されなかった場合のアプリのマウント
- Vue アプリがブラウザーで初期化されマウントされるとき（`app:mounted`）。

::read-more{to="/docs/api/advanced/hooks"}
すべての Nuxt ライフサイクルフックを発見する。
::

アプリケーションのソースディレクトリに `app.vue` と並んで `~/error.vue` を追加することで、デフォルトのエラーページをカスタマイズできます。

<!-- TODO:twoslash: Twoslash does not support tsconfig paths yet -->

```vue [error.vue]
<script setup lang="ts">
import type { NuxtError } from '#app'

const props = defineProps({
  error: Object as () => NuxtError
})

const handleError = () => clearError({ redirect: '/' })
</script>

<template>
  <div>
    <h2>{{ error?.statusCode }}</h2>
    <button @click="handleError">Clear errors</button>
  </div>
</template>
```

::read-more{to="/docs/guide/directory-structure/error"}
`error.vue` とその使用方法について詳しく読む。
::

カスタムエラーに対しては、ページ/コンポーネントの setup 関数で呼び出すことができる `onErrorCaptured` composable や、Nuxt プラグインで設定できる `vue:error` ランタイム Nuxt フックの使用を強く推奨します。

```ts twoslash [plugins/error-handler.ts]
export default defineNuxtPlugin(nuxtApp => {
  nuxtApp.hook('vue:error', (err) => {
    //
  })
})
```

エラーページを削除する準備ができたら、[`clearError`](/docs/api/utils/clear-error) ヘルパー関数を呼び出すことができます。この関数はリダイレクト先のオプションパスを受け取ります（例えば、「安全な」ページにナビゲートしたい場合）。

::important
`$route` や `useRouter` などの Nuxt プラグインに依存するものを使用する前に、必ず確認してください。プラグインがエラーをスローした場合、エラーをクリアするまで再実行されません。
::

::note
エラーページのレンダリングは完全に別のページロードであるため、登録されたミドルウェアは再度実行されます。ミドルウェアで [`useError`](#useerror) を使用して、エラーが処理されているかどうかを確認できます。
::

::note
Node 16 で実行していて、エラーページのレンダリング時にクッキーを設定した場合、[以前に設定されたクッキーを上書き](https://github.com/nuxt/nuxt/pull/20585)します。Node 16 は 2023 年 9 月にサポート終了となったため、より新しいバージョンの Node を使用することを推奨します。
::

## エラーユーティリティ

### `useError`

```ts [TS Signature]
function useError (): Ref<Error | { url, statusCode, statusMessage, message, description, data }>
```

この関数は、処理されているグローバル Nuxt エラーを返します。

::read-more{to="/docs/api/composables/use-error"}
`useError` composable について詳しく読む。
::

### `createError`

```ts [TS Signature]
function createError (err: string | { cause, data, message, name, stack, statusCode, statusMessage, fatal }): Error
```

追加のメタデータを持つエラーオブジェクトを作成します。エラー `message` として設定される文字列、またはエラープロパティを含むオブジェクトを渡すことができます。これはアプリの Vue 部分とサーバー部分の両方で使用可能で、スローされることを意図しています。

`createError` で作成されたエラーをスローした場合：
- サーバーサイドでは、[`clearError`](#clearerror) でクリアできるフルスクリーンエラーページをトリガーします。
- クライアントサイドでは、処理するための非致命的エラーをスローします。フルスクリーンエラーページをトリガーする必要がある場合は、`fatal: true` を設定することで実行できます。

```vue twoslash [pages/movies/[slug\\].vue]
<script setup lang="ts">
const route = useRoute()
const { data } = await useFetch(`/api/movies/${route.params.slug}`)

if (!data.value) {
  throw createError({
    statusCode: 404,
    statusMessage: 'Page Not Found'
  })
}
</script>
```

::read-more{to="/docs/api/utils/create-error"}
`createError` ユーティリティについて詳しく読む。
::

### `showError`

```ts [TS Signature]
function showError (err: string | Error | { statusCode, statusMessage }): Error
```

この関数はクライアントサイドの任意の時点、または（サーバーサイドで）ミドルウェア、プラグイン、または `setup()` 関数内で直接呼び出すことができます。[`clearError`](#clearerror) でクリアできるフルスクリーンエラーページをトリガーします。

代わりに `throw createError()` を使用することを推奨します。

::read-more{to="/docs/api/utils/show-error"}
`showError` ユーティリティについて詳しく読む。
::

### `clearError`

```ts [TS Signature]
function clearError (options?: { redirect?: string }): Promise<void>
```

この関数は、現在処理されている Nuxt エラーをクリアします。また、リダイレクト先のオプションパスを受け取ります（例えば、「安全な」ページにナビゲートしたい場合）。

::read-more{to="/docs/api/utils/clear-error"}
`clearError` ユーティリティについて詳しく読む。
::

## コンポーネント内でのエラーレンダリング

Nuxt は、サイト全体をエラーページで置き換えることなく、アプリ内でクライアントサイドエラーを処理できる [`<NuxtErrorBoundary>`](/docs/api/components/nuxt-error-boundary) コンポーネントも提供します。

このコンポーネントは、デフォルトスロット内で発生するエラーを処理する責任を負います。クライアントサイドでは、エラーがトップレベルに泡立つのを防ぎ、代わりに `#error` スロットをレンダリングします。

`#error` スロットは `error` を prop として受け取ります。（`error = null` を設定するとデフォルトスロットの再レンダリングがトリガーされます。エラースロットが二度レンダリングされるだけにならないように、まずエラーが完全に解決されていることを確認する必要があります。）

::tip
別のルートにナビゲートすると、エラーは自動的にクリアされます。
::

```vue [pages/index.vue]
<template>
  <!-- 何らかのコンテンツ -->
  <NuxtErrorBoundary @error="someErrorLogger">
    <!-- デフォルトスロットを使用してコンテンツをレンダー -->
    <template #error="{ error, clearError }">
      ここでエラーをローカルに表示できます: {{ error }}
      <button @click="clearError">
        これはエラーをクリアします。
      </button>
    </template>
  </NuxtErrorBoundary>
</template>
```
