## Nitro による駆動

![Server engine](/assets/docs/getting-started/server.svg)

Nuxt のサーバーは [Nitro](https://github.com/nitrojs/nitro) です。これは元々 Nuxt のために作成されましたが、現在は [UnJS](https://unjs.io) の一部であり、他のフレームワークにも開放されており、単独でも使用できます。

Nitro を使用することで、Nuxt にスーパーパワーが与えられます：

- アプリのサーバーサイド部分の完全な制御
- あらゆるプロバイダーでのユニバーサルデプロイメント（多くがゼロ設定）
- ハイブリッドレンダリング

Nitro は内部で [h3](https://github.com/h3js/h3) を使用しています。これは高いパフォーマンスとポータビリティのために構築された最小限の H(TTP) フレームワークです。

## サーバーエンドポイントとミドルウェア

API エンドポイントからミドルウェアまで、Nuxt アプリのサーバー専用部分を簡単に管理できます。

エンドポイントとミドルウェアの両方は次のように定義できます：

```ts twoslash [server/api/test.ts]
export default defineEventHandler(async (event) => {
  // ... ここで何でも好きなことができます
})
```

`text`、`json`、`html`、さらには `stream` も直接返すことができます。

そのまま使えて、Nuxt アプリケーションの他の部分と同様に**ホットモジュールリプレースメント**と**自動インポート**をサポートします。

## ハイブリッドレンダリング

Nitro には `routeRules` という強力な機能があり、Nuxt アプリの各ルートがレンダリングされる方法（およびその他）をカスタマイズするルールセットを定義できます。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    // SEO 目的でビルド時に生成
    '/': { prerender: true },
    // 1 時間キャッシュ
    '/api/*': { cache: { maxAge: 60 * 60 } },
    // 404 を避けるためのリダイレクト
    '/old-page': {
      redirect: { to: '/new-page', statusCode: 302 }
    }
    // ...
  }
})
```

::read-more{to="/docs/guide/concepts/rendering#hybrid-rendering"}
ルートのレンダリングモードをカスタマイズするために利用可能なすべてのルートルールについて学ぶ。
::

さらに、ページを HTML にレンダリングする際の動作を変更する Nuxt 固有のルートルール（例：`ssr`、`appMiddleware`、`noScripts`）もあります。

一部のルートルール（`appMiddleware`、`redirect`、`prerender`）はクライアントサイドの動作にも影響します。

Nitro は、サーバーサイドレンダリングおよび事前レンダリング用のアプリ構築に使用されます。
