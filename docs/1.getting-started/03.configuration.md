デフォルトで、Nuxt はほとんどのユースケースをカバーするように設定されています。[`nuxt.config.ts`](/docs/guide/directory-structure/nuxt-config) ファイルでこのデフォルト設定を上書きまたは拡張できます。

## Nuxt 設定

[`nuxt.config.ts`](/docs/guide/directory-structure/nuxt-config) ファイルは Nuxt プロジェクトのルートにあり、アプリケーションの動作を上書きまたは拡張できます。

最小限の設定ファイルは、設定内容を含むオブジェクトを `defineNuxtConfig` 関数でエクスポートします。`defineNuxtConfig` ヘルパーはインポート不要でグローバルに利用できます。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  // My Nuxt config
})
```

このファイルは、カスタムスクリプトの追加、モジュールの登録、レンダリングモードの変更など、ドキュメント内で頻繁に言及されます。

::read-more{to="/docs/api/configuration/nuxt-config"}
すべてのオプションは **設定リファレンス** で説明されています。
::

::note
Nuxt でアプリケーションを構築する際、TypeScript を使う必要はありません。ただし、`nuxt.config` ファイルには `.ts` 拡張子を使うことを強く推奨します。これにより、IDE でヒントが得られ、設定編集時のタイプミスやミスを防げます。
::

### 環境ごとの上書き

nuxt.config で型安全な環境ごとの上書きを設定できます。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  $production: {
    routeRules: {
      '/**': { isr: true }
    }
  },
  $development: {
    //
  },
  $env: {
    staging: {
      // 
    }
  },
})
```

Nuxt CLI コマンド実行時に `--envName` フラグで環境名を指定できます。例: `nuxt build --envName staging`

この仕組みの詳細は、[環境固有の設定](https://github.com/unjs/c12?tab=readme-ov-file#environment-specific-configuration) の `c12` ドキュメントを参照してください。

:video-accordion{title="env-aware nuxt.config.ts について Alexander Lichter 氏の動画を見る" videoId="DFZI2iVCrNc"}

::note
レイヤーを作成する場合は、`$meta` キーで自分やレイヤー利用者向けのメタデータを提供できます。
::

### 環境変数とプライベートトークン

`runtimeConfig` API で環境変数などの値をアプリ全体に公開できます。デフォルトでは、これらのキーはサーバーサイドのみで利用可能です。`runtimeConfig.public` および `runtimeConfig.app`（Nuxt 内部で使用）はクライアントサイドでも利用できます。

これらの値は `nuxt.config` で定義し、環境変数で上書きできます。

::code-group

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // サーバーサイドのみで利用可能なプライベートキー
    apiSecret: '123',
    // public 内のキーはクライアントサイドでも公開
    public: {
      apiBase: '/api'
    }
  }
})
```

```ini [.env]
# apiSecret の値を上書き
NUXT_API_SECRET=api_secret_token
```

::

これらの変数は [`useRuntimeConfig()`](/docs/api/composables/use-runtime-config) composable でアプリ全体から利用できます。

```vue [pages/index.vue]
<script setup lang="ts">
const runtimeConfig = useRuntimeConfig()
</script>
```

:read-more{to="/docs/guide/going-further/runtime-config"}

## アプリ設定

`app.config.ts` ファイルはソースディレクトリ（デフォルトはプロジェクトルート）にあり、ビルド時に決定できるパブリック変数を公開します。`runtimeConfig` オプションと異なり、環境変数で上書きできません。

最小限の設定ファイルは、設定内容を含むオブジェクトを `defineAppConfig` 関数でエクスポートします。`defineAppConfig` ヘルパーはインポート不要でグローバルに利用できます。

```ts [app.config.ts]
export default defineAppConfig({
  title: 'Hello Nuxt',
  theme: {
    dark: true,
    colors: {
      primary: '#ff0000'
    }
  }
})
```

これらの変数は [`useAppConfig`](/docs/api/composables/use-app-config) composable でアプリ全体から利用できます。

```vue [pages/index.vue]
<script setup lang="ts">
const appConfig = useAppConfig()
</script>
```

:read-more{to="/docs/guide/directory-structure/app-config"}

## `runtimeConfig` と `app.config` の違い

前述の通り、`runtimeConfig` と `app.config` はどちらもアプリ全体に変数を公開するために使います。どちらを使うべきか判断するためのガイドラインは以下の通りです:

- `runtimeConfig`: ビルド後に環境変数で指定する必要があるプライベートまたはパブリックトークン
- `app.config`: ビルド時に決定されるパブリックトークン、テーマバリアントやタイトルなどのウェブサイト設定、機密でないプロジェクト設定

機能                              | `runtimeConfig`  | `app.config`
-------------------------------|------------------|-------------------
クライアントサイド              | Hydrated         | Bundled
環境変数                        | ✅ あり           | ❌ なし
リアクティブ                    | ✅ あり           | ✅ あり
型サポート                      | ✅ 一部           | ✅ あり
リクエストごとの設定            | ❌ なし           | ✅ あり
ホットモジュールリプレースメント| ❌ なし           | ✅ あり
非プリミティブ JS 型            | ❌ なし           | ✅ あり

## 外部設定ファイル

Nuxt は [`nuxt.config.ts`](/docs/guide/directory-structure/nuxt-config) ファイルを設定の唯一の情報源とし、外部設定ファイルの読み込みをスキップします。プロジェクト構築中にこれらの設定が必要になる場合があります。以下の表は、一般的な設定と Nuxt での設定方法をまとめたものです。

名前                                         | 設定ファイル               |  設定方法
---------------------------------------------|---------------------------|-------------------------
[Nitro](https://nitro.build)               | ~~`nitro.config.ts`~~     | `nuxt.config` の [`nitro`](/docs/api/nuxt-config#nitro) キーを使用
[PostCSS](https://postcss.org)               | ~~`postcss.config.js`~~   | `nuxt.config` の [`postcss`](/docs/api/nuxt-config#postcss) キーを使用
[Vite](https://vite.dev)                     | ~~`vite.config.ts`~~      | `nuxt.config` の [`vite`](/docs/api/nuxt-config#vite) キーを使用
[webpack](https://webpack.js.org)            | ~~`webpack.config.ts`~~   | `nuxt.config` の [`webpack-1`](/docs/api/nuxt-config#webpack-1) キーを使用

その他の一般的な設定ファイル一覧:

名前                                         | 設定ファイル             | 設定方法
---------------------------------------------|-------------------------|--------------------------
[TypeScript](https://www.typescriptlang.org) | `tsconfig.json`         | [詳細](/docs/guide/concepts/typescript#nuxttsconfigjson)
[ESLint](https://eslint.org)                 | `eslint.config.js`      | [詳細](https://eslint.org/docs/latest/use/configure/configuration-files)
[Prettier](https://prettier.io)              | `prettier.config.js`    | [詳細](https://prettier.io/docs/en/configuration.html)
[Stylelint](https://stylelint.io)            | `stylelint.config.js`   | [詳細](https://stylelint.io/user-guide/configure)
[TailwindCSS](https://tailwindcss.com)       | `tailwind.config.js`    | [詳細](https://tailwindcss.nuxtjs.org/tailwindcss/configuration)
[Vitest](https://vitest.dev)                 | `vitest.config.ts`      | [詳細](https://vitest.dev/config/)

## Vue 設定

### Vite 利用時

`@vitejs/plugin-vue` や `@vitejs/plugin-vue-jsx` にオプションを渡す必要がある場合は、`nuxt.config` ファイルで設定できます。

- `vite.vue` は `@vitejs/plugin-vue` 用。 [利用可能なオプション](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue) を参照してください。
- `vite.vueJsx` は `@vitejs/plugin-vue-jsx` 用。 [利用可能なオプション](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue-jsx) を参照してください。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  vite: {
    vue: {
      customElement: true
    },
    vueJsx: {
      mergeProps: true
    }
  }
})
```

:read-more{to="/docs/api/configuration/nuxt-config#vue"}

### webpack 利用時

webpack を使い `vue-loader` を設定する場合は、`nuxt.config` ファイル内の `webpack.loaders.vue` キーで設定できます。利用可能なオプションは[こちら](https://github.com/vuejs/vue-loader/blob/main/src/index.ts#L32-L62)を参照してください。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  webpack: {
    loaders: {
      vue: {
        hotReload: true,
      }
    }
  }
})
```

:read-more{to="/docs/api/configuration/nuxt-config#loaders"}

### Vue の実験的機能を有効化

Vue の `propsDestructure` などの実験的機能を有効化する場合、ビルダーに関係なく `nuxt.config.ts` で簡単に設定できます:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  vue: {
    propsDestructure: true
  }
})
```

#### experimental `reactivityTransform` の Vue 3.4 および Nuxt 3.9 での移行

Nuxt 3.9 および Vue 3.4 以降、`reactivityTransform` は Vue から Vue Macros に移動し、[Nuxt 統合](https://vue-macros.dev/guide/nuxt-integration.html)が提供されています。
