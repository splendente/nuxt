Nuxt は、コンポーネント間でリアクティブで SSR 対応の共有状態を作成するための [`useState`](/docs/api/composables/use-state) composable を提供します。

[`useState`](/docs/api/composables/use-state) は、SSR 対応の [`ref`](https://vuejs.org/api/reactivity-core.html#ref) の代替品です。その値は、サーバーサイドレンダリング後（クライアントサイドハイドレーション中）に保持され、ユニークなキーを使用してすべてのコンポーネント間で共有されます。

:video-accordion{title="useState を使用する理由とタイミングについて Alexander Lichter のビデオを見る" videoId="mv0WcBABcIk"}

::important
[`useState`](/docs/api/composables/use-state) 内のデータは JSON にシリアル化されるため、クラス、関数、シンボルなどのシリアル化できないものが含まれていないことが重要です。
::

::read-more{to="/docs/api/composables/use-state"}
`useState` composable について詳しく読む。
::

## ベストプラクティス

::warning
`<script setup>` または `setup()` 関数の外で `const state = ref()` を定義しないでください。<br>
例えば、`export myState = ref({})` を行うと、サーバー上でリクエスト間で状態が共有され、メモリーリークにつながる可能性があります。
::

::tip{icon="i-lucide-circle-check"}
代わりに `const useX = () => useState('x')` を使用してください
::

## 例

### 基本的な使用方法

この例では、コンポーネントローカルのカウンター状態を使用します。`useState('counter')` を使用する他のコンポーネントは、同じリアクティブ状態を共有します。

```vue twoslash [app.vue]
<script setup lang="ts">
const counter = useState('counter', () => Math.round(Math.random() * 1000))
</script>

<template>
  <div>
    Counter: {{ counter }}
    <button @click="counter++">
      +
    </button>
    <button @click="counter--">
      -
    </button>
  </div>
</template>
```

:link-example{to="/docs/examples/features/state-management"}

::note
キャッシュされた状態をグローバルに無効化するには、[`clearNuxtState`](/docs/api/utils/clear-nuxt-state) ユーティリティを参照してください。
::

### 状態の初期化

ほとんどの場合、非同期で解決されるデータで状態を初期化したいでしょう。そのために [`app.vue`](/docs/guide/directory-structure/app) コンポーネントと [`callOnce`](/docs/api/utils/call-once) ユーティリティを使用できます。

```vue twoslash [app.vue]
<script setup lang="ts">
const websiteConfig = useState('config')

await callOnce(async () => {
  websiteConfig.value = await $fetch('https://my-cms.com/api/website-config')
})
</script>
```

::tip
これは Nuxt 2 の [`nuxtServerInit` アクション](https://v2.nuxt.com/docs/directory-structure/store/#the-nuxtserverinit-action)と似ており、ページをレンダリングする前にストアの初期状態をサーバーサイドで入力することを可能にします。
::

:read-more{to="/docs/api/utils/call-once"}

### Pinia での使用

この例では、[Pinia モジュール](/modules/pinia) を活用してグローバルストアを作成し、アプリ全体で使用します。

::important
`npx nuxt module add pinia` で Pinia モジュールをインストールするか、[モジュールのインストール手順](https://pinia.vuejs.org/ssr/nuxt.html#Installation) に従ってください。
::

::code-group
```ts [stores/website.ts]
export const useWebsiteStore = defineStore('websiteStore', {
  state: () => ({
    name: '',
    description: ''
  }),
  actions: {
    async fetch() {
      const infos = await $fetch('https://api.nuxt.com/modules/pinia')

      this.name = infos.name
      this.description = infos.description
    }
  }
})
```
```vue [app.vue]
<script setup lang="ts">
const website = useWebsiteStore()

await callOnce(website.fetch)
</script>

<template>
  <main>
    <h1>{{ website.name }}</h1>
    <p>{{ website.description }}</p>
  </main>
</template>
```
::

## 高度な使用方法

::code-group
```ts [composables/locale.ts]
import type { Ref } from 'vue'

export const useLocale = () => {
  return useState<string>('locale', () => useDefaultLocale().value)
}

export const useDefaultLocale = (fallback = 'en-US') => {
  const locale = ref(fallback)
  if (import.meta.server) {
    const reqLocale = useRequestHeaders()['accept-language']?.split(',')[0]
    if (reqLocale) {
      locale.value = reqLocale
    }
  } else if (import.meta.client) {
    const navLang = navigator.language
    if (navLang) {
      locale.value = navLang
    }
  }
  return locale
}

export const useLocales = () => {
  const locale = useLocale()
  const locales = ref([
    'en-US',
    'en-GB',
    ...
    'ja-JP-u-ca-japanese'
  ])
  if (!locales.value.includes(locale.value)) {
    locales.value.unshift(locale.value)
  }
  return locales
}

export const useLocaleDate = (date: Ref<Date> | Date, locale = useLocale()) => {
  return computed(() => new Intl.DateTimeFormat(locale.value, { dateStyle: 'full' }).format(unref(date)))
}
```

```vue [app.vue]
<script setup lang="ts">
const locales = useLocales()
const locale = useLocale()
const date = useLocaleDate(new Date('2016-10-26'))
</script>

<template>
  <div>
    <h1>Nuxt birthday</h1>
    <p>{{ date }}</p>
    <label for="locale-chooser">Preview a different locale</label>
    <select id="locale-chooser" v-model="locale">
      <option v-for="locale of locales" :key="locale" :value="locale">
        {{ locale }}
      </option>
    </select>
  </div>
</template>
```
::

## 共有状態

[自動インポートされる composables](/docs/guide/directory-structure/composables) を使用することで、グローバルで型安全な状態を定義し、アプリ全体でインポートできます。

```ts twoslash [composables/states.ts]
export const useColor = () => useState<string>('color', () => 'pink')
```

```vue [app.vue]
<script setup lang="ts">
// ---cut-start---
const useColor = () => useState<string>('color', () => 'pink')
// ---cut-end---
const color = useColor() // Same as useState('color')
</script>

<template>
  <p>Current color: {{ color }}</p>
</template>
```

## サードパーティライブラリの使用

Nuxt は以前、グローバル状態管理を提供するために Vuex ライブラリに**依存していました**。Nuxt 2 から移行する場合は、[移行ガイド](/docs/migration/configuration#vuex) をご参照ください。

Nuxt は状態管理について特定の方針を持たないため、ニーズに合った適切なソリューションを自由に選択できます。最も人気のある状態管理ライブラリとの複数の統合があります：

- [Pinia](/modules/pinia) - Vue の公式推奨
- [Harlem](/modules/harlem) - イミュータブルなグローバル状態管理
- [XState](/modules/xstate) - 状態ロジックの可視化とテストのためのツールを備えたステートマシンアプローチ
