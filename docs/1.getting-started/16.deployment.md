Nuxt アプリケーションは、Node.js サーバーにデプロイしたり、静的ホスティング用に事前レンダリングしたり、サーバーレスまたはエッジ（CDN）環境にデプロイしたりできます。

::tip
Nuxt をサポートするクラウドプロバイダーのリストをお探しの場合は、[ホスティングプロバイダー](/deploy) セクションをご覧ください。
::

## Node.js サーバー

任意の Node ホスティングにデプロイするための Nitro で Node.js サーバープリセットを発見してください。

- 何も指定されていないか自動検出された場合の**デフォルト出力形式** <br>
- 最適なコールドスタートタイミングのために、リクエストをレンダリングするのに必要なチャンクのみを読み込み <br>
- 任意の Node.js ホスティングに Nuxt アプリをデプロイするのに役立ちます

### エントリーポイント

Node サーバープリセットで `nuxt build` を実行すると、すぐに実行可能な Node サーバーを起動するエントリーポイントが結果として得られます。

```bash [Terminal]
node .output/server/index.mjs
```

これにより、デフォルトでポート 3000 でリッスンする本番環境の Nuxt サーバーが起動します。

以下のランタイム環境変数を尊重します：

- `NITRO_PORT` or `PORT` (defaults to `3000`)
- `NITRO_HOST` or `HOST` (defaults to `'0.0.0.0'`)
- `NITRO_SSL_CERT` と `NITRO_SSL_KEY` - 両方が存在する場合、サーバーを HTTPS モードで起動します。大部分の場合、これはテスト以外では使用すべきではなく、Nitro サーバーは SSL を終端する nginx や Cloudflare などのリバースプロキシの背後で実行されるべきです。

### PM2

[PM2](https://pm2.keymetrics.io/) （Process Manager 2）は、サーバーや VM 上で Nuxt アプリケーションをホスティングするための高速で簡単なソリューションです。

`pm2` を使用するには、`ecosystem.config.cjs` を使用してください：

```ts [ecosystem.config.cjs]
module.exports = {
  apps: [
    {
      name: 'NuxtAppName',
      port: '3000',
      exec_mode: 'cluster',
      instances: 'max',
      script: './.output/server/index.mjs'
    }
  ]
}
```

### クラスターモード

Node.js [cluster](https://nodejs.org/dist/latest/docs/api/cluster.html) モジュールを使用してマルチプロセスパフォーマンスを活用するために、`NITRO_PRESET=node_cluster` を使用できます。

デフォルトでは、ワークロードはラウンドロビン戦略でワーカーに分散されます。

## 静的ホスティング

任意の静的ホスティングサービスに Nuxt アプリケーションをデプロイする方法は 2 つあります：

- `ssr: true` での静的サイト生成（SSG）は、ビルド時にアプリケーションのルートを事前レンダリングします。（これは `nuxt generate` を実行するときのデフォルト動作です。）また、`/200.html` と `/404.html` のシングルページアプリフォールバックページを生成し、クライアントで動的ルートや 404 エラーをレンダリングできます（ただし、静的ホストでこれを設定する必要があるかもしれません）。
- 代わりに、`ssr: false`（静的シングルページアプリ）でサイトを事前レンダリングすることもできます。これにより、通常 Vue アプリがレンダリングされる場所に空の `<div id="__nuxt"></div>` を持つ HTML ページが生成されます。サイトの事前レンダリングの多くの SEO 利点を失うため、代わりに [`<ClientOnly>`](/docs/api/components/client-only) を使用してサーバーレンダリングできないサイトの部分（ある場合）をラップすることが推奨されます。

:read-more{title="Nuxt prerendering" to="/docs/getting-started/prerendering"}

### クライアントサイドのみのレンダリング

ルートを事前レンダリングしたくない場合、静的ホスティングを使用する別の方法は、`nuxt.config` ファイルで `ssr` プロパティを `false` に設定することです。そうすると、`nuxt generate` コマンドはクラシックなクライアントサイド Vue.js アプリケーションのように `.output/public/index.html` エントリーポイントと JavaScript バンドルを出力します。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  ssr: false
})
```

## プリセット

Node.js サーバーと静的ホスティングサービスに加えて、Nuxt プロジェクトは十分にテストされたいくつかのプリセットと最小限の設定でデプロイできます。

[`nuxt.config.ts`](/docs/guide/directory-structure/nuxt-config) ファイルで希望するプリセットを明示的に設定できます：

```js twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    preset: 'node-server'
  }
})
```

... または `nuxt build` を実行する際に `NITRO_PRESET` 環境変数を使用してください：

```bash [Terminal]
NITRO_PRESET=node-server nuxt build
```

🔎 すべての可能なデプロイメントプリセットとプロバイダーについては [Nitro デプロイメント](https://nitro.build/deploy) を確認してください。

## CDN プロキシ

ほとんどの場合、Nuxt は Nuxt 自体で生成または作成されていないサードパーティコンテンツと連携できます。しかし、時にはそのようなコンテンツが問題を引き起こすことがあり、特に Cloudflare の「ミニフィケーションとセキュリティオプション」です。

したがって、Cloudflare で以下のオプションのチェックを外す/無効にすることを確実にしてください。そうしないと、不要な再レンダリングやハイドレーションエラーが本番環境のアプリケーションに影響を与える可能性があります。

1. Speed > Optimization > Content Optimization > "Rocket Loader™" を無効化
2. Speed > Optimization > Image Optimization > "Mirage" を無効化
3. Scrape Shield > "Email Address Obfuscation" を無効化

これらの設定で、Cloudflare が望ましくない副作用を引き起こす可能性のあるスクリプトを Nuxt アプリケーションに注入しないことが保証されます。

::tip
Cloudflare ダッシュボード上の場所が時々変更されるため、避巡することなく探してみてください。
::
